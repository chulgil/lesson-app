## 1. 현재 문제: 앱 사용 시 복잡도 증가

### 1.1 현황 비교

#### 앱 미사용 - 신규 학생 (5단계)

| # | 주체 | 액션 |
|:-:|:----:|------|
| 1 | T | 초대 (카톡 연락) |
| 2 | T | 비용 안내 |
| 3 | S | 입금 |
| 4 | T | 입금 확인 |
| 5 | T | 스케줄 등록 (수기) |

**선생님 4액션, 학생 1액션**

#### 앱 미사용 - 재등록 (2-3단계)

| # | 주체 | 액션 |
|:-:|:----:|------|
| 1 | S | 입금 |
| 2 | T | 입금 확인 |
| 3 | T | 스케줄 확인 (선택) |

**선생님 1-2액션, 학생 1액션** ← 매우 간단!

#### 앱 사용 - 신규 학생 (현재: 7단계)

| # | 주체 | 액션 | 비고 |
|:-:|:----:|------|------|
| 1 | T | 템플릿/설정 | ⚠️ 1회성 |
| 2 | T | QR 초대 | 동일 |
| 3 | S | 회원가입 | ⚠️ 추가 마찰 |
| 4 | T/Auto | 수강권 제안 | |
| 5 | S | 제안 확인 + 입금 | |
| 6 | T | 입금 확인 + 발급 | ⚠️ 2개 액션 |
| 7 | S | 스케줄 등록 | ⚠️ 추가 |

**선생님 3-4액션, 학생 3액션** ← 더 복잡!

#### 앱 사용 - 재등록 (현재: 4단계)

| # | 주체 | 액션 |
|:-:|:----:|------|
| 1 | T/Auto | 수강권 제안 |
| 2 | S | 제안 확인 + 입금 |
| 3 | T | 입금 확인 + 발급 |
| 4 | S | 스케줄 등록 |

**선생님 1-2액션, 학생 2액션** ← 앱 미사용보다 복잡!

## 2. 문제 원인 분석

### 2.1 불필요하게 분리된 액션

| 현재 | 문제 | 해결 |
|------|------|------|
| 입금 확인 → 수강권 발급 | 2개 액션으로 분리 | **1개로 병합** |
| 수강권 발급 → 스케줄 등록 | 별도 단계 | **자동 스케줄** |
| 회원가입 | 별도 단계 | **QR 스캔 = 자동 가입** |

### 2.2 자동화 부족

| 항목 | 현재 | 개선 |
|------|------|------|
| 스케줄 생성 | 학생이 선택 | **자동 생성** (체험 시간 기준) |
| 재등록 제안 | 선생님 수동 | **자동 제안** (잔여 2회 시) |
| 재등록 스케줄 | 학생이 선택 | **이전 스케줄 유지** |

## 3. 간소화 제안

### 3.1 핵심 원칙

> **"앱은 기존보다 단순해야 한다"**

| 원칙 | 설명 |
|------|------|
| **액션 병합** | 관련 액션은 1번에 처리 |
| **스마트 기본값** | 대부분의 경우 기본값으로 완료 |
| **자동화** | 선생님/학생 액션 최소화 |

### 3.2 간소화된 플로우 (신규 학생)

#### 목표: 5단계 (앱 미사용과 동일)

| # | 주체 | 액션 | 자동화 |
|:-:|:----:|------|--------|
| 1 | T | QR 초대 | |
| 2 | S | QR 스캔 | → 자동 가입 + 연결 |
| 3 | Auto | 수강권 제안 | 체험 후 자동 발송 |
| 4 | S | 제안 수락 + 입금 | |
| 5 | T | **입금 확인** | → 자동 발급 + 자동 스케줄 |

**선생님 2액션, 학생 2액션** ← 오히려 간단!

```
변경 포인트:
1. 회원가입 제거: QR 스캔 = 자동 가입 (최소 정보: 이름만)
2. 수강권 제안 자동화: 체험 완료 시 자동 제안
3. 액션 병합: 입금 확인 = 발급 + 스케줄 생성
4. 스케줄 자동화: 체험 시간 기준 자동 생성
```

#### 시퀀스 다이어그램

```
T: QR 제시
    ↓
S: QR 스캔 ──[자동]──→ 가입 + 연결
    ↓
[체험 레슨]
    ↓
Auto: 수강권 제안 발송 (골든타임 할인)
    ↓
S: 수락 + 입금
    ↓
T: 입금 확인 탭 ──[자동]──→ 수강권 발급
                          ──[자동]──→ 스케줄 생성 (체험 시간)
    ↓
Done! ✅
```

### 3.3 간소화된 플로우 (재등록)

#### 목표: 3단계 (앱 미사용과 동일)

| # | 주체 | 액션 | 자동화 |
|:-:|:----:|------|--------|
| 1 | Auto | 갱신 제안 | 잔여 2회 시 자동 |
| 2 | S | 수락 + 입금 | |
| 3 | T | **입금 확인** | → 자동 발급 + 자동 스케줄 |

**선생님 1액션, 학생 1액션** ← 앱 미사용보다 간단!

```
변경 포인트:
1. 선생님 제안 불필요: 시스템 자동 제안
2. 스케줄 유지: 이전과 동일 스케줄로 자동 생성
```

#### 시퀀스 다이어그램

```
[잔여 2회 시점]
    ↓
Auto: 갱신 제안 발송 ──→ S 알림
                     ──→ T 알림 (정보성)
    ↓
S: 수락 + 입금
    ↓
T: 입금 확인 탭 ──[자동]──→ 수강권 발급 (횟수 합산)
                          ──[자동]──→ 스케줄 유지 (이전과 동일)
    ↓
Done! ✅
```

## 4. 관점별 검증

### 4.1 UX 전문가 관점

| 기준 | 현재 | 개선 후 | 평가 |
|------|:----:|:------:|:----:|
| 학습 곡선 | 7단계 | 5단계 | ✅ |
| 인지 부하 | 높음 | 낮음 | ✅ |
| 완료까지 탭 수 | 10+ | 5-6 | ✅ |
| 에러 가능성 | 높음 | 낮음 | ✅ |

**핵심 개선:**
- **Hick's Law**: 선택지 감소 (템플릿 자동 선택)
- **Miller's Law**: 한 화면 정보량 감소
- **피츠의 법칙**: 주요 버튼 크기/위치 최적화

### 4.2 도메인 전문가 관점 (음악 레슨)

| 특성 | 반영 |
|------|------|
| 체험 후 결정 | ✅ 체험 후 자동 제안 |
| 정기 스케줄 | ✅ 체험 시간 기준 자동 |
| 장기 관계 | ✅ 이전 스케줄 유지 |
| 유연한 스케줄 | ✅ 필요 시 변경 가능 |

**핵심:**
- 체험 시간 = 정기 시간 가능성 90%+
- 재등록 시 스케줄 변경 = 10% 미만

### 4.3 선생님 관점

| 항목 | 현재 | 개선 후 | 개선 |
|------|------|---------|------|
| **신규 학생** | 4액션 | 2액션 | 50%↓ |
| **재등록** | 2액션 | 1액션 | 50%↓ |
| **스케줄 등록** | 수동 | 자동 | 100%↓ |
| **제안 발송** | 수동 | 자동 | 100%↓ |

**Pain Point 해결:**
- ❌ "학생에게 먼저 연락하기 어색" → ✅ 앱이 대신 제안
- ❌ "스케줄 매번 등록" → ✅ 자동 생성
- ❌ "결제 독촉" → ✅ 앱 자동 알림

### 4.4 학생 관점

| 항목 | 현재 | 개선 후 | 개선 |
|------|------|---------|------|
| **회원가입** | 별도 화면 | QR = 완료 | 100%↓ |
| **스케줄 선택** | 직접 선택 | 자동 제안 | 90%↓ |
| **재등록** | 2액션 | 1액션 | 50%↓ |

**Pain Point 해결:**
- ❌ "가입 복잡" → ✅ QR 스캔만
- ❌ "언제 레슨인지 헷갈림" → ✅ 자동 알림
- ❌ "선생님께 먼저 연락하기 어색" → ✅ 앱에서 쉽게 갱신

## 5. 자동 스케줄 로직

### 5.1 신규 학생

```
스케줄 기본값 = 체험 레슨 시간

예시:
- 체험: 토요일 15:00
- 정기: 토요일 15:00 (매주)
```

### 5.2 재등록

```
스케줄 기본값 = 이전 정기 레슨 시간

예시:
- 이전: 토요일 15:00 (매주)
- 갱신: 토요일 15:00 (매주) 유지
```

### 5.3 스케줄 변경이 필요한 경우

> 학생이 "다른 시간 선택" 버튼 탭 → 시간 선택 화면

```
┌─────────────────────────────────────────┐
│ 📅 레슨 스케줄                           │
├─────────────────────────────────────────┤
│                                         │
│  ✅ 체험과 동일 시간으로 등록            │
│     토요일 15:00 (매주)                 │
│                                         │
│  ─────────────────────────────          │
│                                         │
│  [다른 시간 선택하기]                    │  ← 필요한 경우만
│                                         │
└─────────────────────────────────────────┘
```

## 6. 병합 액션 상세

### 6.1 "입금 확인" 버튼의 동작

```dart
// 입금 확인 시 자동 처리
void onPaymentConfirmed() {
  // 1. 수강권 발급
  issueSubscription();

  // 2. 관계 상태 변경
  updateRelationStatus(RelationshipStatus.active);

  // 3. 스케줄 자동 생성
  if (isNewStudent) {
    createScheduleFromTrialTime();  // 체험 시간 기준
  } else {
    createScheduleFromPrevious();   // 이전 스케줄 유지
  }

  // 4. 알림 발송
  notifyStudent("수강권 발급 완료 + 스케줄 확정");
}
```

### 6.2 UI 변경

**현재:**
```
[입금 확인] → [수강권 발급] → [스케줄 등록 안내]
   (3개 화면)
```

**개선:**
```
[입금 확인] → 완료! (자동 발급 + 자동 스케줄)
   (1개 버튼)
```
