# 초대 시스템 UX 개선 브레인스토밍

> 작성일: 2025-12-28

## 배경

기존 초대 시스템(v1)의 복잡한 프로세스를 개선하기 위한 브레인스토밍 세션입니다.
인스타그램, 카카오톡, 페이스북 등 익숙한 플랫폼의 UX를 참고하여 개선 방향을 논의했습니다.

---

## 문제 정의

### 기존 시스템 문제점

| 단계 | 마찰 요소 |
|------|----------|
| 1 | 초대 화면 진입 필요 |
| 2 | 6자리 코드 기억/입력 |
| 3 | 연결 "요청" → "수락" 2단계 |
| 4 | 상대방이 앱 열어서 수락해야 함 |

### 타겟 사용자 고려

- 학부모 (디지털 기기 사용 미숙할 수 있음)
- 어린 학생 (복잡한 프로세스 어려움)
- 기존 플랫폼(카톡, 인스타)에 익숙한 사용자

---

## 경쟁사 분석

### 소셜 플랫폼 비교

| 플랫폼 | 연결 방식 | 특징 |
|--------|----------|------|
| 카카오톡 | QR/ID 공유 → 즉시 추가 | 단방향 (수락 불필요) |
| 인스타그램 | 프로필 → 팔로우 | 단방향 (공개), 양방향 (비공개) |
| 페이스북 | 친구 요청 → 수락 | 양방향 필수 |

### 음악 레슨 앱 비교

| 앱 | 연결 방식 | 특징 |
|-----|----------|------|
| My Music Staff | Student Portal | 학생/학부모가 포털 로그인 |
| Teachworks | 별도 계정 | 학생/학부모 self-serve 계정 |
| Duet | 포털 없음 | 문자/이메일로만 소통 |
| TuneKey | 앱 내 연결 | 자료 공유, 레슨 노트 |

### 인사이트

> Duet의 접근: "부모 포털과 비밀번호 필요 없이 문자로 소통"
> → 학부모 친화적 UX의 핵심!

## Q&A 세션

### Q1. 연결 승인 방식

| 옵션 | 설명 |
|:----:|------|
| A | 현재 유지 (요청→수락) |
| **B** | **초대 코드 = 자동 연결** |
| C | 1회용 코드 = 자동 연결 |
| D | 설정에서 선택 가능 |

**결정: B** - 카카오톡처럼 간단하게

---

### Q2. 코드 입력 방식 간소화

| 옵션 | 설명 |
|:----:|------|
| A | 6자리 유지 |
| B | 4자리로 축소 |
| **C** | **QR/링크 위주** |
| **D** | **전화번호/이메일 검색** |

**결정: C, D** - 카카오톡 친구추가와 유사하게

---

### Q3. 초대 진입점

| 옵션 | 설명 |
|:----:|------|
| **A** | **현재 유지 (헤더 버튼)** |
| B | 플로팅 버튼 |
| **C** | **학생 목록에서 "학생 추가"** |
| D | 온보딩 시 유도 |

**결정: A, C** - 헤더 버튼 유지 + 학생 목록에 추가 버튼

---

### Q4. 학부모/어린 학생 고려

| 우려 사항 | 개선 방안 |
|----------|----------|
| 코드 입력 어려움 | **전화번호 입력 가능** |
| 용어 혼란 | **친근한 용어로 개선** |
| 앱 설치 유도 | **링크 전송 시 자동 설치 유도** |

**결정: 모두 적용**

---

### Q5. 자동 연결 시 보안

| 옵션 | 설명 |
|:----:|------|
| A | 1회용 코드 |
| B | 유효기간 단축 (24시간) |
| C | A+B 조합 |
| **D** | **연결 후 알림 → 원치 않으면 해제** |

**결정: D** - 연결 후 알림으로 확인

---

### Q6. 전화번호 검색 범위

| 옵션 | 설명 |
|:----:|------|
| A | 가입자만 검색 |
| B | 미가입자 초대 |
| **C** | **연락처 동기화** |

**결정: C** - 카톡처럼 연락처에서 자동 매칭
- 전화번호 체계: +국가번호 전화번호 공통 구성

---

### Q7. 용어 개선안

| 현재 | 옵션 A | **옵션 B (선택)** |
|------|--------|------------------|
| 초대하기 | 학생 추가 | **선생님 찾기** (역할별) |
| 초대 코드 | 연결 코드 | **내 코드** |
| 연결 완료 | 추가 완료 | **연결되었습니다** |

**결정: B** - 역할별 친근한 용어

---

### Q8. 기존 "대기 중인 요청" 화면

| 옵션 | 설명 |
|:----:|------|
| A | 완전 제거 |
| B | 연결 기록으로 변경 |
| **C** | **알림 센터로 통합** |

**결정: C** - 알림 센터에서 연결 알림 확인

---

### Q9. 수기 등록 학생 vs 앱 연결

**새로운 요구사항**: 인스타 팔로우/팔로워처럼 상호 연결(맞팔) 개념 도입

| 상태 | 아이콘 | 색상 | 설명 |
|------|:------:|:----:|------|
| 앱 연결 | 🟢 | Green | 양쪽 모두 팔로우 (맞팔) |
| 초대 보냄 | 🟡 | Amber | 내가 팔로우, 상대 아직 |
| 초대 받음 | 🔵 | Blue | 상대가 팔로우, 내가 아직 |
| 오프라인 | ⚪ | Grey (연한) | 수기 등록만 (앱 미사용) |

---

### Q10. 수기 등록 학생의 기능 범위

| 옵션 | 범위 |
|:----:|------|
| **A** | **전체 가능** (레슨 기록, 결제, 연습 과제 - 선생님 관리) |
| B | 기본만 (레슨 기록, 결제) |
| C | 최소 (레슨 스케줄만) |

**결정: A** - 오프라인 학생도 전체 기능 사용 가능 (선생님이 관리)

---

## 결정 요약

| 항목 | 결정 |
|------|------|
| 연결 방식 | 자동 맞팔 (승인 단계 제거) |
