# 기존 관계 온보딩 시스템 - 브레인스토밍 Q&A

## 배경

이미 오프라인에서 레슨 중인 선생님-학생이 앱에 처음 진입할 때,
불필요한 체험레슨 단계를 거치지 않고 바로 연결할 수 있어야 함.

---

## Q&A 세션

### Q1. 기존 관계 연결 방식

**질문**: 기존에 레슨 중인 관계를 앱에서 연결할 때, 누가 주도해야 할까?

| 옵션 | 설명 |
|------|------|
| A. 선생님 주도 | 선생님이 학생 초대 코드/링크 발송 |
| B. 학생 주도 | 학생이 선생님에게 연결 요청 |
| **C. 양방향** | **둘 다 가능, 상대방 승인** ✅ |

**결정**: C - 양방향

---

### Q2. 기존 관계 증명 방식

**질문**: 체험레슨 없이 바로 연결할 때, 기존 관계를 어떻게 확인할까?

| 옵션 | 설명 |
|------|------|
| **A. 선생님 승인만** | **선생님이 "기존 학생입니다" 체크** ✅ |
| B. 초대 코드 | 선생님이 발급한 코드로 학생 등록 |
| C. 상호 확인 | 양쪽 모두 "기존 관계" 확인 |
| D. 레슨 이력 입력 | 레슨 시작일, 횟수 등 입력 |

**결정**: A - 선생님 승인만

---

### Q3. 선생님이 앱에 없는 경우

**질문**: 학생이 먼저 가입했는데 선생님이 앱에 없다면?

| 옵션 | 설명 |
|------|------|
| **A. 선생님 초대 기능** | **학생이 선생님에게 앱 초대 링크 발송** ✅ |
| B. 미등록 선생님 정보 등록 | 이름만 기록, 나중에 연결 |
| C. 불가 | 선생님 가입 필수 |

**결정**: A - 초대 기능

---

### Q4. 기존 레슨 유형 선택

**질문**: 기존 관계로 연결 시, 어떤 레슨 유형으로 시작할까?

| 옵션 | 설명 |
|------|------|
| A. 정기레슨 자동 | 기존 관계 = 이미 정기 진행 가정 |
| B. 선택 가능 | 정기 / 비정기 중 선택 |
| **C. 선생님 설정** | **프로필에서 가능한 레슨 유형 설정** ✅ |

**결정**: C - 선생님 설정에 따라 (체험/정기/1회)

---

### Q5. 선생님 레슨 설정 UI

**질문**: 선생님이 받을 수 있는 레슨 유형을 어디서 설정할까?

| 옵션 | 설명 |
|------|------|
| A. 프로필 설정 | 프로필 > 레슨 설정에서 토글 |
| **B. 가용시간 설정과 통합** | **정기=가용시간, 체험/1회=별도 토글** ✅ |
| C. 학생별 설정 | 각 학생마다 허용 레슨 유형 다르게 |

**결정**: B - 가용시간 설정과 통합 (정기레슨은 가용시간에서, 체험/1회는 별도 토글)

---

### Q6. 학생의 선생님 초대 플로우

**질문**: 학생이 선생님을 앱에 초대할 때 어떤 방식으로?

| 옵션 | 설명 |
|------|------|
| A. 링크만 | 초대 링크 복사 → 학생이 직접 전달 |
| B. 앱에서 발송 | 문자/카카오톡으로 앱에서 직접 발송 |
| **C. 둘 다** | **링크 복사 + 공유하기 버튼** ✅ |

**결정**: C - 둘 다

**입력 정보**:
- 선생님 이름 (필수)
- 연락처 (필수)
- 악기 (선택)

---

### Q7. 초대받은 선생님 가입 플로우

**질문**: 선생님이 학생 초대 링크로 가입할 때 어떻게 처리할까?

| 옵션 | 설명 |
|------|------|
| A. 자동 연결 | 가입 즉시 학생과 연결 (승인 생략) |
| **B. 연결 요청 표시** | **가입 후 학생의 연결 요청 알림 → 승인** ✅ |
| C. 선생님 선택 | 가입 후 대기중인 학생 목록 표시 → 선택 연결 |

**결정**: B - 연결 요청 표시

---

### Q8. 기존 관계 연결 시 추가 정보

**질문**: 체험 없이 바로 연결될 때, 레슨 정보를 언제 입력할까?

| 옵션 | 설명 |
|------|------|
| A. 연결 시 필수 | 연결 요청할 때 레슨 요일/시간 입력 |
| B. 연결 후 설정 | 먼저 연결, 나중에 레슨 일정 설정 |
| **C. 선생님이 설정** | **학생은 연결만, 선생님이 일정 등록** ✅ |

**결정**: C - 선생님이 설정

---

### Q9. 가용시간과 레슨 유형 통합 방식 확인

**질문**: Q5 답변 구체화

```
정기레슨: 가용시간 설정에서 시간대별 지정
체험/1회: 별도 ON/OFF 토글 (전체 적용)
```

**결정**: 확인됨 ✅

### Q10. 기존 학생 연결 후 선생님의 일정 등록

**질문**: 선생님이 레슨 일정을 등록할 때 타이밍은?

| 옵션 | 설명 |
|------|------|
| **A. 즉시 등록 유도** | **연결 승인 후 바로 "레슨 일정 등록" 화면으로 이동** ✅ |
| B. 나중에 등록 | 승인만 하고, 학생 상세에서 나중에 등록 |
| C. 알림으로 유도 | 승인 후 "레슨 일정을 등록해주세요" 알림 |

**결정**: A - 즉시 등록 유도

---

### Q11. 과거 레슨 이력 가져오기

**질문**: 기존 관계 연결 시, 과거 레슨 기록은 어떻게 할까?

| 옵션 | 설명 |
|------|------|
| A. 새로 시작 | 앱 연결 시점부터 기록 시작 |
| B. 시작일만 입력 | "레슨 시작일" 입력하여 기간 표시 |
| C. 수동 입력 가능 | 원하면 과거 레슨 기록 수동 입력 |

**결정**: A-C 선생님 선택 가능 (새로 시작이 기본, 원하면 과거 기록 수동 입력)

## 최종 결정 요약

| 항목 | 결정 |
|------|------|
| 연결 방식 | 양방향 (선생님/학생 모두 가능) |
| 관계 증명 | 선생님 승인만 |
| 선생님 없음 | 초대 기능 |
| 레슨 유형 | 선생님 설정 기반 |
| 설정 위치 | 정기=가용시간, 체험/1회=별도 토글 |
| 초대 방식 | 링크 복사 + 공유하기 |
| 초대 가입 후 | 연결 요청 알림 → 승인 |
| 레슨 정보 | 선생님이 설정 |
| 승인 후 | 즉시 일정 등록 화면 이동 |
| 과거 이력 | 선생님 선택 (새로 시작 or 수동 입력) |

### Q12. 정기레슨 중 특정 회차 변경

**질문**: 정기레슨 중 특정 주만 시간 변경이 필요할 때 어떻게 할까?

```
예: 매주 화요일 3시 레슨
    → 다음 주만 5시로 변경하고 싶음
```

| 옵션 | 설명 |
|------|------|
| A. 예외 회차 | 해당 주만 다른 시간으로 예외 등록 |
| B. 취소 + 1회 추가 | 해당 주 취소 → 1회 레슨으로 별도 예약 |
| **C. 둘 다** | **선생님/학생이 상황에 맞게 선택** ✅ |

**결정**: C - 둘 다 가능

### 추가 결정: 단일 레슨 프로세스 통합

**질문**: 체험레슨과 1회레슨의 스케줄 지정 방식

**결정**: 체험레슨과 1회레슨은 **동일한 프로세스, 타입만 다름**

```
[신규 예약]
학생 신청 → 선생님 컨펌

[일정 변경]
학생 스케줄 변경 요청 → 선생님 컨펌

[취소]
기존 정책과 동일

프로그램 관점:
- SingleLessonBooking 모델로 통합
- type 필드로 체험/1회 구분
- 예약/변경/취소 로직 100% 동일
```
