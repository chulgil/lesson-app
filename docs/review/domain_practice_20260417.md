## 한 줄 결론

**practice 도메인은 연습 화면·녹음 Phase 1~5·스트릭 로직 완성도가 가장 높은 핵심 자산이나, 뱃지·A/B 비교 재생·레퍼토리 히스토리 3개 차별화 기능이 "설계 완료·코드 0%" 상태이며, 자동 기록 vs 수동 체크 이중 입력 경로가 스펙 내부에 혼재한다.**

## 1. 구현 완성도 — 56%

### 완성된 영역
- 연습 화면/설정: 날짜 선택, 레퍼토리/섹션 CRUD ✅
- 스트릭 로직: 주말 제외, 레벨 시스템 ✅
- 녹음 Phase 1~5: 스마트 트림, A-B 루프, 속도 조절, 파형 ✅
- iOS 경로 복구, 백업 인프라 ✅
- 메트로놈/튜너 내장 도구 ✅

### 미구현 핵심 기능
1. **뱃지 시스템** — 설계 완료 (스트릭 레벨 4단계 + emoji 정의), 코드 0% → **학생 동기화 핵심**
2. **A/B 녹음 비교 재생 (Phase 2)** — 경쟁사 차별화 기능
3. **레퍼토리 히스토리 타임라인** — 엔티티 있음, UI 0%
4. **빠른 편집** — 설계 완료, 미구현
5. **연습 목표 + 노트** — 설계 완료, 미구현

### 스펙-코드 불일치
- `practice_master.md`: "Phase 1-2 구현 완료" → 실제로는 Phase 1만 완료 (섹션별 아이콘, 과제 N회 반복 스탬프 UI 미완)
- 날짜별 필터: 체크리스트 예정만, 미실장

## 3. 경쟁사 비교 핵심 Gap

| 차원 | Lessonaza | Practice Space / Tonara / Modacity | Gap |
|------|:---------:|:---------------------------------:|:---:|
| 메트로놈 + 튜너 통합 | ✅ 네이티브 | ❌ 부재 | **차별화 완성** |
| A-B 반복 재생 | 설계만 (Phase 2) | ✅ Modacity | **-1 Phase 지연** |
| 게이미피케이션 (뱃지/리더보드) | 🔜 뱃지 예정 | ✅ Tonara 강점 | **-90일 뒤처짐** |
| 연습 자동 기록 | 수동 체크 | ✅ Practice Space | **비자동 = UX 불리** |
| 선생님-학생 피드백 | 인프라 일부 | ✅ Tonara/PS | **채널 약함** |
| 레퍼토리 템플릿 | ✅ 설계 완료 | ❌ 전무 | **확실한 차별점** |

**가장 위험한 Gap**: 게이미피케이션 미구현 → 학생 동기 약화. Tonara 사용자가 Practice Space로 이동한 이유는 "뱃지와 목표 추적".

## 4. 편의성 개선 Top 5

1. **연습 자동 감지** (HIGH) — 메트로놈/튜너/녹음 시작 시 세션 자동 오픈, 종료 시 자동 저장 (Practice Space 모방)
2. **뱃지 시스템 즉시 완성** (CRITICAL) — 2-3일. Model, Provider, UI 리스트만 작성하면 됨
3. **A-B 비교 재생** (MEDIUM) — 섹션 상세 "비교 모드" 탭 추가 → 선생님 시범 vs 학생 연주 (Tonara Compare)
4. **히스토리 타임라인** (MEDIUM) — `RepertoireHistoryScreen` + Provider 10개 미만. "작년에 뭘 했죠?" 해소
5. **학부모 대시보드 연동** (LOW) — `StudentPracticeOverview` 모델 있음. 자녀 주간 요약 + 공유 녹음
