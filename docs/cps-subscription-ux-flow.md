## Context (맥락)

### 도메인

음악 레슨 앱(Lessonaza). 선생님-학생 간 수강권 발급 → 레슨 진행 → 스케줄 변경을 관리하는 플랫폼.

### 현재 구현 상태

| 단계 | 상태 | 비고 |
|------|:----:|------|
| 결제 프로세스 (제안→입금→확인) | ✅ 구현 | ProposalCreate → PaymentConfirm → IssueSubscription |
| 수강권 발급 | ✅ 구현 | 선생님 1탭으로 발급, active 상태 전환 |
| 수강권 목록 표시 | ⚠️ 부분 | 선생님 홈(최대 3개), 학생 홈(미니카드) — **발견성(Discoverability) 낮음** |
| 수강권 상세 화면 | ✅ 구현 | SessionProgressBar + 채팅형 이벤트 + 하단 액션바 |
| 스케줄 변경 (수강권 상세 내) | ✅ 구현 | 바텀시트 → 슬롯 선택 → 이벤트 기록 |
| 수강권 목록 → 상세 네비게이션 | ⚠️ 약함 | 라우트 존재하나 **진입 경로가 직관적이지 않음** |

### 이해관계자

| 역할 | 핵심 니즈 | 현재 불만 |
|------|----------|----------|
| **선생님** | 수강권 현황 한눈에 파악, 만료 관리, 미수금 추적 | 발급 후 "어디에서 보지?" |
| **학생** | 내 수강권 잔여 횟수 확인, 일정 변경 쉽게 | 수강권 발급됐는데 어디서 확인? |
| **학부모** | 자녀 수강권 상태 + 결제 내역 | 결제했는데 진행 상황 모름 |

### 참고 서비스 벤치마크

| 서비스 | 참고 포인트 |
|--------|-----------|
| **토스** | 카드 UI → 상세 드릴다운, 상태 전이 시각화, 알림→상세 딥링크, 미니멀 정보 노출 |
| **네이버 예약** | 예약 카드 → 상세 → 변경/취소, 상태 배지 (확정/대기/완료), 타임라인형 이력 |
| **Practice Space** | 구독 상태 대시보드, 잔여 세션 프로그레스바 |
| **스튜디오메이트** | 수강권 카드형 목록, 잔여 횟수 큰 숫자 표시, 만료일 D-day |

## Problem (문제)

### 핵심 문제

> **수강권 발급 후 "수강권이 있다"는 사실이 사용자에게 충분히 인지되지 않으며, 수강권→스케줄 변경→레슨 진행의 연속적 경험이 단절되어 있다.**

### 세부 문제

#### P-1. 수강권 발견성(Discoverability) 부족

**현상**: 수강권이 발급되었지만, 선생님 홈에서 최대 3개 카드로만 표시. 학생 홈에서는 미니 배지 수준.

**영향**: 
- 선생님: "발급했는데 잘 된 건가?" → 확인을 위해 학생 상세 → 수강권 섹션으로 3탭 이상 필요
- 학생: "수강권이 발급됐다는데 어디서 보지?" → 미니카드가 작아서 탭해야 하는지 모름
- 학부모: 수강권 표시 없음 → "돈 냈는데 어떻게 되고 있는 거야?"

**벤치마크 대비 격차**:
- 토스: 카드 발급 즉시 "카드가 발급되었어요" 풀스크린 → 바로 상세 진입
- 네이버 예약: 예약 완료 시 "예약이 확정되었습니다" + 예약 카드 바로 표시
- **현재 앱**: 발급 후 아무 피드백 없이 홈으로 복귀

#### P-2. 수강권 상세 → 스케줄 변경 연속성

**현상**: 수강권 상세 화면에 스케줄 변경 기능이 있지만, 사용자가 이 화면의 존재를 모름.

**영향**:
- 학생이 일정 변경을 원할 때 진입 경로를 모름
- 선생님이 학생에게 "앱에서 변경 신청해" 말해도 학생이 못 찾음
- 스케줄 변경 기능이 있지만 사용률 0% 예상

**벤치마크 대비 격차**:
- 네이버 예약: 예약 카드에 "변경/취소" 버튼 항상 노출
- 토스: 관련 액션을 카드 하단에 CTA로 제공
- **현재 앱**: 수강권 상세에 들어가야만 변경 버튼 보임

#### P-3. 상태 전이 가시성 부족

**현상**: 수강권 상태(active→expiringSoon→expired)가 코드에서는 자동 전환되지만, 사용자에게 상태 변화가 전달되지 않음.

**영향**:
- 선생님: 만료 예정 수강권을 놓쳐 갱신 타이밍을 놓침 → 학생 이탈
- 학생: 잔여 횟수가 줄어드는 것을 체감하지 못함
- 수강료 인상 근거 제시 불가 (성장 데이터 미활용)

#### P-4. 결제 후 → 수강권 활성 → 첫 레슨 예약의 단절

**현상**: 결제 확인 후 수강권이 발급되지만, "다음에 뭘 해야 하나?"가 불명확.

**영향**:
- 정규권: 자동 스케줄 생성되었는데 확인할 방법이 직관적이지 않음
- 회차권: 수강권은 있는데 예약을 어디서 하는지 모름
- 첫 레슨까지의 전환율(Conversion) 저하

### 현재 해결 방법과 한계

| 현재 방법 | 한계 |
|----------|------|
| 홈에 수강권 미니 위젯 | 작고 눈에 안 띔, 상세 진입이 직관적이지 않음 |
| 학생 상세에 수강권 섹션 | 선생님만 접근, 학생은 이 화면 못 봄 |
| 수강권 상세 내 스케줄 변경 | 수강권 상세를 찾아야 변경 가능 |
| 알림 (설계만) | FCM 미구현, 인앱 알림만 |

## Solution (솔루션)

### 솔루션 개요

**"수강권을 레슨 관계의 허브(Hub)로 만든다"** — 수강권 카드가 선생님/학생 양측의 중앙 진입점이 되어, 잔여 횟수 확인 · 일정 변경 · 레슨 기록 · 갱신까지 원스톱으로 접근.

### 핵심 원칙

| 원칙 | 참고 서비스 | 적용 |
|------|-----------|------|
| **즉시 피드백** | 토스 (카드 발급 완료 화면) | 수강권 발급 즉시 "발급 완료" 화면 + 상세 CTA |
| **상태 가시화** | 네이버 예약 (상태 배지) | 수강권 카드에 잔여 횟수, D-day, 상태 배지 상시 표시 |
| **액션 노출** | 토스 (카드 하단 CTA) | 수강권 카드에 "일정 변경" "레슨 기록" 바로가기 |
| **단계 안내** | 네이버 예약 (예약 완료 후 안내) | 발급 후 "다음 레슨은 X월 X일" 또는 "예약이 필요합니다" |

### 구성 요소

| 컴포넌트 | 역할 | 대상 | 상태 |
|---------|------|------|:----:|
| **수강권 발급 완료 화면** | 발급 직후 확인 + 다음 단계 안내 | 선생님/학생 | 신규 |
| **수강권 카드 (Enhanced)** | 잔여 횟수 + D-day + 액션 버튼 | 홈 화면 양측 | 개선 |
| **수강권 상세 (기존)** | 프로그레스바 + 채팅 + 스케줄 변경 | 양측 | 기존 유지 |
| **수강권 탭 (선생님)** | 전체 수강권 관리 — 활성/만료예정/만료 | 선생님 | 개선 |
| **내 수강권 (학생)** | 수강권 목록 + 빠른 액션 | 학생 | 개선 |
| **상태 변화 알림** | 만료 7일전, 회차 소진 임박, 갱신 안내 | 양측 | 설계 |

### 핵심 플로우

#### Flow 1: 결제 완료 → 수강권 발급 → 첫 레슨

```
[선생님: 입금 확인 1탭]
     │
     ▼
[수강권 자동 발급]
     │
     ├── 선생님 화면 ──────────────────────────┐
     │   "수강권이 발급되었습니다"              │
     │   ┌──────────────────────┐              │
     │   │ 김서연 바이올린       │              │
     │   │ ██████░░░░ 0/8회     │              │
     │   │ 매주 화 14:00~15:00  │              │
     │   │ [상세 보기] [닫기]    │              │
     │   └──────────────────────┘              │
     │                                          │
     └── 학생 화면 (푸시 알림) ─────────────────┘
         "수강권이 발급되었어요! 🎉"
         [수강권 확인하기] → 상세 화면
```

#### Flow 2: 수강권 카드 → 상세 → 스케줄 변경

```
[홈 화면]
  ┌──────────────────────────────┐
  │ 🎻 김서연 · 바이올린          │
  │ ██████████░░ 6/8회  D-14     │
  │ 다음: 4/22(화) 14:00         │
  │ [일정 변경]  [상세 →]         │  ← 카드에서 바로 액션
  └──────────────────────────────┘
       │              │
       │              ▼
       │         [수강권 상세]
       │         프로그레스바 + 챗 + 하단 액션바
       │
       ▼
  [스케줄 변경]
  변경 유형 선택 → 슬롯 선택 → 제안 전송
```

#### Flow 3: 만료 임박 → 갱신

```
[D-7 알림]
  "수강권이 7일 뒤 만료됩니다"
     │
     ▼
[수강권 카드: 만료 예정 배지]
  ┌──────────────────────────────┐
  │ ⚠️ 만료 예정                  │
  │ 🎻 김서연 · 바이올린          │
  │ ██████████████ 8/8회 완료     │
  │ 만료일: 4/30                  │
  │ [갱신 제안]  [상세 →]         │
  └──────────────────────────────┘
```

### UX 설계 원칙 (토스/네이버 참고)

#### 1. 카드형 정보 계층 (토스 패턴)

```
┌─ 수강권 카드 ─────────────────────┐
│                                    │
│  [상태 배지]  학생이름 · 악기      │  ← 1차: 식별
│                                    │
│  ████████░░░░  6/8회    D-14      │  ← 2차: 진행률 + 긴급도
│                                    │
│  다음 레슨: 4/22(화) 14:00        │  ← 3차: 다음 액션
│                                    │
│  [일정 변경]         [상세 보기]   │  ← 4차: CTA
│                                    │
└────────────────────────────────────┘
```

**토스 참고**: 계좌/카드 카드에서 "잔액/한도" → "최근 거래" → "더보기" 순서로 정보 노출. 사용자가 가장 궁금한 것(잔여 횟수)을 가장 크게 표시.

#### 2. 상태 배지 시스템 (네이버 예약 참고)

| 상태 | 배지 | 색상 | 설명 |
|------|------|:----:|------|
| active | 수강 중 | 초록 | 정상 진행 |
| expiringSoon | 만료 예정 | 주황 | D-7 이내 |
| expired | 만료됨 | 빨강 | 갱신 필요 |
| unpaid | 미수금 | 빨강 | 입금 대기 |
| completed | 수강 완료 | 회색 | 전체 소진 |

**네이버 참고**: 예약 상태(확정/대기/취소/완료)를 배지 색상으로 즉시 구분. 목록에서 스캔만으로 긴급 항목 식별.

#### 3. 스케줄 변경 접근성 (네이버 예약 참고)

**네이버 예약**: 예약 카드 하단에 항상 "변경 · 취소" 버튼 노출. 상세 페이지 진입 없이 바로 변경 시작 가능.

**적용**: 수강권 카드에 "일정 변경" 버튼을 직접 노출. 탭하면 바로 변경 유형 선택 바텀시트 → 슬롯 선택.

#### 4. 진행률 시각화 (스튜디오메이트 참고)

- 잔여 횟수를 **큰 숫자**로 표시 (6/8)
- 프로그레스바로 진행률 시각화
- D-day 표시로 긴급도 인지

### 역할별 화면 설계

#### 선생님 뷰

```
[홈 탭]
├── 오늘 레슨 (기존)
├── 수강권 현황 ← 개선
│   ├── 활성 N개 | 만료예정 N개 | 미수금 N건
│   ├── 수강권 카드 (Enhanced) × 최대 3
│   └── [전체 보기 →] → 수강권 관리 탭
└── 레슨 요청 (기존)

[수강권 관리] (TeacherSubscriptionListScreen 개선)
├── 필터 탭: 전체 | 활성 | 만료예정 | 만료
├── 수강권 카드 리스트
└── 각 카드 → 수강권 상세 (프로그레스바+챗)
```

#### 학생 뷰

```
[홈 탭]
├── 다음 레슨 카드 (기존)
├── 내 수강권 ← 개선
│   ├── 수강권 카드 (Enhanced)
│   │   - 잔여 횟수, 다음 레슨, D-day
│   │   - [일정 변경] [상세 →]
│   └── 수강권 없으면: "선생님에게 발급 요청" 안내
└── 연습 요약 (기존)
```

### 기술적 제약/결정

| 제약 | 대응 |
|------|------|
| FCM 미구현 | Phase 1은 인앱 알림 + 이벤트 스트립으로 대체, Phase 2에서 FCM |
| Mock 데이터 | 수강권 카드 UI는 Mock으로 구현, 백엔드 연동 시 Provider만 교체 |
| 오프라인 우선 | 수강권 데이터는 Hive에 캐시, 네트워크 복귀 시 동기화 |

### 범위 밖 (명시적 제외)

| 제외 항목 | 이유 |
|----------|------|
| 앱 내 결제 (PG 연동) | v1.0은 계좌이체 기록만 |
| 자동 갱신 | 선생님이 수동 제안하는 모델 유지 |
| 그룹 레슨 수강권 | 1:1 개인 레슨 우선 |
| 학부모 수강권 결제 화면 | 학부모 뷰는 조회만, 결제 액션은 Phase 2 |

## 점검 체크리스트

### UX 전문가 관점

- [ ] 수강권 발급 후 "발급 완료" 피드백이 있는가?
- [ ] 홈 화면에서 수강권 카드가 충분히 눈에 띄는가?
- [ ] 수강권 카드 → 상세 진입이 1탭인가?
- [ ] 스케줄 변경 버튼이 카드에서 바로 접근 가능한가?
- [ ] 상태 배지로 긴급 항목(만료예정, 미수금)이 즉시 식별되는가?
- [ ] 진행률(잔여 횟수)이 큰 숫자 + 프로그레스바로 표시되는가?
- [ ] "다음에 뭘 해야 하나?"가 항상 안내되는가?

### 기획 전문가 관점
