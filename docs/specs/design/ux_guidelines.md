## 1. 핵심 철학

### 1.1 타겟 사용자 특성

```
"음악인은 IT에 관심이 적으므로 최대한 심플하면서 효율적으로"
```

| 특성 | 설계 원칙 |
|------|----------|
| 연습 시간 부족 | **원클릭 완료** - 최소 입력으로 목적 달성 |
| IT 친숙도 낮음 | **직관적 UI** - 설명 없이도 이해 가능 |
| 다양한 연령대 | **가독성 우선** - 충분한 터치 영역, 명확한 텍스트 |
| 레슨 중 사용 | **빠른 접근** - 3초 내 원하는 화면 도달 |

### 1.2 3가지 황금 원칙

| 원칙 | 설명 | 예시 |
|------|------|------|
| **1. 원클릭** | 핵심 작업은 한 번의 탭으로 완료 | 연습 완료 체크, 좋아요 |
| **2. 재사용** | 동일 컴포넌트를 역할별로 다르게 표시 | 캘린더, 목록 카드 |
| **3. 얕은 뎁스** | 메뉴 진입 최대 2단계 | 홈 → 상세 (끝) |

## 2. 사용자 관점 원칙

> 참고: [UX 실패 사례 분석](https://brunch.co.kr/@leesy0203/25)

### 2.1 사용자 과제 집중

```
❌ 공급자 관점: "이 광고/기능을 노출하자"
✅ 사용자 관점: "사용자가 지금 뭘 하려고 하지?"
```

| 원칙 | 설명 | 예시 |
|------|------|------|
| **과제 집중** | 현재 사용자의 목표와 무관한 요소 배제 | 연습 기록 중 결제 배너 X |
| **맥락 존중** | 사용자의 현재 흐름을 방해하지 않음 | 레슨 예약 중 팝업 X |
| **비즈니스 자연 통합** | 수익화 요소도 자연스럽게 녹임 | 유료 기능은 필요 시점에 안내 |

### 2.2 사용자 언어 사용

```
❌ 개발자/전문가 용어: "내림차순", "오름차순", "동기화"
✅ 일상적 표현: "최신순", "오래된순", "새로고침"
```

| 피해야 할 표현 | 권장 표현 | 이유 |
|----------------|----------|------|
| 내림차순/오름차순 | 최신순/오래된순/이름순 | 정렬 의도가 명확함 |
| 동기화 | 새로고침, 불러오기 | 일상 언어 |
| 렌더링 | 표시, 보기 | 기술 용어 회피 |
| NULL, undefined | 미입력, 없음 | 에러 메시지 명확화 |
| 인스턴스, 엔티티 | 레슨, 학생, 과제 | 도메인 언어 사용 |

### 2.3 일관된 UI 경험

```
❌ 화면마다 다른 헤더/레이아웃
✅ 앱 전체에서 동일한 구조 유지
```

| 요소 | 일관성 규칙 |
|------|------------|
| **헤더** | 모든 화면 동일 높이/스타일 |
| **하단 탭** | 위치/아이콘/라벨 고정 |
| **카드 레이아웃** | 동일한 패딩/마진/그림자 |
| **버튼 스타일** | Primary/Secondary 구분 명확 |
| **색상 의미** | 녹색=성공, 빨간색=경고, 회색=비활성 |

### 2.4 ⚠️ Claude 작업 시 UI 일관성 필수 준수

```
🚨 중요: 동일한 기능은 반드시 동일한 UI 패턴을 사용해야 함
```

**원칙**: 한 화면에서 특정 패턴으로 설계했으면, 유사한 기능의 다른 화면도 동일하게 적용

| 상황 | Claude 행동 |
|------|------------|
| 기존 패턴 존재 | 기존 패턴을 따라 구현 |
| 기존 패턴과 다르게 구현하고 싶음 | **반드시 사용자 동의** 후 진행 |
| 기존 패턴 불명확 | 사용자에게 확인 후 결정 |

**예시: + 버튼 위치**
```
선생님 앱 레슨 탭: 캘린더 위 [+ 레슨 추가] 버튼
    ↓ 동일 패턴 적용 필수
학생 앱 연습 탭: 캘린더 위 [+ 레퍼토리 추가] 버튼
학생 앱 레슨 탭: 캘린더 위 [+ 레슨 추가] 버튼
```

**Claude 체크리스트**:
```markdown
UI 구현 전 확인사항:
- [ ] 유사한 기능이 다른 화면에 이미 구현되어 있는가?
- [ ] 있다면 동일한 UI 패턴을 사용했는가?
- [ ] 다르게 구현하려면 사용자에게 이유 설명 + 동의 요청했는가?
```

### 2.5 기술 부채 경계

```
⚠️ 기술 부채로 인한 UI 불일치가 사용자 경험을 해침
```

| 증상 | 원인 | 해결 |
|------|------|------|
| 특정 화면만 다른 스타일 | 조직/개발자 분리 | 디자인 시스템 준수 |
| 기능별 로딩 방식 상이 | 기술 스택 혼재 | 공통 컴포넌트 사용 |
| 용어 불일치 | 문서화 부재 | 용어집 관리 |

## 3. 정보 우선순위 원칙

> 참고: [경쟁사 UX 분석](competitor_ux_analysis.md)

### 3.1 대시보드 정보 계층

```
1순위: 긴급 (빨강/주황) - 즉시 액션 필요
       예: 미수금 D+, 예약 승인 대기, 결제 기한

2순위: 오늘 - 당일 해야 할 일
       예: 오늘의 레슨, 오늘의 과제

3순위: 트렌드 - 진행 현황/통계
       예: 스트릭, 이번주 연습, 이번달 레슨

4순위: 도구 - 필요시 접근
       예: 메트로놈, 튜너, 녹음
```

### 3.2 홈 화면 레이아웃 원칙

| 영역 | 내용 | 이유 |
|------|------|------|
| **상단** | 핵심 숫자 (오늘 레슨, 미수금, 완료율) | 한눈에 현황 파악 |
| **중상단** | ⚠️ 즉시 확인 필요 섹션 | 긴급 항목 놓치지 않도록 |
| **중앙** | 캘린더 + 오늘의 일정 | 핵심 정보 |
| **하단** | 빠른 도구 | 필요시 접근 |

### 3.3 긴급 표시 규칙

| 긴급도 | 색상 | 표시 | 예시 |
|--------|------|------|------|
| **긴급** | 🔴 빨강 | D+ (기한 초과) | 미수금 D+3 |
| **경고** | 🟠 주황 | D-7 이내 | 결제 기한 D-5 |
| **주의** | 🟡 노랑 | 임박 상태 | 수강권 2회 남음 |
| **정상** | 기본색 | - | 일반 상태 |

## 5. 역할별 화면 재사용

### 3.1 화면 재사용 원칙

```
┌─────────────────────────────────────────────────────────────┐
│  동일한 화면 컴포넌트를 역할에 따라 다르게 표시              │
│  - 레이아웃: 동일                                           │
│  - 데이터: 역할별 필터링                                    │
│  - 텍스트: 역할별 라벨 변경                                 │
│  - 액션: 역할별 권한에 따라 활성화/비활성화                 │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 선생님 ↔ 학부모 화면

**핵심**: 선생님과 학부모는 **관찰자** 역할이 동일하므로 같은 화면 재사용

| 화면 | 선생님 | 학부모 | 재사용 방식 |
|------|--------|--------|------------|
| 학생 목록 | 내 학생들 | 내 자녀들 | 타이틀만 변경 |
| 연습 현황 | 학생 연습 현황 | 자녀 연습 현황 | 타이틀만 변경 |
| 레슨 일정 | 학생별 레슨 일정 | 자녀별 레슨 일정 | 타이틀만 변경 |
| 과제 목록 | 학생 과제 현황 | 자녀 과제 현황 | 타이틀만 변경 |

```dart
// 구현 예시
class StudentListScreen extends StatelessWidget {
  final UserRole role; // teacher or parent

  String get title => role == UserRole.teacher ? '내 학생' : '내 자녀';
  String get emptyMessage => role == UserRole.teacher
      ? '아직 연결된 학생이 없습니다'
      : '아직 연결된 자녀가 없습니다';
}
```

### 3.3 역할별 차이점

| 구분 | 선생님 | 학부모 | 학생 |
|------|--------|--------|------|
| **데이터 권한** | 읽기/쓰기 | 읽기 전용 | 본인 데이터 읽기/쓰기 |
| **과제 관리** | 생성/수정 | 열람만 | 완료 체크 |
| **결제 관리** | 청구서 발행 | 결제 수행 | 열람만 |
| **피드백** | 작성 가능 | 열람만 | 열람만 |

### 3.4 읽기 전용 모드 표시

```
┌─────────────────────────────────────────┐
│ 자녀 연습 현황                    👁️    │  ← 눈 아이콘 = 열람 모드
├─────────────────────────────────────────┤
│ 🎻 라폴리아 1~4마디                     │
│ ☑️ 완료됨 · 12/28 14:30                 │  ← 체크박스 비활성화 (회색)
│                                         │
│ 🎻 스케일 G Major                       │
│ ☐ 미완료                                │  ← 탭해도 반응 없음
└─────────────────────────────────────────┘
```

## 6. 공통 컴포넌트

```dart
class LessonCalendar extends StatelessWidget {
  final CalendarView defaultView;  // weekly or monthly
  final bool canSwitchView;        // 뷰 전환 가능 여부

  // 모든 곳에서 동일한 컴포넌트 사용
  // - 디폴트 뷰만 상황에 따라 다름
  // - 사용자가 언제든 뷰 전환 가능

```

| 사용 위치 | 디폴트 뷰 | 전환 가능 | 이유 |
|----------|----------|----------|------|
| 선생님 대시보드 | 주간 | ✅ | 오늘/이번 주 레슨 집중 |
| 학생 대시보드 | 주간 | ✅ | 이번 주 연습/레슨 집중 |
| 레슨 관리 (선생님) | 월간 | ✅ | 전체 일정 파악 필요 |
| 레슨 예약 | 월간 | ✅ | 날짜 선택 편의 |
| 연습 기록 | 주간 | ✅ | 이번 주 연습 집중 |

### 4.2 목록 카드 컴포넌트

**원칙**: 일관된 카드 레이아웃, 내용만 다름

```
┌─────────────────────────────────────────────────────────┐
│ [아이콘] 제목                              [상태 뱃지]  │
│          부제목 · 추가정보                              │
│                                           [액션 버튼]  │
└─────────────────────────────────────────────────────────┘
```

| 사용처 | 아이콘 | 제목 | 부제목 | 상태 | 액션 |
|--------|--------|------|--------|------|------|
| 학생 카드 | 🎻 | 학생명 | 레벨 · 다음레슨 | 연습상태 | 상세 |
| 레슨 카드 | 📅 | 학생명 | 시간 · 악기 | 확정/대기 | 상세 |
| 과제 카드 | 📝 | 과제명 | 마감 · 우선순위 | 완료/미완료 | 체크 |
| 결제 카드 | 💰 | 금액 | 기간 · 학생명 | 결제/미결제 | 상세 |

### 4.3 바텀시트 컴포넌트

**원칙**: 상세 정보나 빠른 액션은 바텀시트로

```
사용 케이스:
1. 빠른 입력 (BPM 선택, 날짜 선택)
2. 상세 정보 미리보기
3. 액션 메뉴 (수정, 삭제, 공유)
4. 필터/정렬 옵션
```

### 4.4 공통 UI 요소

| 요소 | 용도 | 일관성 규칙 |
|------|------|------------|
| **토스트** | 성공/실패 피드백 | 하단 중앙, 2초 후 자동 닫힘 |
| **로딩** | 데이터 로드 중 | Shimmer 또는 스피너 |
| **빈 상태** | 데이터 없음 | 일러스트 + 안내 문구 + CTA |
| **에러** | 오류 발생 | 재시도 버튼 포함 |

## 7. 네비게이션 원칙

### 5.1 뎁스 최소화


## 11. 수강권 UI 가이드라인

> 참고: 스튜디오메이트, GX 시스템 UX 분석 결과 반영

### 11.1 수강권 카드 표준 레이아웃

수강권 정보는 학생이 가장 자주 확인하는 핵심 정보입니다.

```
[수강권 카드 - 표준 구조]
┌─────────────────────────────────────┐
│ 🎻 바이올린수강권            [활성] │  ← 이름 + 상태
│                                     │
│ 5/8회 남음                          │  ← 잔여/총횟수
│ ██████░░░░                          │  ← 프로그레스바
│                                     │
│ 📅 만료: 3/31   🔄 변경: 1/2회      │  ← 만료일 + 변경횟수
│                                     │
│ ⚠️ 변경 1회 남음                    │  ← 경고 (조건부)
└─────────────────────────────────────┘
```

**구성 요소:**
| 요소 | 필수 | 설명 |
|------|:----:|------|
| 수강권 이름 | ✅ | 선생님이 설정한 이름 (예: "바이올린수강권") |
| 상태 뱃지 | ✅ | 활성/만료/일시정지 |
| 잔여/총횟수 | ✅ | "N/M회 남음" |
| 프로그레스바 | ✅ | 잔여 비율 시각화 |
| 만료일 | ⚠️ | 기간제일 경우 필수 |
| 변경 가능 횟수 | ✅ | "🔄 변경: N/M회" |
| 경고 메시지 | ⚠️ | 임계값 도달 시 표시 |

### 11.2 경고 임계값 및 표시

**잔여 횟수 경고:**
| 조건 | 색상 | 표시 |
|------|------|------|
| ≤ 50% | 기본 | (경고 없음) |
| ≤ 25% | 🟡 | "N회 남음" |
| ≤ 2회 | 🟠 | "2회 남음 - 연장을 고려해주세요" |
| = 1회 | 🔴 | "마지막 1회!" |

**변경/취소 횟수 경고:**
| 조건 | 색상 | 표시 | 액션 |
|------|------|------|------|
| ≥ 2회 남음 | 기본 | "🔄 변경: N/M회" | 자유 변경 |
| = 1회 남음 | 🟡 | "⚠️ 변경 1회 남음" | 확인 다이얼로그 |
| = 0회 | 🔴 | "🚫 변경 불가" | 버튼 비활성화 |

**만료일 경고:**
| 조건 | 색상 | 표시 |
|------|------|------|
| > 7일 | 기본 | "만료: M/D" |
| ≤ 7일 | 🟡 | "⚠️ 7일 후 만료" |
| ≤ 3일 | 🔴 | "🚨 3일 후 만료!" |
| 만료 | ⛔ | "만료됨" (회색) |

### 11.3 변경/취소 시 확인 플로우

```
[변경 횟수 1회 남음 시 - 확인 다이얼로그]
┌─────────────────────────────────────┐
│  ⚠️ 변경 횟수 주의                   │
│                                     │
│  현재: 1/2회 사용                    │
│  변경 후: 2/2회 (마지막 변경!)       │
│                                     │
│  이후 더 이상 변경/취소가            │
│  불가합니다.                         │
│                                     │
│  [취소]           [변경하기]         │
└─────────────────────────────────────┘
```

```
[변경 횟수 0회 - 변경 불가 상태]
┌─────────────────────────────────────┐
│  🚫 변경 불가                        │
│                                     │
│  이 수강권의 변경/취소 횟수를        │
│  모두 사용했습니다.                  │
│                                     │
│  선생님에게 문의해주세요.            │
│                                     │
│  [확인]                              │
└─────────────────────────────────────┘
```

## 12. 슬롯 상태 색상 체계

### 12.1 예약 상태 색상

모든 예약 관련 화면에서 일관된 색상을 사용합니다.

| 상태 | 아이콘 | HEX | RGB | 사용처 |
|------|:------:|-----|-----|--------|
| **예약 가능** | 🟢 | #4CAF50 | 76, 175, 80 | 빈 슬롯, 정원 여유 |
| **내 예약** | 🔵 | #2196F3 | 33, 150, 243 | 내가 예약한 슬롯 |
| **거의 만석** | 🟡 | #FFC107 | 255, 193, 7 | 정원 80% 이상 |
| **만석 (대기 가능)** | 🟠 | #FF9800 | 255, 152, 0 | 정원 100% |
| **예약 불가** | ⛔ | #9E9E9E | 158, 158, 158 | 휴무, 마감, 타인 예약 |

### 12.2 색상 적용 위치

**캘린더 뷰:**
```
┌────┬────┬────┬────┬────┬────┬────┐
│ 월 │ 화 │ 수 │ 목 │ 금 │ 토 │ 일 │
├────┼────┼────┼────┼────┼────┼────┤
│    │🟢14│    │⛔16│    │🔵10│    │
│    │🟢15│    │휴무│    │🟡11│    │
└────┴────┴────┴────┴────┴────┴────┘

🟢 = 예약 가능  🔵 = 내 예약  🟡 = 거의 만석  ⛔ = 예약 불가
```

**슬롯 목록:**
```
┌─────────────────────────────────────┐
│ 2/18(화) 14:00        🟢 예약 가능  │
│ 2/18(화) 15:30        🔵 내 예약    │
│ 2/20(목) 16:00        ⛔ 휴무       │
│ 2/22(토) 10:00        🟡 5/6명      │ ← 그룹레슨
│ 2/22(토) 14:00        🟠 만석       │
└─────────────────────────────────────┘
```

### 12.3 색상 범례 표시 원칙

- 예약 화면 상단에 항상 색상 범례 표시
- 아이콘 + 텍스트 조합 (색맹 접근성)
- 첫 사용자도 이해할 수 있도록 직관적 라벨

```
[색상 범례 - 항상 표시]
🟢 예약가능  🔵 내 예약  🟡 거의만석  🟠 만석  ⛔ 불가
```
