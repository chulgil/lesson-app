# 선생님 빠른 레슨 등록 (Quick Add Lesson)

> 작성일: 2026-03-02
> 상태: 스펙 검토 중
> 관련: [정기 레슨 플로우](flow_regular.md) | [통합 예약 스펙](Unified_Lesson_Booking_Spec.md)

---

## 개요

### 문제

선생님이 홈에서 레슨을 추가할 때 **최소 10탭**이 필요함.
정기 레슨 학생의 패턴 데이터(`lessonDay`, `lessonTime`, `lessonDuration`)가 존재하지만 활용되지 않음.

### 목표

| 현재 | 목표 | 방법 |
|:----:|:----:|------|
| 10탭 | **3탭** | 학생 선택 → 정기 패턴 자동 완성 → 저장 |

### 범위

이 스펙은 **선생님이 직접 레슨을 등록**하는 플로우만 다룸.
학생측 수강권 기반 예약은 [통합 예약 스펙](Unified_Lesson_Booking_Spec.md) 참조.

## 핵심 변경: 학생 선택 시 자동 완성

### 자동 완성 데이터 출처

```
Student 엔티티
├── lessonDay        → 다음 레슨 날짜 계산
├── lessonTime       → 시간 자동 입력
└── lessonDuration   → 레슨 시간 자동 선택

ClassMembership 엔티티 (보조)
├── lessonsPerWeek   → 정기 레슨 빈도
└── lessonDay/Time   → Student 필드와 동일 (우선순위: Membership > Student)
```

### 자동 완성 로직

```
학생 선택 시:
1. lessonDay가 있으면 → 오늘 이후 가장 가까운 해당 요일로 날짜 설정
2. lessonTime이 있으면 → 시간 자동 입력
3. lessonDuration이 있으면 → 레슨 시간 칩 자동 선택
4. 마지막 레슨의 곡명이 있으면 → 곡 제목 힌트 표시 ("이전: 바흐 파르티타 2번")

모든 자동 완성 값은 사용자가 수정 가능
```

## 진입 경로별 개선

### 경로 1: 홈 → [레슨 추가] (핵심 개선 대상)

**현재**: 파라미터 없이 빈 폼 열림 (10탭)

**개선 후**:

```
홈 → [레슨 추가]
  └→ date=오늘, hour=현재+1h 자동 전달 (스케줄탭과 동일 정책)
  └→ 학생 선택 시 → 정기 패턴 자동 완성
```

**변경 사항**:
```dart
// 현재 (home_screen.dart)
context.push('/lessons/add');  // 파라미터 없음

// 개선
final now = DateTime.now();
int nextHour = now.hour + 1;
if (nextHour > 23) nextHour = 9;
final dateStr = DateFormat('yyyy-MM-dd').format(now);
context.push('/lessons/add?date=$dateStr&hour=$nextHour');
```

### 경로 2: 오늘 레슨 카드 → [다음 레슨 추가] (신규)

**현재**: 없음

**추가**:
오늘의 레슨 카드에 `[↻]` (반복) 아이콘 버튼 추가.
탭 시 해당 학생의 **다음 주 동일 시간**으로 레슨 자동 생성.

```
┌─────────────────────────────────────────┐
│  14:00  홍길동 · 바이올린                  │
│  바흐 파르티타 2번 · 60분        [↻] [>] │
└─────────────────────────────────────────┘
                                    ↑
                          다음 레슨 추가 (1탭)
```

**동작**:
```
[↻] 탭 → 확인 다이얼로그:
  "홍길동 다음 레슨을 추가할까요?"
  다음 주 월요일 14:00 · 60분
  [취소] [추가]
```

이 경로의 탭 수: **2탭** (아이콘 탭 + 확인)

### 경로 3: 학생 상세 → FAB (기존 개선)

**현재**: `studentId`만 전달, 날짜/시간은 기본값

**개선 후**:
```
studentId + Student의 lessonDay/lessonTime/lessonDuration 자동 완성
→ 폼이 대부분 채워진 상태로 열림
→ 확인 후 저장만 하면 됨
```

탭 수: **2탭** (FAB + 저장)

## 개선 후 탭 수 비교

| 진입 경로 | 현재 | 개선 후 | 절감 |
|----------|:----:|:------:|:----:|
| 홈 → [레슨 추가] | 10탭 | **3탭** | -70% |
| 레슨 카드 → [↻ 반복] | 없음 | **2탭** | 신규 |
| 스케줄탭 → [+] | 8탭 | **3탭** | -63% |
| 학생상세 → FAB | 4~5탭 | **2탭** | -50% |

### 3탭 시나리오 (홈 → 레슨 추가)

```
[레슨 추가] 탭 (1)
  └→ 폼 열림: 날짜=오늘, 시간=현재+1h, 레슨시간=60분
  └→ 학생 선택 바텀시트 탭 (2)
      └→ 학생 선택 → 정기 패턴으로 날짜/시간/수업시간 자동 갱신
  └→ [저장] 탭 (3)
```

### 2탭 시나리오 (레슨 카드 반복)

```
레슨 카드의 [↻] 탭 (1)
  └→ 확인 다이얼로그: "다음 주 월 14:00 추가?"
  └→ [추가] 탭 (2)
  └→ 완료 (토스트: "3/10(월) 14:00 레슨이 추가되었습니다")
```

## 과거 레슨 기록 모드 (Record Mode)

> 추가일: 2026-03-15
> 업계 분석: Tonara, My Music Staff, Fons, Teachworks 등 10개 앱 참고

### 업계 표준

**"소급 레슨 추가"라는 개념은 업계에 없다.** 모든 앱이 "예약 → 시간 경과 → 출석 확인" 패턴을 따른다.
하지만 현실적으로 앱 밖에서 진행한 레슨을 기록해야 하는 시나리오가 있다.

### 설계 원칙

과거 날짜 선택 시 **자동으로 "레슨 기록 모드"로 전환**하여 기록/예약 혼동을 방지한다.

### 레슨 추가 모드 분기

| 조건 | 모드 | status | 수강권 차감 | 학생 표시 |
|------|------|:------:|:----------:|:--------:|
| 미래 날짜 + 단일 | 예약 모드 | `scheduled` | X (완료 시 차감) | "예정" |
| 미래 날짜 + 정기 | 예약 모드 | `scheduled` | X | "예정" |
| 과거 날짜 + 단일 | **기록 모드** | `completed` | **O (즉시)** | "완료" |

### 기록 모드 UI 변경

| 항목 | 예약 모드 | 기록 모드 |
|------|----------|----------|
| AppBar 제목 | 레슨 추가 | **레슨 기록** |
| 저장 버튼 | 레슨 추가하기 | **레슨 기록하기** |
| 정기 레슨 섹션 | 표시 | **숨김** |
| 리마인더 섹션 | 표시 | **숨김** |
| 날짜 아이콘 | `calendar_today` | **`history`** (주황) |
| 경고 배너 | 없음 | **"과거 시간입니다..."** |
| 저장 확인 | 없음 | **과거 레슨 기록 다이얼로그** |

### 저장 확인 다이얼로그 내용

```
[과거 레슨 기록]

선택한 시간은 이미 지난 시간입니다.

┌──────────────────────────────┐
│ 레슨 기록 시:                 │
│ • "완료" 상태로 저장됩니다     │
│ • 수강권이 있으면 1회 자동 차감 │
│ • 학생에게 레슨 기록으로 표시   │
└──────────────────────────────┘

[취소]  [레슨 기록]
```

### 수강권 차감 정책

- 활성 수강권 있음 → 자동 1회 차감, UsageType: `normal`, note: "레슨 기록 (사후 등록)"
- 활성 수강권 없음 → 차감 없이 레슨만 기록 (info 배너로 안내)
- 차감 실패 → 레슨 생성은 유지, 차감만 skip (선생님이 수동으로 관리)

### 과거 날짜 허용 범위

DatePicker에서 **과거 7일**까지만 허용. 이유:
- 7일 이상 지난 레슨은 기억이 부정확
- 현실적으로 "이번 주 레슨 사후 기록" 시나리오만 지원

### 학생 측 표시

학생 캘린더에서 과거 기록 레슨은 일반 `completed` 레슨과 동일하게 표시된다.
`displayStatus` getter가 DB의 `completed` 상태를 그대로 반환하므로 별도 처리 불필요.

## 경로 4: 학생 선택 시트 → [+ 새 학생 등록] (2026-08-03 신규)

신규 학생의 체험 레슨을 잡는 경로. AddLessonScreen 학생 선택 시트 최상단에
**[+ 새 학생 등록]** 항목을 추가한다.

```
스케줄 (+) → AddLessonScreen → 학생 선택 시트
  └→ [+ 새 학생 등록] → add_student (직접 등록: 이름 + 연락처 최소 입력)
       └→ 등록 완료 → 시트 복귀 + 방금 학생 자동 선택
            └→ 체험 1회권 자동 발급 배너 → 날짜/시간 저장  (총 4~5탭)
```

- 이 경로에서는 등록 직후 "수강권을 발급하시겠습니까?" 다이얼로그 스킵.
- 수강권 분기·발급 연속 플로우: [subscription_required_spec.md §2.6](../subscription/subscription_required_spec.md)
