## 1. 현재 상태 분석

### 1.1 현재 모델 구조

```
┌─────────────────────────────────────────────────────────────┐
│                      현재 구조 (1:1 관계)                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Teacher ─────────────────────────────── Student           │
│      │                                       │              │
│      └── 직접 관리 (1:N)                      └── 1명의 선생님 │
│                                                             │
│   ⚠️ 문제점:                                                 │
│   • organizationId 없음 (학원 소속 표현 불가)                 │
│   • TeacherStudentRelation 없음 (Context 표현 불가)          │
│   • 다중 소속 불가능                                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 현재 Student 모델 필드

```dart
class Student {
  final String id;
  final String name;
  final String instrument;
  final StudentLevel level;
  final StudentStatus status;
  final int monthlyFee;
  // ... (레슨 정보)
  final ConnectionStatus connectionStatus;  // 앱 연결 상태
  final DateTime? connectedAt;
  // ❌ organizationId 없음
  // ❌ teacherId 없음 (implicit 관계)
}
```

### 1.3 현재 Teacher 모델 필드

```dart
class Teacher {
  final String id;
  final String name;
  final List<String> instruments;
  // ... (프로필 정보)
  // ❌ organizationId 없음
  // ❌ memberships 없음
}
```

## 2. 3자 관계 핵심 시나리오

### 2.1 시나리오 A: 학원 강사로 레슨

```
[학원 OO음악학원]
      │
      ├── 소속 강사: 선생님 A
      │       │
      │       └── 담당 학생: 학생 1, 학생 2
      │
      └── 소속 강사: 선생님 B
              │
              └── 담당 학생: 학생 3

특징:
• 수강권은 학원에서 발행
• 레슨 기록은 학원에 귀속
• 강사 퇴사 시 학원에 기록 보존
```

### 2.2 시나리오 B: 개인 레슨 + 학원 레슨 병행 (선생님)

```
[선생님 A]
    │
    ├── OO음악학원 소속 (강사)
    │   └── 학원 학생 1, 2, 3
    │
    ├── XX피아노학원 소속 (강사)
    │   └── 학원 학생 4, 5
    │
    └── 개인 레슨 (독립)
        └── 개인 학생 6, 7

UI 필요:
• 소속 전환 (Context Switch)
• 학생 목록 필터링
• 레슨 기록 시 Context 선택
```

### 2.3 시나리오 C: 학원 레슨 + 개인 레슨 병행 (학생)

```
[학생 B]
    │
    ├── OO음악학원에서 바이올린 레슨 (선생님 A)
    │   └── 8회권 수강권
    │
    └── 개인적으로 피아노 레슨 (선생님 C)
        └── 월정액 수강권

UI 필요:
• 내 레슨 목록 (선생님 + Context 표시)
• 레슨 일정 통합 캘린더
• 연습 기록 (악기별 분리 가능)
```

### 2.4 시나리오 D: 혼자 연습 (선생님 없이)

```
[학생 C]
    │
    └── 연습 공간 (PracticeSpace)
        └── 메트로놈, 튜너, 녹음 사용
        └── 연습 기록 작성

UI 필요:
• 선생님 연결 없이 연습 기능 접근
• 나중에 선생님 초대 가능
```

## 3. 데이터 모델 설계

### 3.1 핵심 원칙

```
"organizationId가 null이면 개인, 있으면 학원"
```

### 3.2 모델 확장 계획

#### Phase 1: Context 필드 추가 (기존 모델 확장)

```dart
// Student 확장
class Student {
  // ... 기존 필드
  final String? organizationId;         // 🆕 학원 소속 (null = 개인)
  final String? assignedTeacherId;      // 🆕 담당 선생님 ID
  final String? currentSubscriptionId;  // 🆕 현재 활성 수강권
}

// Teacher 확장 (TeacherProfile로 통합 고려)
class Teacher {
  // ... 기존 필드
  final List<String> organizationIds;   // 🆕 소속 학원들 (다중 소속)
}

// Lesson 확장
class Lesson {
  // ... 기존 필드
  final String? organizationId;         // 🆕 학원 Context
  final String? subscriptionId;         // 🆕 연결된 수강권
}
```

#### Phase 2: 관계 모델 추가

```dart
/// 선생님-학생 관계 (Context 포함)
/// 한 학생이 같은 선생님에게 학원 레슨 + 개인 레슨 동시 가능
class TeacherStudentRelation {
  final String id;
  final String teacherId;
  final String studentId;
  final String? organizationId;     // null = 개인 레슨
  final String? subscriptionId;     // 연결된 수강권
  final String? instrument;         // 악기 (바이올린, 피아노 등)
  final RelationStatus status;      // active, paused, ended
  final DateTime createdAt;
  final DateTime? endedAt;
}

/// 관계 상태
enum RelationStatus {
  active,   // 레슨 진행 중
  paused,   // 일시 중지
  ended,    // 종료
}
```

#### Phase 3: 학원 멤버십 (학원 모드 전용)

```dart
/// 학원 멤버십 (선생님 1명 → 여러 학원 가능)
class Membership {
  final String id;
  final String organizationId;
  final String userId;              // 선생님 ID
  final MemberRole role;            // owner, manager, instructor
  final MemberStatus status;        // active, inactive, terminated
  final DateTime joinedAt;
  final DateTime? terminatedAt;
}

enum MemberRole {
  owner,       // 대표
  manager,     // 매니저
  instructor,  // 강사
}
```

### 3.3 모델 관계도 (목표 상태)

```
┌─────────────────────────────────────────────────────────────┐
│                      목표 구조 (N:M + Context)                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Organization (학원)                                        │
│        │                                                    │
│        ├── Membership ─── Teacher (선생님)                   │
│        │                      │                             │
│        │                      └── TeacherStudentRelation    │
│        │                              │                     │
│        └── Student ◄──────────────────┘                    │
│              │                                              │
│              └── Subscription (수강권)                       │
│                      │                                      │
│                      └── Lesson (레슨 기록)                  │
│                                                             │
│   ※ organizationId = null 이면 개인 모드                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 4. 레슨 장소 시스템

### 4.1 장소 유형

스튜디오메이트와 같이 레슨 장소를 체계적으로 관리합니다.

| 유형 | 아이콘 | 설명 | 예시 |
|------|:-----:|------|------|
| **학원 레슨실** | 🏫 | 학원 내 지정 공간 | 레슨실 1, 레슨실 2, 그랜드피아노실 |
| **선생님 스튜디오** | 🏠 | 선생님 개인 공간 | 홈스튜디오, OO빌딩 301호 |
| **학생 집 방문** | 🚗 | 출장 레슨 | 학생 자택 |
| **외부 장소** | 📍 | 대여 연습실 등 | 연습실 카페, 음악학원 대여 |
| **온라인** | 💻 | 화상 레슨 | Zoom, 구글 미트, FaceTime |

### 5.2 데이터 모델

#### LessonLocation (레슨 장소)

```dart
/// 레슨 장소 유형
enum LocationType {
  academyRoom,     // 🏫 학원 레슨실
  teacherStudio,   // 🏠 선생님 스튜디오
  studentHome,     // 🚗 학생 집 방문
  externalPlace,   // 📍 외부 장소
  online,          // 💻 온라인
}

/// 레슨 장소
class LessonLocation {
  final String id;
  final String name;                    // "레슨실 1", "홈스튜디오"
  final LocationType type;
  final String? organizationId;         // 학원 소속 (학원 레슨실인 경우)
  final String? ownerId;                // 소유자 (선생님 ID)

  // 주소 정보
  final String? address;                // 전체 주소
  final String? addressDetail;          // 상세 주소 (동/호수)
  final double? latitude;               // 위도 (지도용)
  final double? longitude;              // 경도 (지도용)

  // 온라인 정보
  final String? onlinePlatform;         // "zoom", "google_meet", "facetime"
  final String? onlineLink;             // 미팅 링크 (선택)

  // 메타
  final String? notes;                  // 찾아오는 길, 주차 정보 등
  final bool isDefault;                 // 기본 장소 여부
  final bool isActive;                  // 활성 상태
  final DateTime createdAt;
}
```

#### 학원 레슨실 (Room)

```dart
/// 학원 레슨실 (학원 모드 전용)
class AcademyRoom {
  final String id;
  final String organizationId;          // 학원 ID
  final String name;                    // "레슨실 1"
  final String? description;            // "그랜드 피아노 보유"
  final int? capacity;                  // 수용 인원
  final List<String> equipment;         // 보유 장비 ["그랜드피아노", "보면대"]
  final String? color;                  // 캘린더 표시 색상
  final int sortOrder;                  // 정렬 순서
  final bool isActive;
}
```

#### Lesson 모델 확장

```dart
class Lesson {
  // ... 기존 필드

  // 🆕 장소 관련 필드

  final LocationType? locationType;     // 장소 유형 (빠른 조회용)
```

## 6. 구현 전략

### 6.1 점진적 마이그레이션 전략

```
현재 상태: 1:1 관계 (Teacher → Students)
    │
    ▼
Phase 1: organizationId 필드 추가 (null = 개인)
    │      • 기존 데이터: organizationId = null (개인)
    │      • 신규 학원 가입 시 organizationId 설정
    │
    ▼
Phase 2: TeacherStudentRelation 도입
    │      • 기존 관계 마이그레이션
    │      • Context 기반 레슨 기록
    │
    ▼
Phase 3: Membership (학원 역할) 도입
    │      • 학원 가입/초대 플로우
    │      • 역할별 권한 체크
    │
    ▼
Phase 4: 학원 관리 기능 (웹 대시보드)
         • 학원 설정
         • 강사 관리
         • 매출 리포트
```

### 6.2 하위 호환성 보장

```dart
/// 기존 코드 호환성 유지
extension StudentCompatibility on Student {
  /// 개인 레슨 학생인지 확인
  bool get isPersonalStudent => organizationId == null;

  /// 기존 로직 호환: teacherId 접근
  /// (TeacherStudentRelation 도입 전까지 사용)
  String get teacherId => _legacyTeacherId ?? assignedTeacherId ?? '';
}
```

## 8. Q&A

### Q1: 기존 개인 선생님 사용자는 어떻게 되나요?

**A**: 아무 영향 없습니다. 기존 방식 그대로 사용 가능합니다.

```
기존 사용자:
• organizationId = null (개인)
• 학생 관리, 레슨 기록 동일
• 학원 기능은 옵트인 (가입 시에만 활성화)
```

### Q2: 같은 학생을 학원/개인 양쪽에서 가르칠 수 있나요?

**A**: 네, TeacherStudentRelation으로 가능합니다.

```dart
// 학원 레슨 관계
TeacherStudentRelation {
  teacherId: "선생님A",
  studentId: "학생B",
  organizationId: "OO음악학원",
  instrument: "바이올린"
}

// 개인 레슨 관계 (같은 선생님-학생)
TeacherStudentRelation {
  teacherId: "선생님A",
  studentId: "학생B",
  organizationId: null,  // 개인
  instrument: "피아노"
}
```

### Q3: 학원 없이 혼자 연습만 하는 학생은?

**A**: 지원됩니다. PracticeSpace 아키텍처 그대로입니다.

```
학생 앱:
• 선생님 연결 없이 연습 기능 사용
• 메트로놈, 튜너, 녹음 모두 가능
• 나중에 선생님 초대 가능
```

### Q4: Context 전환이 번거롭지 않나요?

**A**: "전체 보기"를 기본값으로 하여 Context 전환 최소화합니다.

```
선생님 앱 기본값: 전체 보기
• 모든 학생 통합 조회
• 필요시에만 학원별 필터링
• 레슨 기록 시에만 Context 선택 (필수)
```

### Q5: 레슨 장소는 어떻게 관리하나요?

**A**: 선생님 설정에서 장소를 미리 등록해두고, 레슨 기록 시 선택합니다.

```
개인 선생님:
• 내 스튜디오, 온라인 등 장소 등록
• 기본 장소 설정 → 레슨 기록 시 자동 선택
• 학생 집 방문은 별도 주소 입력

학원 모드:
• 학원에서 레슨실 관리 (레슨실 1, 2, 3...)
• 강사는 학원 레슨실 중 선택
• 레슨실 충돌 시 경고 표시
```

### Q6: 온라인 레슨은 어떻게 처리하나요?

**A**: 온라인 장소 유형으로 Zoom/구글 미트/FaceTime 지원합니다.

```
온라인 장소 설정:
• 플랫폼 선택 (Zoom, Google Meet, FaceTime)
• 고정 미팅 링크 설정 (선택)
• 레슨별 링크 입력도 가능

학생 앱:
• [미팅 참여하기] 버튼으로 바로 접속

```
