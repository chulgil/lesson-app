## 개요

네이버 미용실 예약 시스템을 참고한 통합 레슨 신청 플로우.
기존 "체험레슨 신청"을 "레슨 신청"으로 확장하여 모든 유형의 레슨을 하나의 플로우로 처리.

### 기존 시스템의 한계

1. **레슨 재개 불가**: 정규레슨 종료 후 같은 선생님께 다시 레슨 신청하는 방법 없음
2. **추가 레슨 불가**: 정규레슨 진행 중 1회 추가 레슨을 요청하는 방법 없음
3. **분리된 플로우**: 체험→정규 전환이 별도 프로세스로 복잡

### 목표

- 모든 레슨 신청을 **하나의 통합 플로우**로 처리
- 선생님-학생 관계에 따라 **자동으로 옵션 활성화/비활성화**
- 사용자 학습 비용 최소화

## 레슨 유형

### LessonType

| 값 | 설명 | 대상 |
|----|------|------|
| `trial` | 체험레슨 - 첫 만남, 상호 평가용 1회 | 새로운 선생님 |
| `regular` | 정기레슨 - 매주 고정 요일/시간 | 연결된/이전 선생님 |
| `oneTime` | 1회 레슨 - 단발성 추가 레슨 | 연결된/이전 선생님 |

→ 엔티티 정의: [booking.md](../../schema/entities/booking.md#lessontype-레슨-유형)

## 선생님-학생 관계

### TeacherStudentRelation

| 값 | 설명 |
|----|------|
| `none` | 처음 만남 (이력 없음) |
| `active` | 현재 정규레슨 진행 중 |

| 관계 | 체험 | 정기 | 1회 | 설명 |
|------|:----:|:----:|:----:|------|
| `none` | ✅ | ❌ | ❌ | 첫 만남은 체험부터 |
| `active` | ❌ | ❌ | ✅ | 이미 정기 진행중, 추가만 가능 |
| `inactive` | ❌ | ✅ | ✅ | 재개 또는 1회 가능 |

## 통합 레슨 신청 플로우

### 전체 흐름

```
[선생님 목록/검색]
       ↓
[선생님 선택] → 관계 확인
       ↓
[레슨 유형 선택] ← 관계에 따라 활성화
       ↓
[일정 선택]
  - 체험/1회: 단일 날짜+시간
  - 정기: 요일 + 시작일 + 기간
       ↓
[추가 정보 입력]
  - 체험: 레슨 목표, 현재 수준
  - 정기/1회: 요청사항 (선택)
       ↓
[신청 확인 & 제출]
       ↓
[선생님 알림] → 승인/거절
       ↓
[학생 알림] → 일정 확정
```

| `cancelled` | 취소됨 |
| `completed` | 완료됨 |
| `noShow` | 노쇼 |

## 시간 선택 UI

### 기본 원칙

| 항목 | 설명 |
|------|------|
| 시간 간격 | **30분 단위** (09:00, 09:30, 10:00...) |
| 레이아웃 | **4열 그리드** |
| 시간 표시 | **24시간제** (09:00, 14:00, 16:30) |
| 비활성 슬롯 | **회색으로 표시** (숨기지 않음) |

### 슬롯 상태

| 상태 | 설명 | UI |
|------|------|-----|
| `available` | 선택 가능 | 흰 배경, 테두리 |
| `unavailable` | 선택 불가 | 회색 배경 |
| `booked` | 예약됨 | 회색 배경 |
| `selected` | 선택됨 | Primary 색상 |

### 비활성화 조건

1. **가용시간 외**: 선생님의 가용 시작 시간 이전
2. **레슨 시간 초과**: 해당 슬롯 시작 + 레슨 시간 > 가용 종료 시간
3. **이미 예약**: 다른 학생이 이미 예약한 시간

| `TrialLessonRequestScreen` | ✅ |
| `RegisterRegularLessonScreen` | ✅ |
| 1회 레슨 예약 화면 | ⏳ 예정 |

## 기존 관계 온보딩

이미 오프라인에서 레슨 중인 선생님-학생이 앱에 처음 진입할 때 적용.

### 핵심 결정사항

| 항목 | 결정 |
|------|------|
| 연결 방식 | **양방향** - 선생님/학생 모두 연결 시작 가능 |
| 관계 증명 | **선생님 승인만** - 선생님이 확인하면 연결 완료 |
| 선생님 없을 때 | **초대 기능** - 학생이 선생님에게 앱 초대 링크 발송 |
| 레슨 정보 입력 | **선생님이 설정** - 학생은 연결만, 선생님이 일정 등록 |
| 승인 후 플로우 | **즉시 일정 등록** - 승인 후 바로 레슨 일정 등록 화면 |
| 과거 이력 | **선생님 선택** - 새로 시작 또는 과거 기록 수동 입력 |

### 연결 플로우

#### 플로우 1: 선생님이 기존 학생 초대

```
선생님: 학생 관리 → "기존 학생 초대" → 초대 코드/링크 공유
학생: 앱 가입 → 초대 코드 입력 → 연결 요청 자동 생성
선생님: 연결 요청 승인 → 레슨 일정 등록
```

#### 플로우 2: 학생이 기존 선생님 연결 요청

```
학생: 선생님 검색 → "이미 레슨 중이에요" 선택 → 연결 요청
선생님: 연결 요청 승인 → 레슨 일정 등록
```

#### 플로우 3: 선생님이 앱에 없음

```
학생: 선생님 검색 → 결과 없음 → "선생님 초대하기"
     → 선생님 정보 입력 → 초대 링크 공유
선생님: 초대 링크로 앱 가입 → 학생 연결 요청 알림 → 승인
```

## 정기 레슨 관리

### 정기레슨 특성

| 구분 | 단일 레슨 (체험/1회) | 정기 레슨 |
|------|---------------------|----------|
| 일정 | 1회성 날짜/시간 | 반복 패턴 (매주 X요일 Y시) |
| 관리 | 개별 예약 | 시리즈 + 개별 회차 |
| 변경 | 건별 변경 | 패턴 변경 or 특정 회차 변경 |

### 정기레슨 상태

| RegularLessonStatus | 설명 |
|---------------------|------|
| `active` | 진행 중 |
| `paused` | 일시 중단 |
| `terminated` | 종료 |

### 개별 회차 상태

| LessonInstanceStatus | 설명 |
|----------------------|------|
| `scheduled` | 예정됨 |
| `modified` | 예외 시간으로 변경됨 |
| `completed` | 완료 |
| `cancelled` | 취소됨 |
| `noShow` | 노쇼 |

### 특정 회차 변경 방법

**방법 1: 예외 회차 등록**
- 해당 회차만 새 시간으로 변경
- 다음 주부터는 기존 시간으로 복귀

**방법 2: 취소 + 1회 레슨 추가**
- 해당 회차 취소
- 1회 레슨으로 새로 예약

## 첫 달 일할 계산

### 핵심 규칙

| 항목 | 설명 |
|------|------|
| 주차 계산 기준 | ISO 주차 (월요일 시작) |
| 5주차 처리 | 기본 휴강으로 계산에 포함 |
| 적용 범위 | 첫 달만 일할 계산 |
| 계산 공식 | `월 수강료 × (남은 주차 / 4)` |
| 반올림 | 1,000원 단위로 반올림 |

### 일할 계산 예시

**시나리오: 월 수강료 200,000원**

| 시작 시점 | 남은 주차 | 첫 달 수강료 |
|----------|:--------:|------------:|
| 1주차 시작 | 4주 | 200,000원 |
| 2주차 시작 | 3주 | 150,000원 |
| 3주차 시작 | 2주 | 100,000원 |
| 4주차 시작 | 1주 | 50,000원 |

### 구현 위치

- **유틸리티**: `lib/core/utils/date_utils.dart`
  - `LessonDateUtils.getWeekOfMonth()`: 주차 계산
  - `LessonDateUtils.calculateProratedFee()`: 일할 계산

- **화면**: `lib/features/schedule/presentation/screens/register_regular_lesson_screen.dart`

## 선생님 레슨 설정

### 레슨 유형별 로직

| 유형 | 가용시간 | 설정 방식 |
|------|----------|----------|
| 정기 레슨 | 요일/시간대별 설정 | 가용시간 편집 |
| 체험 레슨 | 정기 가용시간 공유 | ON/OFF 토글 |
| 1회 레슨 | 정기 가용시간 공유 | ON/OFF 토글 |

### 단일 레슨 예약 프로세스 (체험/1회 통합)

**핵심 원칙**: 체험레슨과 1회레슨은 동일한 프로세스, 타입만 다름

| 항목 | 체험레슨 | 1회레슨 |
|------|----------|---------|
| 대상 | 새로운 선생님 | 기존/연결된 선생님 |
| 예약 프로세스 | **동일** | **동일** |
| 변경 프로세스 | **동일** | **동일** |
| 취소 프로세스 | **동일** | **동일** |
| 레슨 후 | 정규레슨 전환 제안 | 완료 |
| 결제 | 체험가 or 무료 | 1회 레슨비 |

## 향후 확장 가능성

1. **패키지 레슨**: N회 묶음 레슨 (예: 10회 패키지)
2. **그룹 레슨**: 여러 학생이 함께 신청
3. **대기열 시스템**: 원하는 시간이 없을 때 대기 신청
4. **자동 매칭**: 조건에 맞는 선생님 자동 추천

## 수강권 상태별 예약 플로우

> 2026-01-27 추가

### 예약 전 수강권 확인

```
[학생이 레슨 예약 요청]
         │
         ▼
   ┌─────────────┐
   │ 수강권 상태? │
   └──────┬──────┘
          │
    ┌─────┴─────┬─────────────┐
    │           │             │
    ▼           ▼             ▼
 [없음]      [만료됨]       [유효함]
    │           │             │
    ▼           ▼             ▼
┌──────────────────┐    ┌──────────────┐
│ 수강권 제안 플로우 │    │ 바로 예약 가능 │
│ (결제 → 발급)     │    │ (시간 선택)   │
└──────────────────┘    └──────────────┘
```

### 수강권 제안 플로우 (수강권 없음/만료 시)

| 단계 | 주체 | 액션 | 설명 |
|:----:|------|------|------|
| 1 | 선생님 | 템플릿 선택 → 제안 | 미리 설정한 템플릿 사용 |
| 2 | 학생 | 제안 확인 → 입금 | 외부 뱅킹 앱으로 입금 |
| 3 | 학생 | [입금 완료했어요] 클릭 | 선생님에게 알림 |
| 4 | 선생님 | 입금 확인 → [확인 완료] | 수강권 자동 발급 |
| 5 | 학생 | 레슨 예약 | LessonBookingScreen |

→ 상세: [subscription_master.md](../subscription/subscription_master.md)

### 단일 예약 화면 원칙

모든 레슨 예약은 **LessonBookingScreen** 하나로 통일됩니다.

| 시나리오 | 진입점 | 결과 |
|----------|--------|------|
| 수강권 보유 학생 | 직접 예약 화면 접근 | 시간 선택 → 즉시 확정 |
| 수강권 제안 수락 후 | 푸시 알림 → 예약 화면 | 시간 선택 → 즉시 확정 |
| 체험레슨 | 선생님 검색 → 예약 | 시간 선택 → 즉시 확정 |
