# 레슨 스케줄 플로우 (앱 미사용)

> 마지막 업데이트: 2026-01-27

실제 강사-학생 간 레슨 스케줄을 잡는 현실적인 플로우입니다.
앱 없이 카카오톡, 전화, 문자 등을 사용하는 일반적인 상황을 다룹니다.

## 1. 선생님 발굴 및 첫 연락 플로우

### 1.1 개인 레슨 - 시퀀스 다이어그램

```mermaid
sequenceDiagram
    autonumber
    participant S as 🎓 학생/학부모
    participant P as 📱 외부 플랫폼<br/>(숨고/크몽/블로그)
    participant K as 💬 카카오톡
    participant T as 🎻 선생님

    Note over S,T: 🔍 Phase 1: 선생님 탐색 (평균 3-7일)

    S->>P: 검색 "강남 바이올린 레슨"
    P-->>S: 숨고, 크몽, 블로그, 인스타 결과

    S->>S: 여러 선생님 프로필 비교
    Note over S: 플랫폼마다 정보 형식 다름<br/>가격 비교 어려움

    S->>S: 가격, 위치, 경력 확인

    Note over S,T: ⚠️ Pain Point #1: 정보 파편화<br/>각 플랫폼마다 다른 정보, 비교 어려움

    S->>P: 선생님 A 연락처 확인
    P-->>S: 카카오톡 ID 또는 전화번호

    Note over S,T: 📞 Phase 2: 첫 연락 (1-3일)

    S->>K: "안녕하세요, 바이올린 레슨 문의드립니다"

    Note over K: ⏳ 대기 시간: 수 시간 ~ 1일<br/>선생님 응답까지

    K->>T: 메시지 알림
    T->>K: "네, 어떤 분이 레슨 받으실 건가요?"
    K->>S: 메시지

    S->>K: "초등학생 아이, 처음 배워요"
    K->>T: 메시지

    T->>K: "체험레슨 가능합니다. 언제가 편하세요?"
    K->>S: 메시지

    Note over S,T: ⚠️ Pain Point #2: 비동기 커뮤니케이션<br/>메시지 주고받기에 시간 소요
```

### 1.2 학원 레슨 - 시퀀스 다이어그램

```mermaid
sequenceDiagram
    autonumber
    participant S as 🎓 학생/학부모
    participant W as 🌐 학원 웹사이트<br/>/네이버 플레이스
    participant Ph as 📞 전화
    participant A as 🏫 학원 (데스크)
    participant T as 🎻 담당 선생님

    Note over S,T: 🔍 Phase 1: 학원 탐색

    S->>W: 검색 "강남역 음악학원"
    W-->>S: 네이버 플레이스, 학원 홈페이지

    S->>S: 학원 리뷰, 위치, 커리큘럼 확인

    Note over S,A: 📞 Phase 2: 학원 문의

    S->>Ph: 학원 전화
    Ph->>A: 전화 연결

    A->>Ph: "OO음악학원입니다"
    Ph->>S: 응답

    S->>Ph: "바이올린 레슨 문의드려요"
    Ph->>A: 문의

    A->>Ph: "체험레슨 예약해드릴까요?<br/>화/목 오후 가능합니다"
    Ph->>S: 안내

    S->>Ph: "목요일 4시 가능한가요?"
    Ph->>A: 예약 요청

    Note over A,T: 내부 스케줄 확인

    A->>Ph: "목요일 4시 예약 완료되었습니다.<br/>김선생님이 담당하십니다"
    Ph->>S: 확정

    Note over S,T: ⚠️ Pain Point: 선생님 선택 불가<br/>학원에서 배정, 사전 정보 없음

    Note over S,T: 🎻 Phase 3: 체험 당일

    S->>A: 학원 방문
    A->>T: "체험 레슨 학생 오셨어요"
    T->>S: 첫 만남 (사전 정보 없이)

    Note over T,S: ⚠️ Pain Point: 정보 단절<br/>데스크 ↔ 선생님 간 정보 공유 부족
```

### 1.3 Pain Points 요약

| 구분 | 개인 레슨 | 학원 레슨 |
|------|----------|----------|
| 탐색 | 플랫폼마다 정보 분산 | 학원 정보만 있음 (선생님 정보 부족) |
| 연락 | 응답 대기 시간 길음 | 전화 연결 필요 |
| 선택 | 선생님 직접 선택 | 학원에서 배정 (선택 불가) |
| 정보 | 메시지로 산발적 교환 | 데스크 ↔ 선생님 정보 단절 |

## 2. 체험 레슨 예약 플로우

### 2.1 시퀀스 다이어그램

```mermaid
sequenceDiagram
    autonumber
    participant S as 🎓 학생/학부모
    participant K as 💬 카카오톡
    participant T as 🎻 선생님
    participant C as 📅 캘린더<br/>(개인)

    Note over S,C: 📅 Phase 1: 일정 조율 (2-5일)

    S->>K: "토요일 오후 어때요?"
    K->>T: 메시지

    T->>C: 토요일 스케줄 확인
    C-->>T: 14:00 다른 레슨 있음

    T->>K: "토요일 오후 2시는 다른 레슨이 있어서요.<br/>3시 반 이후 가능합니다"
    K->>S: 메시지

    S->>S: 가족 일정 확인
    S->>K: "3시 반은 학원이 있어서요. 일요일은요?"
    K->>T: 메시지

    T->>C: 일요일 스케줄 확인
    C-->>T: 비어있음

    T->>K: "일요일 오후 2시 어떠세요?"
    K->>S: 메시지

    S->>K: "네, 좋아요!"
    K->>T: 메시지

    Note over S,T: ⚠️ Pain Point #3: 단일 제안 → 핑퐁 메시지<br/>한 번에 하나씩 제안 → 거절 → 다시 제안<br/>시간 맞추기까지 5-10회 메시지 왕복

    Note over S,C: 📍 Phase 2: 상세 정보 교환 (당일)

    T->>K: "장소는 강남역 3번 출구 OO빌딩 5층입니다.<br/>체험비는 5만원이고, 레슨 시간은 40분입니다"
    K->>S: 메시지

    S->>K: "알겠습니다. 주차 가능한가요?"
    K->>T: 메시지

    T->>K: "주차는 1시간 무료입니다"
    K->>S: 메시지

    S->>K: "아이 이름은 김민수, 연락처는 010-xxxx입니다"
    K->>T: 메시지

    Note over S,T: ⚠️ Pain Point #4: 정보 누락<br/>필요 정보를 여러 번에 걸쳐 주고받음

    Note over S,C: ✅ Phase 3: 최종 확인 (레슨 전날)

    T->>C: 일정 등록 (수동)

    T->>K: "내일 2시 체험레슨 잊지 마세요~"
    K->>S: 리마인더

    S->>K: "네, 내일 뵙겠습니다!"
    K->>T: 확인

    Note over S,T: ⚠️ Pain Point #5: 수동 리마인더<br/>선생님이 직접 알림 보내야 함
```

### 2.2 Pain Points 요약

| 단계 | 문제점 | 영향 |
|------|--------|------|
| 탐색 | 정보 파편화 | 3-7일 소요, 비교 어려움 |
| 첫 연락 | 응답 대기 | 수 시간 ~ 1일 |
| **일정 조율** | **단일 제안 핑퐁** | **5-10회 왕복, 2-5일** |
| 정보 교환 | 누락/반복 | 필수 정보 여러 번 요청 |
| 리마인더 | 수동 알림 | 선생님 부담, 노쇼 위험 |

> 💡 **다중 옵션 없이 단일 제안 반복**: "토요일 2시요?" → "안돼요" → "그럼 3시요?" → "그것도..." → 반복
>
> 🎯 **앱 해결책**: 선생님이 가용 시간 오픈 → 학생이 원하는 시간 선택 → 즉시 예약 (조율 0회)

**총 소요 시간: 평균 7-14일** → 앱 사용 시: **즉시 (탭 1회)**

## 3. 정기 레슨 등록 플로우

### 3.1 시퀀스 다이어그램

```mermaid
sequenceDiagram
    autonumber
    participant S as 🎓 학생/학부모
    participant K as 💬 카카오톡
    participant T as 🎻 선생님
    participant C as 📅 캘린더<br/>(개인)
    participant B as 🏦 은행앱
    participant N as 📓 레슨노트<br/>(수기/엑셀)

    Note over S,N: ✅ Phase 1: 체험 레슨 완료 후 결정 (당일)

    T->>S: "오늘 레슨 어떠셨어요?"
    S->>T: "아이가 재밌어했어요. 등록하고 싶어요"

    Note over S,N: 💰 Phase 2: 수강료/시간 협의 (당일-1일)

    T->>K: "정기 레슨은 주 1회 40분, 월 20만원입니다"
    K->>S: 메시지

    S->>K: "네, 알겠습니다. 매주 토요일 가능한가요?"
    K->>T: 메시지

    T->>C: 토요일 빈 시간 확인
    C-->>T: 11시, 15시, 17시 가능

    T->>K: "토요일은 11시, 3시, 5시 가능해요"
    K->>S: 메시지

    S->>S: 가족 일정 조율
    S->>K: "11시는 학원이 있어서요. 3시나 5시 중에..."
    K->>T: 메시지

    T->>K: "3시는 다음 학생이랑 좀 빡빡한데, 5시는요?"
    K->>S: 메시지

    S->>K: "5시는 너무 늦어서... 혹시 일요일은요?"
    K->>T: 메시지

    T->>C: 일요일 스케줄 확인
    T->>K: "일요일은 2시, 4시 가능해요"
    K->>S: 메시지

    S->>K: "일요일 2시로 할게요"
    K->>T: 확정

    Note over S,T: ⚠️ Pain Point #6: 일정 조율 핑퐁<br/>선생님이 옵션 제시 → 학생 확인 → 재조율 반복<br/>평균 5-8회 메시지 왕복, 2-3일 소요

    Note over S,T: ⚠️ Pain Point #6-1: 구두 약속<br/>문서화된 계약 없음

    Note over S,N: 💳 Phase 3: 결제 및 수강권 처리 (1-3일)

    T->>K: "수강료는 매월 첫 주에 입금해주세요<br/>국민 xxx-xxxx-xxxx 홍길동"
    K->>S: 계좌 정보

    Note over S: ⏳ 결제 타이밍 기억해야 함

    S->>B: 이체 (20만원)

    Note over T: ⏳ 입금 확인 (수동)

    T->>B: 은행 앱에서 입금 확인
    B-->>T: 입금 내역 확인

    T->>K: "입금 확인했습니다. 감사합니다!"
    K->>S: 확인

    T->>N: 입금 내역 기록 (수동)
    T->>N: "김민수 1월 수강권 4회" (수동 메모)

    Note over S,T: ⚠️ Pain Point #7: 수동 입금 확인 + 수강권 관리<br/>입금 확인 → 수강권 끊기 모두 선생님 머릿속/메모

    Note over S,N: 🎫 Phase 3-1: 수강권 관리 (수동)

    Note over T,N: 수강권 기록 방식
    Note over N: - 종이 메모: "김민수 4회"<br/>- 엑셀: "김민수, 4회, 1/5 시작"<br/>- 기억: "김민수는 월 4회였지..."

    Note over S,T: ⚠️ Pain Point #7-1: 수강권 투명성 부족<br/>학생은 잔여 횟수를 선생님에게 물어봐야 함

    Note over S,N: 📅 Phase 4: 스케줄 관리 (매월)

    T->>C: 1개월 레슨 일정 등록 (수동)

    loop 매주 토요일
        T->>K: "내일 3시 레슨 있습니다"
        K->>S: 리마인더

        Note over T,S: 레슨 진행

        T->>N: 레슨 노트 작성 (수기/사진)
    end

    Note over S,T: ⚠️ Pain Point #8: 반복 작업<br/>매주 수동 리마인더, 기록

    Note over S,N: 🔄 Phase 5: 변경 시 (수시)

    S->>K: "다음 주 토요일 가족 여행이라 못 가요"
    K->>T: 변경 요청

    T->>C: 해당 날짜 취소
    T->>K: "알겠습니다. 보강은 언제 하실래요?"
    K->>S: 메시지

    S->>K: "그 다음주 일요일 가능할까요?"
    K->>T: 메시지

    T->>C: 일요일 스케줄 확인
    T->>K: "일요일 2시 어떠세요?"
    K->>S: 메시지

    S->>K: "네, 좋아요"
    K->>T: 확정

    T->>C: 보강 일정 추가 (수동)
    T->>N: 변경 사항 메모

    Note over S,T: ⚠️ Pain Point #9: 변경 추적 어려움<br/>보강, 취소 이력 관리 어려움

    Note over S,N: 📊 Phase 6: 월말 정산 (매월)

    T->>N: 이번 달 레슨 횟수 계산
    T->>N: 보강/취소 반영
    T->>K: "다음 달 수강료 입금 부탁드려요"
    K->>S: 결제 요청

    Note over T: ⏳ 입금 대기 (1-7일)

    alt 입금 안 됨
        T->>K: "혹시 입금하셨나요?"
        K->>S: 독촉 (불편)
        S->>B: 뒤늦게 이체
    end

    Note over S,T: ⚠️ Pain Point #10: 어색한 독촉<br/>결제 요청이 관계에 부담
```

### 3.2 Pain Points 요약

| 단계 | 문제점 | 영향 |
|------|--------|------|
| **일정 조율** | **단일 제안 핑퐁** | **5-8회 메시지 왕복, 2-3일 소요** |
| 계약 | 구두 약속만 | 분쟁 시 증거 없음 |
| 결제 | 수동 입금 확인 | 선생님 매번 은행 앱 확인 필요 |
| **수강권 발급** | **수동 메모/기억** | **학생에게 공식 내역 없음** |
| **잔여 횟수** | **선생님만 알고 있음** | **학생은 물어봐야 함** |
| 스케줄 | 수동 등록 | 매월 반복 작업 |
| 리마인더 | 수동 알림 | 선생님 부담 |
| 변경 | 추적 어려움 | 보강/취소 내역 혼란 |
| 정산 | 어색한 독촉 | 관계 부담 |

> 💡 **다중 옵션 부재**: 선생님이 "토요일 11시, 3시, 5시 가능해요" → 학생 "3시는 안되고..." → 재조율 반복
>
> 🎯 **앱 해결책**: 선생님이 시간대 미리 오픈 → 학생이 칩 버튼으로 선택 → 메시지 0회

**선생님 월간 관리 시간: 평균 4-6시간** → 앱 사용 시: **30분 미만**

## 4. 회차권 레슨 플로우

### 4.1 시퀀스 다이어그램

```mermaid
sequenceDiagram
    autonumber
    participant S as 🎓 학생/학부모
    participant K as 💬 카카오톡
    participant T as 🎻 선생님
    participant C as 📅 캘린더<br/>(개인)
    participant N as 📓 메모<br/>(잔여 횟수)

    Note over S,N: 🎫 Phase 1: 회차권 구매 및 수강권 발급 (1-3일)

    S->>K: "10회권 끊고 싶어요"
    K->>T: 구매 요청

    T->>K: "10회권은 90만원입니다 (1회 9만원)<br/>국민 xxx-xxxx-xxxx 홍길동"
    K->>S: 금액 + 계좌 안내

    S->>K: "네, 입금할게요"
    K->>T: 입금 예정

    Note over S,T: 💳 결제 처리 (외부)

    S->>B: 계좌이체 (90만원)

    Note over T: ⏳ 입금 확인 (수동)

    T->>B: 은행 앱 확인
    B-->>T: 90만원 입금 확인

    T->>K: "입금 확인했습니다!"
    K->>S: 확인
```

## 7. 결론

### 핵심 문제 요약

1. **커뮤니케이션 비효율**: 단일 제안 → 거절 → 재제안 반복 (다중 옵션 부재)
2. **수동 관리 부담**: 스케줄, 결제, 기록 모두 선생님이 직접 관리
3. **정보 비대칭**: 잔여 횟수, 결제 내역 등 학생은 확인 어려움
4. **관계 부담**: 결제 독촉, 노쇼 대응 등 어색한 상황 발생
5. **기록 부재**: 레슨 이력, 진도 등 체계적 관리 불가

### 앱으로 해결 가능한 영역

| 문제 | 해결 방안 | 기대 효과 |
|------|----------|----------|
| **일정 조율 핑퐁** | **선생님 시간 오픈 → 학생 선택** | **조율 0회 (100%↓)** |
| 결제 관리 | 자동 알림 + 입금 확인 체크 | 독촉 부담 제거 |
| **수강권 발급** | **입금 확인 → 앱에서 발급** | **공식 발급 내역 제공** |
| **잔여 횟수** | **자동 차감 + 실시간 표시** | **학생도 직접 확인 가능** |
| 스케줄 관리 | 정기 레슨 자동 생성 | 월 30분 → 0분 |
| 리마인더 | 자동 푸시 알림 | 수동 알림 불필요 |
| 레슨 기록 | 인앱 노트 + 녹음 | 체계적 이력 관리 |

> **시간 오픈 → 선택 방식**: 선생님이 미리 가용 시간대를 오픈 → 학생이 칩 버튼으로 원하는 시간 선택 → 즉시 예약 확정
>
> 기존 "다중 옵션 제안"보다 발전된 방식으로, **조율 자체가 필요 없음**

### 핵심 해결책: 시간 오픈 → 학생 선택 예약 시스템

앱 미사용 시 가장 큰 문제인 **일정 조율 핑퐁**을 근본적으로 해결:

```
┌─────────────────────────────────────────────────────────────────┐
│  [앱 미사용]                      [앱 사용]                      │
│                                                                 │
│  선생님: "토요일 어때요?"         선생님: 가용 시간 미리 오픈      │
│  학생: "안돼요"                   ┌─────────────────────────────┐│
│  선생님: "그럼 일요일은요?"       │  ◀  2/18(화)  ▶             ││
│  학생: "일요일도..."             │  예약 가능한 시간             ││
│  ... (5-10회 반복)               │  [15:00] [⭐16:00] [17:00]  ││
│                                  │                              ││
│  ⏱️ 평균 2-5일 소요              │  → 탭 한 번으로 예약 완료!    ││
│                                  └─────────────────────────────┘│
│                                  ⏱️ 즉시 완료 (0회 조율)         │
└─────────────────────────────────────────────────────────────────┘
```

#### 선생님 관점
- **사전 작업**: 가용 시간대를 블록 그리드로 한 번 설정
- **이후 작업**: 없음 (학생이 알아서 선택)
- **효과**: 메시지 주고받기 0회, 시간 절약

#### 학생 관점
- **보이는 것**: 선생님이 오픈한 시간대만 칩 버튼으로 표시
