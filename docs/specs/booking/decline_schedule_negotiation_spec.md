# 통합 거절/일정조율 바텀시트 스펙

> 작성일: 2026-03-28
> 상태: 구현 예정

## 1. 배경

거절/보류 UI가 4곳에 혼재되어 있어 UX 일관성이 떨어짐.
실제 사용의 95%가 일정 조율이므로 "거절" 대신 일정 조율 중심으로 프레이밍.

## 2. 통합 플로우

### 2.1 1단계: 바텀시트 (DeclineBottomSheet)

```
┌─────────────────────────────────┐
│ 이 시간에 레슨이 어렵습니다        │
│                                  │
│ ┌──────────────────────────┐    │
│ │ 현재 가능한 시간이 없어       │    │  ← 디폴트 메시지, 수정 가능
│ │ 이번에는 어렵습니다.          │    │
│ └──────────────────────────┘    │
│                                  │
│ [메시지만 전달]   [다른 시간 제안]   │
└─────────────────────────────────┘
```

- 진입: 모든 거절/보류 버튼
- 반환: `({String message, List<TimeSlot> suggestedSlots})?`
- "메시지만 전달" → `(message, [])` 반환
- "다른 시간 제안" → 2단계 화면 push

### 2.2 2단계: 대안 시간 제안 화면 (SuggestAlternativeScreen)

```
┌─────────────────────────────────┐
│ ← 대안 시간 제안                  │
│                                  │
│ 메시지: "현재 가능한 시간이..."     │  ← 1단계에서 전달된 메시지
│                                  │
│ [주간 스케줄 그리드]               │  ← 기존 수업 표시 + 빈 칸 탭
│                                  │
│ 제안 시간 (1/3)                   │
│ ┌──────────────────────────┐    │
│ │ 금 14:00-14:45  ✎ ✕     │    │
│ └──────────────────────────┘    │
│                                  │
│        [제안하기]                  │
└─────────────────────────────────┘
```

- 주간 스케줄 그리드: `weekLessonsProvider` 기반, 빈 시간대 탭 가능
- 레슨 길이: 학생 예약 시 확정된 `durationMinutes` 자동 적용
- 최대 3개 시간 제안
- 각 제안 시간은 수정(DatePicker + TimePicker) / 삭제 가능
- 중복 체크: 기존 수업과 겹치면 경고 (향후 이중 제안은 서버에서 체크)
- 반환: `List<TimeSlot>`

## 3. 사용처 (4곳 통합)

| 화면 | API 호출 |
|------|---------|
| lesson_request_card (레슨 요청) | `declineRequest(id, reason, suggestedSlots?)` |
| lesson_requests_screen (통합 신청 거절) | `rejectRequest()` + `proposeAlternatives()` |
| lesson_requests_screen (역제안) | `proposeAlternatives()` |
| approval_bottom_sheet (체험레슨) | `markUnavailable(id, reason, suggestedSlots?)` |

## 4. 라벨 (모든 상황 동일)

| 요소 | 텍스트 |
|------|-------|
| 바텀시트 제목 | 이 시간에 레슨이 어렵습니다 |
| 디폴트 메시지 | 현재 가능한 시간이 없어 이번에는 어렵습니다. |
| 좌 CTA | 메시지만 전달 |
| 우 CTA | 다른 시간 제안 |
| 2단계 제목 | 대안 시간 제안 |
| 2단계 CTA | 제안하기 |

## 5. 삭제 대상

- `UnavailableReason` enum → 자유 텍스트로 대체
- `unavailable_bottom_sheet.dart` → 통합 바텀시트로 대체
- `counter_propose_bottom_sheet.dart` → 통합 바텀시트로 대체

## 6. 설계 결정

| 결정 | 값 |
|------|-----|
| API 연동 | 콜백 방식 (바텀시트는 결과만 반환) |
| 시간 선택 | 선생님 가용 시간 (주간 스케줄 그리드) |
| 사유 입력 | 자유 텍스트 + 디폴트 메시지 |
| 최대 제안 수 | 3개 |
| 중복 체크 | 클라이언트: 기존 수업. 서버: 이중 제안 (향후) |
| 조율 라운드 | 최대 2라운드 |
