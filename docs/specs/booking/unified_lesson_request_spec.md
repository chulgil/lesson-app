# 통합 레슨 신청 플로우 스펙

> **문서 버전**: 1.0
> **최종 수정**: 2026-03-26
> **상태**: 설계 완료, Phase 1 구현 예정
> **역할**: 학생-선생님 최초 연결부터 레슨 시작까지의 전체 플로우

---

## 1. 배경 및 문제 정의

### 1.1 현재 문제

- 학생이 "정규레슨" 클릭 시 수강권 없으면 막다른 길 (NoSubscriptionView)
- 학생이 할 수 있는 행동이 없음 (선생님에게 연락 방법 없음)
- 체험레슨과 정규레슨의 플로우가 완전히 분리되어 있어 중복 코드 발생
- 체험레슨이 즉시 예약 방식이라 선생님이 거절할 수 없음

### 1.2 설계 원칙

- **학생에게 항상 다음 행동을 제공** (막다른 길 금지)
- **체험/정규 플로우 통합** (하나의 신청 폼, 하나의 협상 프로세스)
- **선생님 주도 가격 결정** (학생마다 가격이 다를 수 있음)
- **시간 협상은 시각적으로** (주간 스케줄 UI에서 빈 슬롯 클릭)

---

## 2. 용어 정의

| 용어 | 설명 |
|------|------|
| 레슨 신청 | 학생이 선생님에게 레슨을 요청하는 행위 (체험/정규 모두 포함) |
| 시간 협상 | 학생-선생님 간 레슨 시간을 합의하는 과정 (최대 3라운드) |
| 라운드 | 학생 제안 → 선생님 응답의 1사이클 |
| 대안 제안 | 선생님이 학생 희망 시간 대신 제시하는 최대 3개 시간 슬롯 |
| 역제안 | 학생이 선생님 대안을 거부하고 다른 시간을 제안하는 행위 |
| 가격표 | 선생님이 악기별 x 레벨별로 설정한 레슨 가격 매트릭스 |

## 3. 대상 사용자

| 사용자 | 시나리오 |
|--------|----------|
| 새 학생 | 선생님 검색 → 프로필 확인 → 체험/정규 레슨 신청 |
| 복귀 학생 | 이전 선생님에게 다시 레슨 요청 (이전 정보 프리필) |
| 오프라인 전환 학생 | 이미 오프라인 레슨 중인데 앱으로 전환 (정규 바로 신청) |
| 선생님 | 요청 검토 → 승인/대안 제안/거절 → 수강권 제안 |

## 4. 전체 플로우

### 4.1 진입점

```
TeacherDetailScreen:
  ├── 새 선생님:     [레슨 신청] 버튼 1개
  └── 이전 선생님:   [다시 시작하기] 버튼 1개
                     + 배너: "이전 레슨: 2024.03 ~ 2024.12"
```

### 4.2 통합 신청 폼 (UnifiedLessonRequestScreen)

```
┌─────────────────────────────────┐
│ AppBar: "레슨 신청"              │
├─────────────────────────────────┤
│ [선생님 정보 헤더]               │
│ 이름 · 악기 · 경력              │
├─────────────────────────────────┤
│ [레슨 유형 선택]                │
│ ○ 체험레슨  ○ 정규레슨          │
├─────────────────────────────────┤
│ [악기 선택]                     │
│ 선생님 악기 목록에서 Chip 선택   │
├─────────────────────────────────┤
│ [레슨 목적]                     │
│ Dropdown: 취미/입시/연주/기타    │
├─────────────────────────────────┤
│ [경험 수준]                     │
│ ○ 초급  ○ 중급  ○ 고급          │
├─────────────────────────────────┤
│ [희망 레슨 시간]                │
│ 선생님 주간 스케줄 (빈 슬롯 선택)│
│ (다른 학생 정보 숨김, 빈/찬 표시)│
├─────────────────────────────────┤
│ [메모]                          │
│ 자유 텍스트 (선택, 최대 200자)   │
├─────────────────────────────────┤
│ [참고 가격] (가격표 매칭 시)     │
│ "바이올린 초급 기준: 40,000원"   │
├─────────────────────────────────┤
│ [레슨 신청하기] 버튼             │
└─────────────────────────────────┘
```

#### 이전 선생님 "다시 시작하기" 프리필

- 악기: 이전 레슨 악기 자동 선택
- 희망 요일/시간: 이전 스케줄 자동 채움
- 레슨 유형: 정규 기본 선택 (변경 가능)
- 학생이 변경하거나 그대로 전송

### 4.3 시간 협상 프로세스 (최대 3라운드, 6턴)

```
Round 1:
  학생 → 희망 시간 1개 + 메모 전송
  선생님 →
    ├── [승인] → 시간 확정
    ├── [대안 제안] → 최대 3개 시간 슬롯 + 메모
    └── [거절] → 기본 메시지 ("스케줄이 꽉 차서 다음에 신청해주세요")

Round 2:
  학생 →
    ├── 대안 3개 중 1개 선택 → 시간 확정
    ├── [다른 시간 역제안] → 선생님 스케줄에서 빈 슬롯 클릭 + 메모
    └── [취소]
  선생님 →
    ├── [승인]
    ├── [대안 제안] 최대 3개 + 메모
    └── [거절]

Round 3 (마지막):
  학생 →
    ├── 대안 중 선택 → 확정
    ├── [역제안] → 선생님 스케줄에서 선택 + 메모
    └── [취소]
  선생님 →
    ├── [승인] → 확정
    └── [거절] (더 이상 대안 불가)

3라운드 후 미합의 → "시간 협의가 어렵습니다. 직접 연락해주세요."
```

#### 선생님 대안 제안 UI

- 선생님 화면의 주간 스케줄과 동일한 UI
- 다른 학생 정보는 숨기고 빈/찬 여부만 표시
- 빈 슬롯 클릭 → 대안 시간으로 추가 (최대 3개)
- 메모란 포함 (선택)

#### 학생 역제안 UI

- 선생님 주간 스케줄 (빈 슬롯만 표시)
- 빈 슬롯 클릭 → 역제안 시간 선택
- 메모란 포함 (선택)

### 4.4 시간 확정 후 분기

```
시간 확정
  ├── 체험레슨 (무료): 레슨 예약 완료 → 대시보드 표시
  ├── 체험레슨 (유료): 수강권 제안 프로세스로 진행
  └── 정규레슨: 수강권 제안 프로세스로 진행
```

### 4.5 수강권 제안 → 결제 → 발급

```
1. 선생님: 수강권 제안 발송
   - 가격: 악기×레벨 가격표 기본값 (선생님 수정 가능)
   - 횟수, 기간 설정

2. 학생: 수강권 제안 수락

3. 학생: "결제 완료" 알림 전송

4. 선생님: 입금 확인 → 수강권 발급 확정

5. 레슨 시작
```

## 5. 가격 체계

### 5.1 선생님 가격표 (악기 x 레벨)

```
선생님 설정 > 레슨 운영:

┌─────────┬────────┬────────┬────────┐
│         │ 초급   │ 중급   │ 고급   │
├─────────┼────────┼────────┼────────┤
│ 바이올린 │ 40,000 │ 50,000 │ 70,000 │
│ 비올라   │ 45,000 │ 55,000 │ 75,000 │
└─────────┴────────┴────────┴────────┘
```

### 5.2 가격 매칭 로직

- 학생 신청 시 악기 + 경험수준 선택
- 선생님 가격표에서 해당 조합의 가격 조회
- 수강권 제안 화면에서 기본값으로 표시
- 선생님이 클릭하면 해당 금액이 입력됨 (수정 가능)

### 5.3 체험레슨 무료 설정

- 선생님 설정 > 레슨 운영에 "체험레슨 무료 여부" 토글
- 무료: 시간 확정 → 바로 예약 완료
- 유료: 시간 확정 → 수강권 제안 프로세스

## 8. 데이터 모델

### 8.1 LessonRequest (통합)

```dart
class UnifiedLessonRequest {
  final String id;
  final String studentId;
  final String teacherId;

  // 레슨 정보
  final LessonRequestType type;      // trial, regular
  final String instrument;            // 선택한 악기
  final LessonGoal goal;             // hobby, exam, performance, other
  final ExperienceLevel experience;   // beginner, intermediate, advanced
  final String? message;              // 메모 (최대 200자)

  // 시간 협상
  final String? preferredDay;         // 희망 요일
  final String? preferredTime;        // 희망 시간
  final int? preferredDuration;       // 희망 레슨 시간 (분)
  final List<TimeProposal> proposals; // 협상 히스토리
  final int currentRound;            // 현재 라운드 (1-3)

  // 이전 선생님 정보 (복귀 학생)
  final bool isReturningStudent;
  final String? previousLessonDay;
  final String? previousLessonTime;
  final int? previousLessonDuration;

  // 상태
  final LessonRequestStatus status;
  final DateTime createdAt;
  final DateTime? confirmedAt;
  final DateTime? cancelledAt;
  final String? rejectionReason;

  // 가격 참고
  final int? suggestedPrice;         // 가격표 매칭 금액
}
```

### 8.2 TimeProposal (협상 턴)

```dart
class TimeProposal {
  final String id;
  final String proposerId;           // 누가 제안했는지
  final ProposerRole role;           // student, teacher
  final List<TimeSlotOption> slots;  // 제안 시간 (학생 1개, 선생님 최대 3개)
  final String? message;             // 메모
  final ProposalAction action;       // propose, accept, reject, counterPropose
  final DateTime createdAt;
}
```

### 8.3 TimeSlotOption

```dart
class TimeSlotOption {
  final String id;
  final int dayOfWeek;               // 0-6
  final String startTime;            // "HH:mm"
  final String endTime;              // "HH:mm"
  final bool isSelected;             // 학생이 선택한 슬롯
}
```

### 8.4 LessonRequestStatus

```dart
enum LessonRequestStatus {
  pending,              // 선생님 확인 대기
  negotiating,          // 시간 협상 중
  timeConfirmed,        // 시간 확정
  proposalSent,         // 수강권 제안 발송됨
  proposalAccepted,     // 수강권 제안 수락됨
  paymentNotified,      // 학생 결제 완료 알림
  completed,            // 선생님 입금 확인 → 수강권 발급 완료
  rejected,             // 거절됨
  cancelled,            // 학생 취소
  expired,              // 3라운드 미합의 만료
}
```

## 11. 구현 Phase

| Phase | 내용 | 핵심 가치 |
|-------|------|----------|
| **1** | 통합 신청 폼 + 선생님 요청 수신 + 승인/거절 | 최소 동작 (막다른 길 해소) |
| **2** | 시간 협상 (대안 3개 + 역제안 3라운드) | 시간 합의 완성 |
| **3** | 수강권 제안 → 결제 → 발급 연동 | 수익 연결 |
| **4** | 가격표 설정 (악기×레벨) + 자동 매칭 | 가격 자동화 |
| **5** | 대시보드 진행 상태 카드 + 체험 무료 설정 | 가시성 |
