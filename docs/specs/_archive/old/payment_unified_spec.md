## 개요

### 설계 원칙

1. **선생님 자율성** - 결제 방식, 미결제 처리, 환불 정책 등 선생님이 설정
2. **유연한 결제 단위** - 월정액, 패키지(N회권) 선택 가능
3. **단계적 확장** - 무통장입금 → 간편결제 → 카드 순차 확장
4. **투명한 정산** - 월별 수익 리포트 제공
5. **학생 중심** - 학생/학부모가 입금 상태를 확인 가능

### 핵심 결정사항

| 항목 | 결정 |
|------|------|
| 결제 방식 | 선생님 선택 (선결제/후결제) |
| 결제 단위 | 월정액 + 패키지(N회권) |
| 결제 수단 | Phase 1: 무통장입금, Phase 2: 간편결제 |
| 입금 확인 | 2단계 (학생 입금완료 → 선생님 확인) |
| 정산 | 월별 리포트 |

## 결제 상태

### PaymentStatus

| 값 | 설명 | UI 표시 |
|----|------|---------|
| `pending` | 청구됨 (입금 대기) | 🟡 입금 대기 |
| `studentConfirmed` | 학생이 입금완료 표시 | 🔔 확인 대기 |
| `confirmed` | 선생님이 확인 완료 | 🟢 완료 |
| `overdue` | 납부기한 초과 | 🔴 연체 |
| `cancelled` | 취소 | ⚪ 취소됨 |
| `refunded` | 환불 | ⚪ 환불됨 |

### 상태 전환 다이어그램

```
[청구서 발행]
      │
      ▼
  pending (🟡 입금 대기)
      │
      ├──[학생: 입금완료 클릭]──► studentConfirmed (🔔 확인 대기)
      │                              │
      │                              ├──[선생님: 입금확인]──► confirmed (🟢 완료)
      │                              │
      │                              └──[선생님: 반려]──► pending (다시 대기)
      │
      ├──[납부기한 초과]──► overdue (🔴 연체)
      │                       │
      │                       └──[입금 후]──► studentConfirmed
      │
      ├──[취소]──► cancelled (⚪ 취소)
      │
      └──[환불]──► refunded (⚪ 환불)
```

| 입문 (beginner) | 160,000원 | 320,000원 |
| 초급 (elementary) | 180,000원 | 360,000원 |
| 중급 (intermediate) | 200,000원 | 400,000원 |
| 고급 (advanced) | 240,000원 | 480,000원 |

## 결제 단위

### PaymentUnit

| 값 | 설명 |
|----|------|
| `monthly` | 월정액 |
| `package` | 패키지 (N회권) |

### 월정액

- 계산: 레벨별 기본 수강료 × 주당 레슨 횟수
- 청구: 매월 1일 자동 발행
- 레슨 횟수: 주 1회 = 월 4회, 주 2회 = 월 8회

### 패키지 (N회권)

| 패키지 | 할인율 | 유효기간 | 예시 (중급 기준) |
|--------|:------:|:--------:|-----------------|
| 4회권 | 0% | 60일 | 200,000원 |
| 8회권 | 5% | 90일 | 380,000원 |
| 12회권 | 10% | 120일 | 540,000원 |

## 자녀 프로필 결제

### BillingTarget

| 값 | 설명 |
|----|------|
| `student` | 학생 본인 (만 14세 이상) |
| `parent` | 부모 계정 (만 14세 미만) |

### 청구 대상 결정 규칙

1. 자녀 프로필(ChildProfile) → 항상 `parent`
2. 학생(Student) + 학부모 연결 + 학부모 결제 활성화 → `parent`
3. 그 외 → `student`

## 2단계 입금확인

### 워크플로우

```
1단계: 학생/학부모가 "입금완료" 버튼 클릭
       → 상태: studentConfirmed (🔔 확인 대기)
       → 선생님에게 알림 발송

2단계: 선생님이 계좌 확인 후 "입금확인" 클릭
       → 상태: confirmed (🟢 완료)
       → 수강권 활성화
```

### 알림

| 시점 | 발신 | 수신 | 내용 |
|------|------|------|------|
| 학생 입금완료 | 시스템 | 선생님 | "김민수님이 입금완료를 표시했습니다" |
| 선생님 확인 | 시스템 | 학생 | "입금이 확인되었습니다" |
| 선생님 반려 | 시스템 | 학생 | "입금 내역을 확인해주세요" |

## 결제 설정 (선생님)

### PaymentTiming

| 값 | 설명 |
|----|------|
| `prepaid` | 선결제 |
| `postpaid` | 후결제 |

### 선결제 vs 후결제

| 항목 | 선결제 | 후결제 |
|------|--------|--------|
| 결제 시점 | 레슨 전 | 레슨 후 |
| 노쇼 처리 | 잔여 횟수 차감 | 100% 청구 |
| 취소 처리 | 잔여 횟수 유지/차감 | 청구 안 함 |
| 현금 흐름 | 안정적 | 미수금 위험 |

### PaymentMethod

| 값 | 설명 |
|----|------|
| `transfer` | 계좌이체 |
| `card` | 카드 |
| `cash` | 현금 |

## 미결제 처리

> **2026-02-06 변경**: UnpaidPolicy 삭제, Subscription.paymentConfirmed 기반 단순 모델로 변경.
> 상세: [세션 로그](../../session/2026-02-06_payment_redesign.md)

### 미수금 모델 (통합 후)

미수금 = 활성 수강권(`active`) 중 `paymentConfirmed == false`인 것.

| 경로 | paymentConfirmed | 미수금 |
|------|:----------------:|:------:|
| 선불 (Proposal) | 항상 true | X |
| 후불 (직접 발급, "입금 확인됨") | true | X |
| 후불 (직접 발급, "나중에 결제") | false | **O** |

### ~~UnpaidPolicy~~ (삭제됨)

~~allowLesson, blockLesson, reminderOnly~~ — 미구현 상태로 삭제.
D+3/5/7 자동 리마인더도 삭제 (푸시 알림 인프라 미구현).

### 처리 플로우 (단순화)

```
선생님이 "나중에 결제"로 수강권 발급
      │
   paymentConfirmed: false
      │
   홈 대시보드 미수금 StatCard에 표시
      │
   선생님이 오프라인에서 입금 확인
      │
   미수금 목록 → [입금확인] 탭
      │
   paymentConfirmed: true
      │
   미수금 해소
```

## 환불 정책

### 환불 계산 예시

**시나리오**: 8회권 380,000원 (5% 할인) 구매, 3회 사용 후 환불

| 정책 | 계산 | 환불금액 |
|------|------|----------|
| 100% 환불 | 5회 × (380,000 ÷ 8) | 237,500원 |
| 90% 환불 | 237,500 × 0.9 | 213,750원 |
| 회당 재계산 | 380,000 - (3 × 50,000) | 230,000원 |
