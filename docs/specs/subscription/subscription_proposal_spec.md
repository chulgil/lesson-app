## 1. 개요

### 1.1 배경

정기레슨 시작 전, 선생님이 학생에게 수강권을 제안하고 결제를 받은 후 수강권을 발급하는 플로우가 필요합니다.

### 1.2 기존 문제점

| 문제 | 설명 |
|------|------|
| 복잡한 제안 플로우 | 시간 3개 제안 → 선택 → 승인 (왕복 3회) |
| 결제 시점 불명확 | 시간 먼저 잡고 결제? 결제 먼저? |
| 반복 작업 | 선생님이 매번 금액/회차 설정 |

### 1.3 해결책: 수강권 템플릿 + 리드 관리 시스템

```
[핵심 아이디어]
1. 선생님이 수강권 템플릿을 미리 만들어둠 (1회성)
2. 템플릿이 선생님 프로필에 메뉴판처럼 공개 표시
3. 체험레슨 완료 시 → 앱이 자동으로 리드 생성 + 골든타임 할인 제안
4. 24h/48h/72h 자동 리마인더 발송 (앱이 선생님 대신)
5. 학생이 입금 후 알림 → 선생님이 확인 → 수강권 발급
6. 선생님 대시보드에서 리드 현황 한눈에 파악
```

### 1.4 v2 추가 기능

| 기능 | 설명 | 효과 |
|------|------|------|
| **리드 관리** | 체험 후 전환되지 않은 학생 추적 | 학생 이탈 방지 |
| **골든타임 전환** | 체험 직후 24시간 한정 할인 | 전환율 70%↑ |
| **자동 리마인더** | 앱이 선생님 대신 알림 발송 | 선생님 부담↓ |
| **대시보드** | 리드 상태 한눈에 파악 | 관리 효율↑ |

## 2. 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **수강권 우선** | 수강권이 있어야만 레슨 예약 가능 |
| **템플릿 재사용** | 선생님은 한 번 설정, 무한 재사용 |
| **메뉴판 공개** | 템플릿이 프로필에 공개되어 학생이 미리 확인 가능 |
| **앱 대리 알림** | 선생님이 트리거, 앱이 대신 알림 발송 (선생님 부담↓) |
| **단일 예약 화면** | 예약은 LessonBookingScreen 하나로 통일 |
| **자연스러운 순서** | 결제 → 수강권 발급 → 시간 예약 |
| **최소 클릭** | 선생님 제안: 2~3클릭, 학생 수락: 2클릭 |

### 2.1 학원 vs 개인 선생님 구분

| 유형 | 가격 설정 | 템플릿 소유 |
|------|----------|------------|
| **학원 소속** | 학원이 설정한 가격 사용 | 학원 템플릿 상속 |
| **개인 선생님** | 선생님 본인이 설정 | 본인 템플릿 관리 |

```
학원 소속 선생님:
├── 학원 관리자가 수강권 템플릿 설정
├── 소속 선생님들이 학원 템플릿 사용
└── 학원 계좌로 입금 안내

개인 선생님:
├── 본인이 직접 수강권 템플릿 설정
├── 본인 계좌로 입금 안내
└── 자유롭게 가격 조정 가능
```

### 3.3 시나리오별 분기

| 시나리오 | 수강권 상태 | 플로우 |
|----------|------------|--------|
| **신규 학생** | 없음 | 프로필 메뉴판 확인 → 체험레슨 → 리드 생성 |
| **체험레슨 후** | 없음 | 골든타임 제안 → (자동 리마인더) → 입금 → 발급 → 예약 |
| **수강권 만료** | 만료됨 | 갱신 제안 → 입금 → 발급 → 예약 |
| **수강권 보유** | 유효 | 바로 예약 (LessonBookingScreen) |
| **수강권 소진 임박** | 1~2회 남음 | 선생님이 갱신 제안 |

## 4. 수강권 템플릿

### 4.1 개념

선생님이 자주 사용하는 수강권 구성을 미리 저장해두고 재사용합니다.

### 4.2 템플릿 예시

| 템플릿명 | 횟수 | 금액 | 시간 | 유효기간 | 변경 |
|----------|:----:|-----:|:----:|:--------:|:----:|
| 바이올린 8회권 | 8회 | 380,000원 | 60분 | 2개월 | 2회 |
| 바이올린 4회권 | 4회 | 200,000원 | 60분 | 1개월 | 1회 |
| 체험레슨 | 1회 | 30,000원 | 45분 | 2주 | 0회 |
| 첼로 8회권 | 8회 | 400,000원 | 60분 | 2개월 | 2회 |

### 4.3 템플릿 필드

| 필드 | 필수 | 설명 | 예시 |
|------|:----:|------|------|
| name | ✅ | 템플릿 이름 | "바이올린 8회권" |
| instrument | ✅ | 악기 | "바이올린" |
| totalLessons | ✅ | 총 횟수 | 8 |
| amount | ✅ | 금액 (원) | 380000 |
| lessonDuration | ✅ | 레슨 시간 (분) | 60 |
| validityDays | ✅ | 유효 기간 (일) | 60 |
| rescheduleLimit | ✅ | 변경 가능 횟수 | 2 |
| description | ❌ | 설명 | "주 1회 권장" |
| isActive | ✅ | 활성화 여부 | true |

### 4.4 기본 템플릿 제공

선생님 가입 시 기본 템플릿 3개 자동 생성:

```dart
// 기본 템플릿 (선생님이 수정 가능)
- 체험레슨: 1회, 30,000원, 45분
- 4회권: 4회, 200,000원, 60분, 1개월
- 8회권: 8회, 380,000원, 60분, 2개월
```

## 5. 리드 관리 시스템

### 5.1 개요

체험레슨을 완료했지만 정규레슨으로 전환하지 않은 잠재 학생을 추적합니다.

### 5.2 리드 상태

| 상태 | 조건 | 설명 | 색상 |
|------|------|------|:----:|
| `hot` | 체험 후 24시간 이내 | 전환 가능성 높음, 즉시 접근 필요 | 🔴 |
| `warm` | 체험 후 24~72시간 | 관심은 있으나 고민 중 | 🟠 |
| `cold` | 체험 후 72시간 이상 | 관심 식어감, 적극적 접근 필요 | ⚪ |
| `converted` | 정규레슨 시작 | 전환 완료 | 🟢 |
| `lost` | 거절 또는 7일 초과 무응답 | 이탈 | ⚫ |

### 5.3 리드 상태 전이

```
체험레슨 완료
      │
      ▼
┌─────────────┐
│    hot      │ ← 0~24시간
│    🔴       │
└──────┬──────┘
       │
       │ 24시간 경과
       ▼
┌─────────────┐
│    warm     │ ← 24~72시간
│    🟠       │
└──────┬──────┘
       │
       │ 72시간 경과
       ▼
┌─────────────┐
│    cold     │ ← 72시간+
│    ⚪       │
└──────┬──────┘
       │
       │ 7일 경과 (무응답)
       ▼
┌─────────────┐
│    lost     │
│    ⚫       │
└─────────────┘

[어느 단계에서든]
       │
       │ 입금 완료
       ▼
┌─────────────┐
│  converted  │
│    🟢       │
└─────────────┘
```

## 7. 자동 리마인더

### 7.1 개요

체험 후 "다음에 할게요"를 선택한 학생에게 앱이 자동으로 리마인더를 발송합니다.
선생님은 설정만 하면 되고, 발송은 앱이 대신 처리합니다.

### 7.2 리마인더 스케줄

| 단계 | 발송 시점 | 리드 상태 | 메시지 톤 |
|:----:|----------|:--------:|----------|
| 1 | 24시간 후 | hot → warm | 부드러운 리마인드 |
| 2 | 48시간 후 | warm | 혜택 강조 |
| 3 | 72시간 후 | warm → cold | 마감 임박 긴급성 |
| 4 | 7일 후 | cold | 마지막 기회 |

  final bool autoReminderEnabled;       // 자동 리마인더 사용

    this.goldenTimeDiscountPercent = 10,

## 8. 통합 수강권 플로우 (Template-First) ✨ v7 통합

> **v7 핵심 변경**: 기존 "수강권 제안"과 "수강권 발급" 두 개의 분리된 플로우를
> **하나의 Template-First 플로우**로 통합합니다.
>
> | 항목 | v6 이전 | v7 |
> |------|---------|-----|
> | 발급 경로 | 수동 입력 폼 (모든 필드 직접) | **템플릿 선택 우선, 직접 입력은 폴백** |
> | 제안 경로 | 체크박스로 템플릿 선택 | **동일한 Selectable Card UI** |
> | 화면 수 | 2개 (제안 + 발급) | **1개 통합 화면 + 액션 분기** |

### 8.6 입금 확인 프로세스

> **핵심**: 입금 확인 = 수강권 발급 → 학생이 스케줄 확인

**학생 측:**
1. 제안 상세에서 계좌 정보 확인
2. 외부 앱(뱅킹)으로 입금
3. 앱으로 돌아와 [입금 완료했어요] 클릭

**선생님 측:**
1. 입금 알림 수신
2. 실제 입금 확인 (뱅킹 앱 확인)
3. **[입금 확인 완료] 클릭 → 자동 처리:**
   - 수강권 자동 발급
   - 관계 상태 → `active`
   - **스케줄 확인 카드 생성** (학생에게 표시)

**학생 스케줄 확인 (v3 변경!):**

| 케이스 | 카드 내용 | 학생 액션 |

| 신규 학생 | "체험 시간(토 15시)으로 예약?" | [예약] or [다른 시간] |
| 재등록 | "이전 스케줄(월 9시)로 예약?" | [예약] or [다른 시간] |
| 추가 악기 | "레슨 시간을 선택해주세요" | 가용시간에서 선택 |

// 입금 확인 시 처리
void onPaymentConfirmed(Proposal proposal) {
  // 1. 수강권 발급
  final subscription = issueSubscription(proposal);

  // 2. 관계 상태 변경
  updateRelationStatus(RelationshipStatus.active);

  // 3. 스케줄 확인 카드 생성 (학생에게 표시)
  if (proposal.isAppTransition) {
    // 앱 전환: 선생님이 직접 입력
    navigateToScheduleSetup(proposal.studentId);
  } else {
    // 스케줄 확인 카드 생성
    createScheduleConfirmationCard(
      studentId: proposal.studentId,
      suggestedTime: getSuggestedTime(proposal), // 체험/이전 스케줄
    );
  }

  // 4. 알림 발송
  notifyStudent("수강권 발급! 레슨 시간을 확정해주세요");
  notifyTeacher("수강권 발급 완료");
}

### 8.7 기존 정기레슨 → 앱 전환 ("결제 완료로 발급")

> 👉 전체 플로우: [flow_with_app.md](../lesson/flow_with_app.md) 섹션 2.5

기존에 앱 없이 정기레슨을 진행하다가 앱으로 전환하는 경우, 이미 결제가 완료된 상태이므로 **입금 확인 단계 없이** 바로 수강권을 발급합니다.

#### 앱 전환 vs 일반 발급 비교

| 항목 | 일반 발급 | 앱 전환 |
|------|----------|--------|
| 결제 상태 | 결제 대기 → 입금 완료 | **이미 결제됨** |
| 입금 확인 | 필요 | **불필요** |
| 스케줄 | 학생이 확인 (추천 시간) | **선생님 직접 입력** |
| 단계 수 | 5단계 | **3단계** |

## 9. 갱신 간소화 플로우

### 9.1 개요

재수강(갱신)은 **시스템이 자동으로 제안**합니다.
선생님 개입 없이 학생이 바로 갱신할 수 있습니다.

**핵심 원칙:**
- **시스템 자동 제안** - 선생님이 제안하지 않음
- **학생 주도** - 학생이 원하면 바로 갱신 진행
- **선생님 확인만** - 입금 확인만 선생님이 처리

**기존 vs 개선:**
| 구분 | 기존 (선생님 제안) | 개선 (시스템 자동) |
|------|-------------------|-------------------|
| 트리거 | 선생님이 수동 제안 | 시스템이 자동 알림 |
| 학생 액션 | 제안 기다림 → 수락 | 직접 갱신 버튼 클릭 |
| 선생님 액션 | 제안 + 입금 확인 | 입금 확인만 |

### 9.2 갱신 트리거 (시스템 자동)

| 트리거 | 조건 | 학생 알림 | 선생님 알림 |
|--------|------|----------|------------|
| **소진 임박** | 남은 횟수 ≤ 2회 | "수강권이 2회 남았어요" | "김서연 학생 수강권 2회 남음" |
| **만료 임박** | 유효기간 7일 이내 | "수강권이 7일 후 만료됩니다" | "김서연 학생 수강권 7일 후 만료" |
| **완전 소진** | 남은 횟수 = 0 | "수강권이 모두 소진되었어요" | "김서연 학생 수강권 소진" |

### 9.8 데이터 모델 변경

```dart
/// 갱신 요청 (학생이 직접 시작)
@HiveType(typeId: 97)
@JsonSerializable()
class SubscriptionRenewal {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String studentId;

  @HiveField(2)
  final String teacherId;

  @HiveField(3)
  final String previousSubscriptionId;  // 이전 수강권 ID

  @HiveField(4)
  final String templateId;              // 갱신할 수강권 템플릿

  @HiveField(5)
  final RenewalStatus status;

  @HiveField(6)
  final DateTime createdAt;

  @HiveField(7)
  final DateTime? paymentNotifiedAt;

  @HiveField(8)
  final DateTime? confirmedAt;

  @HiveField(9)
  final String? newSubscriptionId;      // 발급된 새 수강권 ID
}

enum RenewalStatus {
  pending,          // 학생이 갱신 시작
  paymentNotified,  // 입금 완료 알림
  confirmed,        // 입금 확인, 수강권 발급됨
  cancelled,        // 학생 취소
}
```

### 9.9 갱신 알림 타입

| 알림 ID | 수신자 | 트리거 | 내용 |
|---------|--------|--------|------|
| `SUBSCRIPTION_LOW` | 학생 | 시스템 자동 (2회 이하) | "수강권이 2회 남았어요" + [갱신하기] |
| `SUBSCRIPTION_LOW_INFO` | 선생님 | 시스템 자동 | "김서연 학생 수강권 2회 남음" (정보) |
| `RENEWAL_STARTED` | 선생님 | 학생 갱신 시작 | "김서연 학생이 갱신 진행 중" |
| `RENEWAL_PAYMENT` | 선생님 | 학생 입금 알림 | "김서연 학생이 갱신 입금 완료" |
| `RENEWAL_CONFIRMED` | 학생 | 입금 확인 시 | "수강권이 갱신되었습니다" |

### 9.10 갱신 vs 신규 제안 차이

| 항목 | 신규 제안 | 갱신 |
|------|----------|------|
| **시작 주체** | 선생님 | 시스템 (학생 액션) |
| **학생 화면** | 제안 수락/거절 | 직접 갱신 진행 |
| **수강 이력** | 표시 안함 | 이전 수강 이력 표시 |
| **엔티티** | SubscriptionProposal | SubscriptionRenewal |
| **알림 톤** | "제안했습니다" | "남았어요" + 액션 버튼 |

### 12.2 SubscriptionTemplate (수강권 템플릿)
> **v3 변경**: `teacherId` → `ownerId` + `ownerType`로 학원/개인 분리
> **v5 변경**: `isAutoProposalEnabled` 필드 추가 - 템플릿별 자동 제안 대상 설정

```dart
@HiveType(typeId: 96)
@JsonSerializable()
class SubscriptionTemplate {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String ownerId;           // teacherId 또는 academyId

  @HiveField(2)
  final SubscriptionTemplateOwnerType ownerType;  // teacher 또는 academy

  @HiveField(3)
  final String name;              // "8회권"

  @HiveField(4)
  final int totalLessons;         // 8

  @HiveField(5)
  final int lessonDurationMinutes; // 50 (분) - 이 수강권의 고정 수업 시간

  @HiveField(6)
  final int validityDays;         // 90

  @HiveField(7)
  final int price;                // 400000

  @HiveField(8)
  final bool isActive;            // true

  @HiveField(9)
  final int displayOrder;         // 표시 순서 (낮을수록 먼저)

  @HiveField(10)
  final String? description;      // "주 1회 권장"

  @HiveField(11)
  final DateTime createdAt;

  @HiveField(12)
  final DateTime? updatedAt;

  @HiveField(13)
  final int rescheduleAllowance;  // 변경 가능 횟수 (기본: 2)

  // 🆕 v5: 자동 제안 대상 여부
  @HiveField(14)
  final bool isAutoProposalEnabled;  // true: 체험 후 자동 제안 대상

  const SubscriptionTemplate({
    required this.id,
    required this.ownerId,
    required this.ownerType,
    required this.name,
    required this.totalLessons,
    required this.lessonDurationMinutes,
    required this.validityDays,
    required this.price,
    this.isActive = true,
    this.displayOrder = 0,
    this.description,
    required this.createdAt,
    this.updatedAt,
    this.rescheduleAllowance = 2,
    this.isAutoProposalEnabled = true,  // 기본값: 자동 제안 대상 ✅
  });

  // 회당 가격
  int get pricePerLesson => totalLessons > 0 ? price ~/ totalLessons : 0;

  // 표시용 레이블 (예: "8회권 (50분)")
  String get displayLabel => '$name ($lessonDurationMinutes분)';
}
```

**isAutoProposalEnabled 설명:**

| 값 | 의미 | 사용 시나리오 |
|----|------|-------------|
| `true` (기본값) | 체험레슨/재수강 시 자동 제안 대상 | 일반적인 수강권 (4회, 8회권 등) |
| `false` | 선생님 직접 제안만 가능 | 특별 패키지, 장기권 등 |

**자동 제안 발송 시점:**
- 체험레슨 완료 시 → 신규 학생에게 자동 제안
- 수강권 만료 시 → 기존 학생에게 재수강 자동 제안

**학원 vs 개인 설정 사용 규칙:**

| 예약 경로 | 사용하는 템플릿 | 설정 주체 |
|----------|----------------|----------|
| 학원 QR → 선생님 선택 | 학원 템플릿 (`ownerType: academy`) | 학원 관리자 |
| 선생님 직접 초대/검색 | 선생님 템플릿 (`ownerType: teacher`) | 선생님 본인 |

### 12.3 StudentLead (학생 리드)
```dart
@HiveType(typeId: 83)
enum LeadStatus {
  @HiveField(0)
  hot,        // 체험 후 24시간 이내

  @HiveField(1)
  warm,       // 체험 후 24~72시간

  @HiveField(2)
  cold,       // 체험 후 72시간 이상

  @HiveField(3)
  converted,  // 전환 완료 (정규레슨 시작)

  @HiveField(4)
  lost,       // 포기/거절
}

@HiveType(typeId: 84)
@JsonSerializable()
class StudentLead {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String teacherId;

  @HiveField(2)
  final String studentId;

  @HiveField(3)
  final String? trialLessonId;      // 체험레슨 ID (있는 경우)

  @HiveField(4)
  final LeadStatus status;

  @HiveField(5)
  final DateTime createdAt;         // 리드 생성 시점 (체험 완료 시점)

  @HiveField(6)
  final DateTime? convertedAt;      // 전환 시점

  @HiveField(7)
  final DateTime? lostAt;           // 포기/이탈 시점

  @HiveField(8)
  final int remindersSent;          // 발송된 리마인더 수

  @HiveField(9)
  final DateTime? lastReminderAt;   // 마지막 리마인더 발송 시점

  @HiveField(10)
  final bool discountOffered;       // 골든타임 할인 제안 여부

  @HiveField(11)
  final int? discountPercent;       // 제안된 할인율 (%)

  @HiveField(12)
  final DateTime? discountExpiresAt; // 할인 만료 시점

  @HiveField(13)
  final String? trialFeedback;      // 체험 후 학생 피드백 (선택)

  @HiveField(14)
  final String? lostReason;         // 이탈 사유 (선택)

  const StudentLead({
    required this.id,
    required this.teacherId,
    required this.studentId,
    this.trialLessonId,
    this.status = LeadStatus.hot,
    required this.createdAt,
    this.convertedAt,
    this.lostAt,
    this.remindersSent = 0,
    this.lastReminderAt,
    this.discountOffered = false,
    this.discountPercent,
    this.discountExpiresAt,
    this.trialFeedback,
    this.lostReason,
  });

  /// 현재 리드 상태 계산 (시간 기반)
  LeadStatus get currentStatus {
    if (status == LeadStatus.converted || status == LeadStatus.lost) {
      return status;
    }

    final hoursSinceCreation = DateTime.now().difference(createdAt).inHours;

    if (hoursSinceCreation < 24) {
      return LeadStatus.hot;
    } else if (hoursSinceCreation < 72) {
      return LeadStatus.warm;
    } else {
      return LeadStatus.cold;
    }
  }

  /// 할인 유효 여부
  bool get isDiscountValid {
    if (!discountOffered || discountExpiresAt == null) return false;
    return DateTime.now().isBefore(discountExpiresAt!);
  }

  /// 할인 남은 시간 (초 단위)
  int get discountRemainingSeconds {
    if (!isDiscountValid) return 0;
    return discountExpiresAt!.difference(DateTime.now()).inSeconds;
  }
}
```

### 13.4 충돌 감지 로직
```dart
/// 시작 시간 선택 시 충돌 체크
bool isSlotAvailable(
  DateTime date,
  TimeOfDay startTime,
  int durationMinutes,  // 수강권에서 가져옴
  List<AvailabilitySlot> bookedSlots,
) {
  final startMinutes = startTime.hour * 60 + startTime.minute;
  final endMinutes = startMinutes + durationMinutes;

  for (final booked in bookedSlots) {
    final bookedStart = booked.startTime.hour * 60 + booked.startTime.minute;
    final bookedEnd = booked.endTime.hour * 60 + booked.endTime.minute;

    // 겹치는지 확인
    if (startMinutes < bookedEnd && endMinutes > bookedStart) {
      return false;  // 충돌
    }
  }
  return true;  // 예약 가능
}
```
