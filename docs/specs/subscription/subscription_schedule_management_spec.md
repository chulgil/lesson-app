## 1. 현재 상태 & 갭 분석

### 구현 완료 (Phase 3 / 3B)

| 항목 | 상태 |
|------|------|
| 수강권 티켓 카드 (콘서트 스타일) | ✅ |
| 수강권 상세 — 챕터 모델 (Ch.1 정보, Ch.2 결제, Ch.3 레슨 진행) | ✅ |
| 변경/취소 바텀시트 (변경취소권 소진) | ✅ |
| 선생님 홈 수강권 섹션 | ✅ |
| 선생님 수강권 전체 목록 (상태 탭) | ✅ |
| 발급 시 기준시간 설정 | ✅ |

### 설계 갭 5가지

| # | 갭 | 영향 |
|---|---|------|
| G-1 | **수강권 전체 화면 부재** — 학생 뷰에 수강권 대시보드/개요 화면이 없음 | 학생이 수강권 현황을 한눈에 파악 불가 |
| G-2 | **스케줄 변경이 챗이 아님** — 바텀시트로 단발 변경만 가능, 선생님↔학생 메시지 교환 없음 | 변경 과정의 맥락(이유, 협의)이 기록 안 됨 |
| G-3 | **선생님 빈 시간대 UI 미연결** — 변경 시 선생님이 빈 시간대를 보여주고 학생이 선택하는 플로우 없음 | 변경이 단순 날짜 피커 → 충돌 가능 |
| G-4 | **홈 카드에 학원/학생 정보 없음** — 티켓 카드에 누구의 수강권인지 구별 불가 | 선생님이 여러 학생 관리 시 혼란 |
| G-5 | **변경 요청 알림/리스트 설계 없음** — 학생→선생님 변경 요청 시 알림·대기 목록이 없음 | 선생님이 변경 요청을 놓칠 수 있음 |

```
  ✅ 2회차 4/12(토) 14:00 완료

  📅 3회차 4/19(토) 14:00 예정     [▼ 펼치기]
  ┌──────────────────────────────────┐
  │  [학생 버블]                      │
  │  "이번 주 토요일 시간 변경       │
  │   부탁드립니다"                   │
  │  변경취소권 1회 사용 (잔여 1회)   │
  │                                  │
  │  [선생님 버블]                    │
  │  "가능한 시간 3개를 보내드려요"   │
  │  ┌────────────────────────┐     │
  │  │ 1순위 일 10:00~11:00   │     │  ← TimeSlotOption 칩
  │  │ 2순위 월 14:00~15:00   │     │
  │  │ 3순위 화 10:00~11:00   │     │
  │  └────────────────────────┘     │
  │                                  │
  │  [학생 버블]                      │
  │  "1순위 일 10:00으로 하겠습니다" │
  │                                  │
  │  ✅ 3회차 → 4/20(일) 10:00 확정  │  ← 확정 이벤트
```

> **참고**: 미래 미정 회차는 챗 리스트에 표시하지 않는다. 현재 회차(다음 예정)까지만 출력.

**데이터 모델**:
- `SubscriptionEvent` (NEW) — `RequestEvent`의 수강권 버전

**또는**: 기존 `RequestEvent`에 `subscriptionId` + `sessionNumber` 필드 추가하여 통합 관리.

```
[이벤트 타입 매핑]

레슨 요청 Phase 1       ↔   수강권 Phase 3 (스케줄 변경)
```

### G-3: 선생님 빈 시간대 연동

**변경 플로우 (전체)**:

```
[학생]                              [선생님]
  │                                    │
  ├─ 3회차 "시간 변경" 탭               │
  │  → 변경취소권 체크                  │
  │  → 후보 시간 최대 3개 + 사유 입력    │
  │  → scheduleChanged 이벤트           │
  │                                    │
  │     🔔 알림: "3회차 시간 변경 요청" ─┤
  │                                    │
  │                    학생이 보낸 1/2/3순위 후보 중 선택
  │                    scheduleChangeAccepted 이벤트
  │  ←─────────────────────────────────┤
  │                                    │
  │  ✅ 3회차 확정: 선택된 후보 시간      │
  │                                    │
```

**동일 프로세스 원칙**
- 학생과 선생님 모두 같은 규칙을 따른다.
- 내가 후보 시간을 보내면 상대의 하단 액션바가 레슨요청 UI와 같은 선택/수락 UI로 전환된다.
- 상대가 후보 시간을 이미 보낸 경우 나는 새 변경 플로우를 다시 시작하지 않는다.
- 수락 이벤트는 원 요청/제안의 `suggestedSlots`와 선택한 `selectedSlotIndex`를 보존한다.
- 내가 수락한 뒤에는 하단 액션바가 `응답 대기 + 결정 변경` 상태로 전환된다.
- `결정 변경`을 누르면 `withdrawApproval` 이벤트를 기록하고, 이전 수락 시간은 히스토리에서 취소선으로 표시한다.

**역방향 플로우도 동일**
```
[선생님]                            [학생]
  │                                    │
  ├─ 3회차 변경 후보 최대 3개 제안      │
  │  → scheduleChangeProposed 이벤트   │
  │                                    │
  │──── 🔔 "선생님이 시간을 제안했어요" ─►
  │                                    │
  │                    선생님이 보낸 1/2/3순위 후보 중 선택
  │                    scheduleChangeAccepted 이벤트
  │  ◄─────────────────────────────────┤
  │                                    │
  │  ✅ 3회차 확정: 선택된 후보 시간      │
```

**선생님이 학생 후보를 그대로 수락할 수 없는 경우**:
- `거절`: `scheduleChangeRejected`
- 다른 시간 제시: `scheduleChangeCountered` 또는 `scheduleChangeProposed`
- 이 응답이 기록된 뒤에는 기존 학생 요청 버블의 `[수락]` 액션을 숨긴다.

**학생이 선생님 후보를 그대로 수락할 수 없는 경우**:
- `거절`: `scheduleChangeRejected`
- 다른 시간 제시: `scheduleChangeCountered`
- 이 응답이 기록된 뒤에는 기존 선생님 제안 버블의 `[수락]` 액션을 숨긴다.

**선생님 수강권 상세에서 변경 응답 UI**:
```
┌──────────────────────────────────────┐
│  📅 3회차 — 변경 요청 도착!           │
│                                      │
│  학생 요청: "이번 주 시간 변경"       │
│  기존: 4/19(토) 14:00                │
│  ┌──────────────────────────────┐    │  ← 말풍선: 히스토리
│  │ 1순위 일 10:00~11:00         │    │
│  │ 2순위 월 14:00~15:00         │    │
│  │ 3순위 화 10:00~11:00         │    │
│  └──────────────────────────────┘    │
│                                      │
│  ─────────────────────────────────── │
│  일정을 탭하여 선택하세요              │  ← 하단 액션바
│  [1. 일 10:00] [2. 월 14:00] [3. 화 10:00]
│  [메시지 입력]                        │
│  [수락]                               │

```

**수락 후 UI**:

```
│  "2순위 월 14:00~15:00을 선택했습니다"│
│                                      │
│  ─────────────────────────────────── │
│  ⏳ 김소연님의 응답을 기다리고 있습니다 │
```

**예외 대응**:

## 3. 데이터 모델 결정

### 옵션 A: `RequestEvent`에 필드 추가 (기존 확장)

```dart
class RequestEvent {
  // ... 기존 필드 ...
  final String? subscriptionId;  // NEW: null이면 레슨 요청 이벤트
  final int? sessionNumber;      // NEW: 수강권 회차 번호
}
```

**장점**: 기존 `RequestHistoryChat` 100% 재사용
**단점**: `RequestEvent`가 레슨 요청 + 수강권 이중 책임

### 옵션 B: `SubscriptionEvent` 별도 엔티티 (NEW)

```dart
class SubscriptionEvent {
  final String id;
  final String subscriptionId;
  final int sessionNumber;
  final String actorId;
  final String actorType; // 'teacher' | 'student'
  final SubscriptionEventType eventType;
  final List<TimeSlotOption> suggestedSlots;
  final int? selectedSlotIndex;
  final String? message;
  final DateTime createdAt;
}
```

**장점**: 책임 분리, 독립적 진화 가능
**단점**: Chat 위젯 신규 구현 필요 (패턴은 동일하지만 코드 중복)

### 권장: **옵션 A** (RequestEvent 확장)

이유:
- `RequestHistoryChat`, `AlternativeTimeGrid`, `TimeSlotPicker` 100% 재사용
- 이벤트 타입 (`scheduleChangeProposed` 등) 이미 존재
- 데이터 양이 적음 (회차당 최대 5-10개 이벤트)

## 4.5 추가: 학생 상세 화면 티켓 카드 교체 (G-6)

### 현재 상태

`StudentSubscriptionSection` (`student_subscription_section.dart`)는 자체 `_SubscriptionMembershipCard`를 사용.
홈 화면의 `SubscriptionTicketCard`와 완전히 다른 디자인.

## 6. 수강권 유형별 스케줄 관리 규칙 (핵심)

### 6.1 정규권 (monthly) vs 회차권 (package)

| | 정규권 (monthly) | 회차권 (package) |
|---|---|---|
| **스케줄 설정** | 첫 시작 시 고정 요일/시간 설정 (예: 매주 토 14:00) | 1회차만 스케줄 잡고, 이후 매회 예약 |
| **자동 생성** | 고정 스케줄로 전체 회차 자동 생성 | 1회차만 생성, 이후는 학생이 예약 |
| **스케줄 변경** | 이번 회차만 / 현재~이후 전체 변경 선택 | 해당 회차만 변경 |
| **예약 방식** | 자동 (고정) | 학생이 선생님 빈 시간대에서 선택 |

### 6.2 정규권 — 고정 스케줄 + 2가지 변경 모드

```
[정규권 수강권 상세]

  Ch.3 레슨 진행 (3/8회)  — 매주 토 14:00

  ✅ 1회차 4/5(토) 14:00 완료
  ✅ 2회차 4/12(토) 14:00 완료
  ✅ 3회차 4/19(토) 14:00 완료
  📅 4회차 4/26(토) 14:00 예정      ← 자동 생성된 고정 스케줄
  📅 5회차 5/3(토) 14:00 예정
  📅 6회차 5/10(토) 14:00 예정
  ⏳ 7~8회차 (5주차 정책에 따라)
```

**변경 시 선택지:**
```
┌──────────────────────────────────────┐
│  스케줄 변경 유형 선택                 │
│                                      │
│  ┌──────────────────────────────┐   │
│  │ 📅 이번 회차만 변경           │   │  ← singleLesson
│  │    4회차 4/26(토) 14:00만     │   │
│  │    다른 회차는 그대로          │   │
│  └──────────────────────────────┘   │
│                                      │
│  ┌──────────────────────────────┐   │
│  │ 🔄 앞으로 전체 변경           │   │  ← bulkChange
│  │    4회차~8회차 모두            │   │
│  │    새로운 고정 요일/시간       │   │
│  └──────────────────────────────┘   │
│                                      │
│  ⚠️ 완료된 1~3회차는 변경 불가    │   │
└──────────────────────────────────────┘
```

**전체 변경 (bulkChange) 플로우:**

> **UI 통일**: "이번 회차만"과 동일한 `ScheduleChangeSlotScreen` 사용 (선생님 빈 시간대 그리드).
> 최대 3개 후보 제안 → 상대방 수락 시 해당 요일+시간이 매주 반복 고정 스케줄로 적용.

```
학생: "앞으로 전체 변경" 선택
  → 변경취소권 소진 (기준시간 이내일 때)
  → 선생님에게 변경 요청

선생님: ScheduleChangeSlotScreen에서 빈 시간대 최대 3개 선택
  → 각 슬롯은 "매주 [요일] [시간]" 의미
  → scheduleChangeProposed (bulkChange)

학생: 3개 중 1개 수락
  → 4회차~8회차 전체 → 수락한 요일+시간으로 재생성
```

**삭제 대상**: `RegularScheduleChangeScreen` (요일 칩 + 드롭다운) → `ScheduleChangeSlotScreen`으로 통합

### 6.3 회차권 — 매회 예약 방식

```
[회차권 수강권 상세]

  Ch.3 레슨 진행 (2/10회)

  ✅ 1회차 4/5(토) 14:00 완료        ← 최초 예약
  ✅ 2회차 4/10(목) 16:00 완료        ← 학생이 빈 시간대에서 예약

  📅 3회차 — 예약 필요               ← 다음 회차 예약 필요
  ┌──────────────────────────────┐
  │  선생님의 빈 시간대             │
  │  ┌────┐ ┌────┐ ┌────┐       │  ← TimeSlotPicker
  │  │토14 │ │일10 │ │월15 │       │
  │  └────┘ └────┘ └────┘       │
  │                              │
  │  [예약하기]                    │
  └──────────────────────────────┘

  ⏳ 4~10회차 (예약 대기)
```

**회차권은 "전체 변경" 없음** — 각 회차가 독립적이므로 해당 회차만 변경.

### 6.4 온보딩 가이드 메시지

첫 사용 시 상태별 가이드를 화면 상단에 표시 (기존 `ChatGuideMessage` 패턴 재사용):

| 유형 | 시점 | 가이드 메시지 (선생님) | 가이드 메시지 (학생) |
|------|------|----------------------|---------------------|
| **정규권 발급 직후** | Ch.3 첫 진입 | "고정 스케줄이 자동 생성되었습니다. 변경이 필요하면 해당 회차를 탭하세요." | "매주 [요일] [시간]에 레슨이 예정되어 있습니다." |
| **회차권 1회차 완료 후** | 2회차 예약 필요 | "학생이 다음 레슨을 예약하면 알림을 보내드립니다." | "다음 레슨 시간을 선생님의 빈 시간대에서 선택하세요." |
| **정규권 변경 요청** | 변경 챗 진입 | "이번 회차만 변경하거나, 앞으로의 전체 스케줄을 변경할 수 있습니다." | "이번 회차만 변경하거나, 앞으로의 전체 스케줄을 변경할 수 있습니다." |
| **변경취소권 소진 임박** | 잔여 1회 | "변경취소권이 1회 남았습니다." | "변경취소권이 1회 남았습니다. 신중하게 사용하세요." |
| **변경취소권 소진** | 잔여 0회 | "이 수강권의 변경취소권이 모두 소진되었습니다." | "변경취소권이 소진되어 스케줄 변경이 불가합니다." |

**가이드 표시 규칙:**
- 해당 조건에 처음 도달했을 때만 표시
- 닫기(X) 탭하면 해당 가이드 다시 표시 안 함
- 색상: action(primary) / warning(amber) — 기존 가이드 2색 규칙 준수

## 7. 최종 구현 Phase (수정)

| Phase | 내용 | 핵심 포인트 |
|-------|------|------------|
| **C-1** | 티켓 카드 보강 + 학생 상세 교체 | 역할별 이름 표시 |

| **C-3** | 회차별 챗 임베딩 (유형별 분기) | 현재 회차까지만 표시 (미래 미정 숨김) |
| **C-4** | 변경 플로우 (유형별) | 정규권: 이번만/전체 선택, 회차권: 해당만 |

| **C-6** | 수강권 전체 화면 확장 | Summary + Pending |

### Phase C-2 상세 — 유형별 스케줄 생성

```
수강권 발급 시:
  정규권 (monthly) → 고정 요일/시간으로 전체 회차 스케줄 자동 생성
  회차권 (package) → 1회차만 스케줄 생성, 이후는 "예약 필요" 상태
```

### Phase C-4 상세 — 유형별 변경 플로우

```
정규권:
  ├── "이번 회차만" → singleLesson 변경 (기존과 동일)

회차권:
  └── 해당 회차만 변경 (선택지 없음, singleLesson만)
```
