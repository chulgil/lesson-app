## 1. v2 → v3 전면 재설계 근거

### 1.1 v2의 문제

| 문제 | 설명 |
|------|------|
| **공지와 취소가 결합** | 휴강 공지를 보내면 레슨이 자동 취소됨 → 선생님이 "공지만 보내고 싶은데 취소까지 되네?" |
| **학생 선택이 전제** | 수강관리에서 학생을 먼저 체크해야 휴강 가능 → "나는 날짜를 정하고 싶은데 학생을 먼저 고르라니?" |
| **스케줄 조정이 자동** | 학생마다 수업일/시간이 다른데 일괄 취소 → 보강 일정은 결국 개별로 잡아야 함 |
| **영향 학생 인지 부족** | 휴강일에 수업이 있는 학생이 누구인지 선생님이 한눈에 파악 어려움 |

### 1.2 v3 핵심 원칙

> **"공지는 공지, 스케줄 조정은 개별"**

| 원칙 | 설명 |
|------|------|
| **공지 우선** | 휴강 공지 = 날짜 지정 + 메시지 → 전체 학생에게 알림. 레슨 자동 취소 안 함 |
| **영향 학생 인지** | 공지 후 "이 날 수업 있는 학생" 목록 제공 → 선생님이 개별 스케줄 변경 |
| **휴강일 전역 표시** | 선생님/학생 스케줄 탭, 수강권 상세, 시간 선택 UI 등 모든 관련 화면에 표시 |
| **진입점 변경** | 학생 선택 불필요 → Masthead 공지 아이콘에서 바로 접근 |

### 1.3 유사 서비스 벤치마크

| 서비스 | 방식 | 배울 점 |
|--------|------|---------|
| **클래스팅 (학원 관리)** | 공지 게시 → 학부모가 확인 | 공지와 스케줄 분리 |
| **똑닥 (병원 예약)** | 휴진 공지 → 해당일 예약 자동 취소 | 의료는 자동 취소가 맞지만 레슨은 학생별 스케줄이 다름 |
| **Acuity Scheduling** | "Block off time" → 해당 시간 예약 불가 | 시간 차단 개념 (우리의 휴강일 마킹) |
| **Google Calendar** | 부재중 설정 → 해당 시간 회의 자동 거절 | 선택적 자동 거절 |
| **카카오톡 채널** | 상단 고정 공지 | 공지는 공지, 개별 대화는 별도 |

## 2. 진입점 — 수강관리 Masthead

### 2.1 아이콘 배치

```
┌─── 수강관리 Masthead ──────────────────────────┐
│ ENROLLMENTS                                     │
│                    [📢 공지] [☑ 선택] [+ 추가]  │
└─────────────────────────────────────────────────┘
```

- `📢` (Icons.campaign): 공지 아이콘 — 탭 → 공지 작성 시트
- `☑` (Icons.checklist_rounded): 선택 모드 — 기존 일괄 작업 (메시지 보내기)
- `+` (Icons.add): 학생 추가 — 기존

### 2.2 공지 작성 시트 (AnnouncementSheet)

```
┌─── 공지 작성 ──────────────────────────────────┐
│                                                 │
│  ♪ 공지                                         │
│  ──────────────                                 │
│                                                 │
│  타입                                           │
│  [● 휴강]  [○ 일반 공지]                         │
│                                                 │
│  날짜 (휴강 시)                                  │
│  [📅 5월 9일 금요일              ]               │
│                                                 │
│  메시지                                          │
│  ┌─────────────────────────────────────┐        │
│  │ 개인 사정으로 휴강합니다.              │        │
│  │ 보강 일정은 개별 연락드리겠습니다.      │        │
│  └─────────────────────────────────────┘        │
│                                                 │
│  [공지 보내기]                                   │
└─────────────────────────────────────────────────┘
```

**타입별 동작:**

| 타입 | 날짜 선택 | 동작 |
|------|----------|------|
| **휴강** | 필수 (단일 날짜) | 해당 날짜를 "휴강일"로 등록 + 전체 활성 학생에게 알림 |
| **일반 공지** | 불필요 | 전체 활성 학생에게 메시지 알림 |

> **복수 날짜**: 복수 날짜 휴강 시 각 날짜별로 공지를 별도 생성.
> "5/9~5/11 3일간 휴강"이면 공지 1건(날짜: 5/9, 메시지에 기간 명시)으로 처리.
> 시스템적으로는 날짜별 휴강 마킹이 필요하므로 날짜 목록도 저장.

## 3. 공지 후 — 영향 학생 목록

### 3.1 휴강 공지 발송 후 결과 화면

```
┌─── 공지 발송 완료 ─────────────────────────────┐
│                                                 │
│  ✓ 휴강 공지가 발송되었습니다                     │
│  5월 9일 금요일 · 12명에게 알림                   │
│                                                 │
│  ── 이 날 수업이 있는 학생 ──                    │
│                                                 │
│  ┌─────────────────────────────────────┐        │
│  │ 김민지 · 바이올린 · 14:00 · 3회차    │        │
│  │                   [스케줄 변경 →]    │        │
│  ├─────────────────────────────────────┤        │
│  │ 박지수 · 피아노 · 15:30 · 5회차      │        │
│  │                   [스케줄 변경 →]    │        │
│  ├─────────────────────────────────────┤        │
│  │ 이서연 · 바이올린 · 17:00 · 2회차    │        │
│  │                   [스케줄 변경 →]    │        │
│  └─────────────────────────────────────┘        │
│                                                 │
│  ※ 레슨은 자동 취소되지 않습니다.                 │
│    개별 스케줄 변경을 진행해주세요.                │
│                                                 │
│  [확인]                                          │
└─────────────────────────────────────────────────┘
```

**핵심: 레슨 자동 취소 안 함.**
- 공지만 보내고, 선생님이 영향 학생을 확인한 후 **개별적으로** 스케줄 변경 진행
- [스케줄 변경 →] 탭 → 해당 학생의 수강권 상세 화면으로 이동 → 기존 스케줄 변경 플로우

### 3.2 왜 자동 취소를 하지 않는가?

| 이유 | 설명 |
|------|------|
| **학생별 상황이 다름** | 어떤 학생은 보강 필요, 어떤 학생은 그냥 1회 빠져도 OK |
| **선생님 판단 필요** | "김민지는 시험 기간이라 보강 안 해도 되고, 박지수는 발표 앞이라 꼭 보강" |
| **오취소 방지** | 한 번 취소하면 되돌리기 어려움. 공지 후 개별 판단이 안전 |
| **유사 서비스 패턴** | 학원/병원 앱도 공지와 예약 취소를 분리하는 추세 |

## 4. 데이터 모델

### 4.1 TeacherAnnouncement 엔티티

```dart
/// 선생님 공지 (휴강/일반)
class TeacherAnnouncement {
  final String id;
  final String teacherId;
  final AnnouncementType type;      // dayOff, general
  final List<DateTime> dates;       // 휴강 날짜 목록 (dayOff 시 필수)
  final String message;
  final DateTime createdAt;
  final List<String> affectedStudentIds;  // 해당 날짜 수업 있는 학생 (dayOff 시)
}

enum AnnouncementType {
  dayOff,     // 휴강
  general,    // 일반 공지
}
```

### 4.2 Backend API

| Endpoint | Method | 용도 |
|----------|--------|------|
| `/api/v1/announcements` | POST | 공지 생성 (휴강/일반) |
| `/api/v1/announcements` | GET | 선생님의 공지 목록 |
| `/api/v1/announcements/day-offs` | GET | 특정 기간의 휴강일 목록 (스케줄 표시용) |

**POST /api/v1/announcements Request:**
```json
{
  "teacher_id": "uuid",
  "type": "dayOff",
  "dates": ["2026-05-09"],
  "message": "개인 사정으로 휴강합니다"
}
```

**처리 로직:**
1. `TeacherAnnouncement` 레코드 저장
2. 해당 선생님의 전체 활성 수강권 학생에게 Notification 발송
3. 휴강 타입이면: 해당 날짜에 수업이 있는 학생 ID 목록을 `affectedStudentIds`에 저장
4. Response에 `affectedStudentIds` + 레슨 정보 반환

**Response:**
```json
{
  "id": "ann_uuid",
  "notified_count": 12,
  "affected_lessons": [
    { "student_id": "s1", "student_name": "김민지", "instrument": "바이올린", "start_time": "14:00", "session_number": 3 },
    { "student_id": "s2", "student_name": "박지수", "instrument": "피아노", "start_time": "15:30", "session_number": 5 }
  ]
}
```

## 5. 휴강일 전역 표시 — 모든 관련 화면

### 5.1 표시 화면 매트릭스

| # | 화면 | 대상 | 표시 방식 | 구현 방법 |
|---|------|------|----------|----------|
| 1 | **선생님 스케줄 탭** (주간 뷰) | 선생님 | 해당 날짜 셀에 "휴강" 라벨 + grey-out 배경 | `teacherDayOffsProvider` 구독 |
| 2 | **학생 스케줄 탭** | 학생 | 해당 날짜 레슨에 "휴강" 마크 | `studentDayOffsProvider` 구독 |
| 3 | **수강권 상세 (시간변경 상세)** | 선생님+학생 | 상단 배너 "5/9 휴강" | `_TeacherCancelBanner` (기존) |
| 4 | **스케줄 재조절 시간 선택** | 선생님+학생 | 휴강일 시간대 비활성화 (선택 불가) | 슬롯 생성 시 휴강일 제외 |
| 5 | **알림 리스트** | 학생 | "5/9 휴강 안내" | Notification |
| 6 | **선생님 홈 대시보드** | 선생님 | 오늘이 휴강일이면 "오늘 휴강" 배너 | TimeContextBanner 확장 |

### 5.2 선생님 스케줄 탭 — 휴강일 표시

```
┌─── 주간 스케줄 ────────────────────────────────┐
│ 월 5/5  화 5/6  수 5/7  목 5/8  금 5/9  토 5/10│
│                                                │
│ 14:00   14:00                   ┌──────────┐   │
│ 김민지  이서연                   │ ⚠ 휴강    │   │
│                                 │           │   │
│ 15:30                           │ 김민지    │   │
│ 박지수                          │ 14:00    │   │
│                                 │ (취소필요)│   │
│                                 │           │   │
│                                 │ 박지수    │   │
│                                 │ 15:30    │   │
│                                 │ (취소필요)│   │
│                                 └──────────┘   │
└────────────────────────────────────────────────┘
```

- 휴강일 셀: `paperDark` 배경 + "⚠ 휴강" 헤더
- 해당일 레슨: 표시되되 "(취소필요)" 힌트로 선생님에게 스케줄 변경 유도
- 탭 → 해당 학생 수강권 상세로 이동

### 5.3 학생 스케줄 변경 상세 — 상단 배너

기존 `_TeacherCancelBanner` 재사용. 데이터 소스만 `TeacherAnnouncement`로 변경.

### 5.4 스케줄 재조절 시간 선택 — 휴강일 비활성화

│ 5/9 금 ← ❌ 휴강일 (선택 불가)     │

## 6. 선생님 ↔ 학생 E2E 프로세스

```
[선생님]                       [시스템]                    [학생]
  │                             │                          │
  ├─ 📢 공지 아이콘 탭           │                          │
  ├─ 타입: 휴강                  │                          │
  ├─ 날짜: 5/9                   │                          │
  ├─ 메시지 입력                 │                          │
  ├─ [공지 보내기]               │                          │
  │                             │                          │

  │                        │ 1. Announcement 저장    │       │

  │   박지수 15:30 [변경→]       │                          │
  │   이서연 17:00 [변경→]       │                          │
  │                             │                          │
  │  ※ 레슨 자동 취소 안 함      │                          │
  │                             │                          │
  ├─ 김민지 [변경→] 탭           │                          │
  │                             │                          │
  │  (기존 스케줄 변경 플로우)     │                          │
  ├─ 3개 시간대 제안 ───────→   │                          │
  │                             │── 제안 알림 ──────────→  │
  │                             │                          │
  │                             │  ←── 수락 ──────────────│
  │ ← 수락 알림                  │                          │
  │   "3회차 보강 5/16 확정"     │                          │
  │                             │                          │
```

### 6.1 선생님 어드벤티지

| 어드벤티지 | 설명 |
|-----------|------|
| **1탭 공지** | Masthead 공지 아이콘 → 날짜 + 메시지 → 완료. 학생 선택 불필요 |
| **영향 학생 즉시 인지** | "이 날 수업 있는 학생 N명" + 시간/회차 정보 한눈에 |
| **개별 스케줄 변경 딥링크** | [변경→] 1탭으로 해당 학생 스케줄 변경 화면 진입 |
| **스케줄 탭에 휴강일 표시** | 주간 뷰에서 휴강일 셀이 grey-out → 일정 관리 편의 |
| **오취소 방지** | 자동 취소 없으므로 실수로 레슨이 사라지지 않음 |

### 6.2 학생이 받는 경험

| 시점 | 학생 경험 |
|------|----------|
| 공지 수신 | 푸시 알림 "5/9 휴강 안내" + 메시지 |
| 스케줄 탭 확인 | 5/9 레슨에 "휴강" 마크 표시 |
| 수강권 상세 진입 | 상단 배너 "5/9 휴강" (7일간) |
| 선생님이 보강 제안 | 기존 스케줄 변경 플로우 (시간대 선택 → 수락) |

## 7. 기존 일괄 작업과의 관계

### 7.1 기능 분리

| 기능 | 진입점 | 용도 |
|------|--------|------|
| **📢 공지** (v3 신규) | Masthead 공지 아이콘 | 휴강/일반 공지 → 전체 학생 알림 + 휴강일 마킹 |
| **☑ 선택 모드** (기존 유지) | Masthead 체크리스트 아이콘 | 선택된 학생에게 일괄 메시지 (활성 수강권 학생만) |

### 7.2 v2에서 제거/변경되는 것

| v2 기능 | v3 처리 |
|---------|---------|
| `BulkCancelScreen` (휴강 공지) | → `AnnouncementSheet` (공지 시트)로 대체 |
| 레슨 자동 `cancelledByTeacher` | → **제거** (공지만, 취소 안 함) |
| `RequestEvent(lessonCancelledByTeacher)` | → **제거** (스케줄 변경은 기존 협상 플로우로) |
| `BulkMessageSheet` (일괄 메시지) | → 유지 (선택 모드에서 접근) |
| 하단 액션바 [휴강 공지] 버튼 | → **제거** (Masthead 공지 아이콘으로 이동) |

### 7.3 유지되는 것

- ☑ 선택 모드 + 전체 선택/해제
- 일괄 메시지 (활성 수강권 학생만 + 안내 텍스트)
- 기존 스케줄 변경 협상 플로우 (scheduleChanged → proposed → accepted)

## 9. Lore 결정

- **Lore-directive**: 휴강 = 공지 + 휴강일 마킹. 레슨 자동 취소 안 함. 스케줄 조정은 선생님이 개별 판단.
- **Lore-directive**: 공지 진입점은 Masthead 공지 아이콘. 학생 선택 불필요 (전체 학생 대상).
- **Lore-directive**: 휴강일은 선생님/학생 스케줄 탭, 수강권 상세, 시간 선택 UI 등 모든 관련 화면에 전역 표시.
- **Lore-constraint**: 복수 날짜 휴강은 각 날짜별 공지가 아닌, 1건 공지에 dates[] 배열로 저장.
- **Lore-rejected**: v2 레슨 자동 취소 — 학생별 상황이 다르므로 일괄 취소는 오취소 위험. 선생님 개별 판단이 안전.
- **Lore-rejected**: 학생 선택 후 휴강 — "날짜를 정하고 누가 영향받는지 보고 싶다"가 선생님의 실제 사고 흐름.

## 10. 공지 이력 + 영향 학생 재확인

### 10.1 문제

공지 발송 후 선생님이 다시 확인할 방법이 없음:
- "내가 언제 휴강 공지를 보냈지?"
- "그날 수업 있는 학생이 누구였지?"
- "스케줄 변경을 아직 안 한 학생이 누구지?"

### 10.2 공지 이력 화면

진입: 수강관리 Masthead 📢 아이콘 **길게 누르기** → 공지 이력 화면

```
┌─── 공지 이력 ───────────────────────────────┐
│ Masthead: "ANNOUNCEMENTS"                    │
│                                              │
│ ── 5월 7일 (오늘) ──                          │
│ ┌────────────────────────────────────────┐   │
│ │ ⚠ 휴강 · 5/9                           │   │
│ │ 개인 사정으로 휴강합니다                  │   │
│ │                                        │   │
│ │ 영향 학생 3명:                           │   │
│ │ · 김민지 14:00 ✓ 스케줄 변경 완료        │   │
│ │ · 박지수 15:30 ⚠ 미처리                 │   │
│ │ · 이서연 17:00 ⚠ 미처리                 │   │
│ │                                        │   │
│ │ [스케줄 변경 →] [삭제]                   │   │
│ └────────────────────────────────────────┘   │
│                                              │
│ ── 4월 28일 ──                                │
│ ┌────────────────────────────────────────┐   │
│ │ 📋 일반 공지                             │   │
│ │ 5월 발표회 안내                           │   │
│ └────────────────────────────────────────┘   │
└──────────────────────────────────────────────┘
```

### 10.3 영향 학생 처리 상태

휴강 공지의 영향 학생은 스케줄 변경 처리 여부를 추적:

| 상태 | 표시 | 조건 |
|------|------|------|
| ✓ 완료 | `paperOk` | 해당 학생 수강권에 `scheduleChangeAccepted` 이벤트 존재 |
| ⚠ 미처리 | `paperAccent` | 스케줄 변경 미진행 |

[스케줄 변경 →] 탭 → 해당 학생 수강권 상세로 이동

### 10.4 공지 아이콘 뱃지

수강관리 📢 아이콘에 미처리 학생이 있으면 dot 뱃지:
- 빨간 dot = 휴강 공지 중 미처리 학생 1명+
- dot 없음 = 모든 영향 학생 처리 완료 또는 공지 없음
