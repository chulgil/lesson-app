## 문제점

현재 가용시간 관리 화면(`TeacherAvailabilityScreen`)이 직관적이지 않아 선생님이 어떤 기능인지 이해하기 어려움.

### 현재 UX 문제

1. **용어 모호성**: "가용시간", "시간 예외", "슬롯" 등 기술적 용어 사용
2. **적용 기준 불명확**: 설정한 가용시간이 어디에 어떻게 반영되는지 안내 없음
3. **진입 경로 깊음**: 프로필 → 레슨 시간 설정 → 가용시간 관리 (3단계)
4. **시각적 피드백 부족**: 설정 후 실제 스케줄에 어떻게 반영되는지 미리보기 없음
5. **설정 항목 분산**: 슬롯 길이, 쉬는시간, 요일별 시간이 별도 화면

## 설계 원칙

1. **한눈에 이해**: 화면을 보자마자 "내 레슨 시간을 설정하는 곳"임을 인지
2. **실시간 미리보기**: 설정 변경 시 주간 스케줄 미리보기 즉시 반영
3. **가이드 텍스트**: 각 설정이 어디에 영향을 미치는지 안내

## UI 설계

### 레이아웃 패턴 — Split (2026-06-01 — E2E 감사 #9 C-G2)

Calendly 차용. 좌측 설정 + 우측 미리보기 동시 노출.

```
┌──────────────────────────────┬──────────────────────────────┐
│ 설정 (좌측)                  │ 미리보기 (우측 — 실시간)     │
├──────────────────────────────┼──────────────────────────────┤
│ 화면 제목                    │ 이번 주 예상 스케줄          │
│                              │                              │
│ 섹션 1: 주간 레슨 시간       │ ┌──┬──┬──┬──┬──┬──┬──┐    │
│   요일별 시간대 토글         │ │월│화│수│목│금│토│일│    │
│                              │ ├──┼──┼──┼──┼──┼──┼──┤    │
│ 섹션 2: 레슨 설정            │ │14│14│  │14│14│  │  │ 가용│
│   레슨 1회 시간 / 쉬는 시간 │ │15│15│  │15│15│  │  │      │
│                              │ │  │  │쉼│ ▓│ ▓│  │  │ 예약│
│ 섹션 4: 임시 휴무/추가 오픈 │ │  │  │  │ ▓│  │  │  │      │
│                              │ │16│16│  │  │  │  │  │      │
│                              │ │17│17│  │16│16│  │  │      │
│                              │ └──┴──┴──┴──┴──┴──┴──┘    │
│                              │                              │
│ [저장]                       │ 위 미리보기는 다음 주        │
│                              │ 학생이 예약할 수 있는 시간   │
└──────────────────────────────┴──────────────────────────────┘
```

- 좌측 설정 변경 시 우측 미리보기 실시간 업데이트
- 모바일 (≤ 768px) 에서는 단일 컬럼 + 상단 고정 미리보기 카드
- 첫 슬롯 등록까지 탭 수 목표: **≤ 3탭**

### 진입 경로 단축 (E2E 감사 #9)

```
Before: 프로필 → 레슨 시간 설정 → 가용시간 관리 (3단계)
After:  홈 → "레슨 시간 설정" 직접 진입 (1단계) + 온보딩 첫 가용시간 인터스티셜
```

> 온보딩 중 첫 가용시간 등록은 [teacher_first_availability_setup.md](../onboarding/teacher_first_availability_setup.md) 의 간소 화면 사용. 본 스펙의 풀 화면은 이후 변경·추가 용도.

### 사용자 친숙 용어 매핑 (2026-06-01 — E2E 감사 #9 C-G2)

내부 기술 용어는 UI 에 노출하지 않는다. 화면·도움말·에러 메시지 모두 표시 용어 사용.

| 내부 용어 (코드/스펙) | 표시 용어 (UI) | 비고 |
|---|---|---|
| `TeacherAvailability` | "레슨 운영 시간" | 화면 제목 |
| `WeeklySchedule` | "주간 레슨 시간" | 섹션 1 헤더 |
| `TimeException` | "임시 휴무/추가 오픈" | 섹션 4 헤더 |
| `slotDurationMinutes` | "레슨 1회 시간" | 섹션 2 |
| `breakTimeBetweenLessons` | "쉬는 시간" | 섹션 2 |
| `slotStartInterval` | (UI 미노출) | 내부 자동 계산 |
| "가용시간" (이전) | "레슨 시간" / "레슨 운영 시간" | 기술 용어 → 일상 용어 |
| "슬롯" (이전) | "예약 가능 시간" / "레슨" | 시스템 용어 → 사용자 표현 |
| "시간 예외" (이전) | "임시 휴무" / "추가 오픈" | 추상 용어 → 구체 행위 |

> SSOT: 글로서리 (`.harness/knowledge/glossary.md` §3, `docs/specs/glossary.md`). 새 UI 텍스트는 `AppStrings` 키로 등록 (`lessonDurationLabel`, `breakTimeLabel`, etc.). 다국어 대비.

### 섹션 1: 주간 레슨 시간

**헤더**: "레슨하는 요일과 시간을 설정하세요"
**부제**: "설정한 시간이 스케줄과 학생 예약 화면에 반영됩니다"

| 요일 | 시작 | ~ | 종료 | 토글 |
|------|------|---|------|------|
| 월요일 | 14:00 | ~ | 18:00 | ON/OFF |
| 화요일 | 14:00 | ~ | 18:00 | ON |
| 수요일 | - | | - | OFF (쉬는날) |
| ... | | | | |

- 각 요일에 ON/OFF 토글
- OFF = 쉬는날 (스케줄에 회색 배경으로 표시)
- ON 시 시작/종료 시간 선택 (TimePicker)
- 같은 요일에 복수 시간대 지원 (예: 오전 10-12, 오후 14-18)
- "+ 시간대 추가" 버튼으로 복수 시간대 추가

#### 3.5 시간대 추가/삭제 UX (2026-06-10 — audit C1 C3)

> 출처: `docs/specs/_audits/2026-06-10-teacher-flow-ux-audit.md` §4.7 / §4.9.
> 마스터 정의: `teacher_availability_spec.md` §3.7.

요일 카드 안의 시간대 행은 **`SwipeActionTile`** 로 감싸 좌측 스와이프 → "삭제" 액션을 노출한다. 기존 Wrap chip 가로 배치 + 행 단위 삭제 경로 0개 문제 (audit C1) 해결.

| 인터랙션 | UX |
|---|---|
| 시간대 편집 | 행 본체 탭 또는 trailing ✏ → `ScheduleEditBottomSheet` |
| 시간대 삭제 | 행 좌측 스와이프 → "삭제" 탭 |
| 삭제 전 가드 | `affectedBookingsForWeeklyScheduleProvider` 영향 카운트 → 0건 일반 / 1+건 강조 다이얼로그 |
| 시간대 추가 | 카드 하단 "+ 시간대 추가" |

trailing 위치에 별도 "삭제" 아이콘 버튼은 두지 않는다. (ux-rules: SwipeActionTile 적용 행은 trailing 아이콘 중복 배치 금지.)

### 섹션 2: 레슨 설정

**헤더**: "레슨 기본 설정"

| 항목 | 사용자 표시명 | 설명 | 기본값 (통일 2026-06-01) |
|------|-------------|------|--------|
| `slotDurationMinutes` | **레슨 1회 시간** | 한 레슨의 기본 시간 | **50분** (한국 음악 레슨 표준) |
| `breakTimeBetweenLessons` | **쉬는 시간** | 레슨 사이 휴식 | **10분** |
| `slotStartInterval` | (내부) | 레슨 시작 가능 시간 간격 | **60분** (= 레슨+쉬는시간, 자동 계산) |

> **기본값 통일 (2026-06-01)**: `schedule_master.md §2` 와 본 스펙의 기본값이 충돌하던 문제 해소. 50/10/60 으로 통일. 시작 간격은 사용자 노출 X, 내부 계산값(레슨+쉬는시간).

각 항목에 도움말 텍스트:
- 레슨 1회 시간: "학생이 예약 시 이 길이로 예약됩니다"
- 쉬는 시간: "연속 레슨 사이에 자동으로 쉬는 시간이 추가됩니다 (이동·악기 준비 시간)"

### 섹션 3: 미리보기

**헤더**: "이번 주 예상 스케줄"

설정한 시간을 기반으로 한 주간 미니 그리드 미리보기:
- 가용시간 = 밝은 보라색 영역
- 쉬는날 = 회색 영역
- 기존 레슨 = 작은 색상 블록

### 섹션 4: 임시 휴무/추가 오픈

**헤더**: "특별 일정"
**부제**: "휴가, 공휴일, 추가 오픈 등을 관리합니다"

- 휴무 추가: 날짜 선택 + 사유 입력
- 추가 오픈: 평소 쉬는 날에 레슨 추가
- 리스트로 표시 (다가오는 것부터)

## 반영 범위

가용시간 설정이 영향을 미치는 곳:

| 화면 | 영향 |
|------|------|
| 타임라인 (일간) | 가용시간 범위만 표시 |
| 주간 그리드 | 쉬는날 진한 회색 배경 |
| 학생 예약 화면 | 가용 슬롯만 표시 |
| 레슨 추가 | 시간 선택 시 가용시간 우선 표시 |
