# 선생님 가용시간 설정 시스템

> 작성일: 2026-01-25
> 상태: 📝 설계 중
> 관련: [lesson_schedule.md](../lesson/lesson_schedule.md)

---

## 개요

선생님이 레슨 가능한 시간대를 설정하고, 학원/학생이 이를 기반으로 예약하는 시스템.

### 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **장소별 분리** | 학원/자택/방문/온라인 별도 시간표 관리 |
| **기존 예약 시각화** | 설정 화면에서 이미 예약된 레슨 표시 |
| **자동 차단** | 예약 확정 시 해당 시간 자동 비활성화 |
| **간단한 기본값** | 처음엔 "전체 허용" → 필요시 제한 추가 |

### 2. 선생님 관점 (Teacher)

#### 목표
- 장소별 가용시간 설정 (학원/자택/방문/온라인)
- 기존 예약 확인하며 시간 조정
- 개인레슨/학원 레슨 일정 통합 관리

#### 시나리오

| 시나리오 | 설명 | 설정 방식 |
|----------|------|----------|
| **학원 소속** | 학원에 가용시간 제출 → 학원이 학생 배정 | 학원 탭에서 제출 |
| **개인 체험레슨** | 가용시간 공개 → 학생이 직접 예약 | 자택/온라인 탭에서 설정 |
| **개인 정규레슨** | 고정 시간 자동 반복 | 정규레슨 등록 시 설정 |
| **혼합** | 학원 + 개인 동시 운영 | 장소별 탭 분리 |

## UX 설계 원칙 (중계 시스템)

> 이 시스템은 학원-선생님-학생 간의 "중계자" 역할을 합니다.
> 각 역할이 최소한의 노력으로 원하는 결과를 얻을 수 있어야 합니다.

### 핵심 UX 원칙

| 원칙 | 설명 | 적용 예시 |
|------|------|----------|
| **최소 입력** | 필수 정보만 요청, 나머지는 기본값 | 시간 설정 시 "전체 허용" 기본값 |
| **맥락 제공** | 결정에 필요한 정보를 미리 표시 | 기존 예약 현황 오버레이 |
| **즉각 피드백** | 행동 결과를 즉시 확인 | 저장 후 캘린더에 반영 즉시 표시 |
| **역할별 최적화** | 각 역할에 맞는 뷰 제공 | 학원은 전체 뷰, 학생은 가용 시간만 |
| **실수 방지** | 충돌/오류 사전 차단 | 이미 예약된 시간 선택 불가 |

### 역할별 UX 목표

#### 🏫 학원 관리자

```
목표: 최소 클릭으로 강사-학생 매칭
해결: 한눈에 보는 주간 시간표 + 드래그앤드롭 배정

┌─────────────────────────────────────────────────────────────┐
│  🎯 학원 UX 목표                                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Before (복잡)              After (간단)                    │
│  ─────────────              ─────────────                   │
│  1. 강사 선택               1. 시간표에서 빈 칸 클릭        │
│  2. 가용시간 확인           2. 학생 선택                    │
│  3. 학생 선택               3. 완료                         │
│  4. 시간 선택                                               │
│  5. 저장                                                    │
│                                                             │
│  4단계 → 2단계로 단축                                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

┌─────────────────────────────────────────────────────────────┐

### 정보 흐름 (Data Flow)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           정보 흐름                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1️⃣ 가용시간 설정 (선생님 → 시스템)                                      │
│     선생님이 장소별 운영시간 설정                                        │
│     ↓                                                                   │
│  2️⃣ 가용시간 공개 (시스템 → 학원/학생)                                   │
│     - 학원: 전체 시간표 열람 가능                                        │
│     - 학생: 예약 가능 시간만 표시                                        │
│     ↓                                                                   │
│  3️⃣ 예약 신청 (학생 → 시스템 → 선생님)                                   │
│     학생이 시간 선택 → 선생님에게 승인 요청                              │
│     ↓                                                                   │
│  4️⃣ 예약 승인/거절 (선생님 → 시스템 → 학생)                              │
│     선생님 결정 → 학생에게 결과 알림                                     │
│     ↓                                                                   │
│  5️⃣ 시간 자동 차단 (시스템)                                              │
│     승인된 예약 → 해당 시간 자동 비활성화                                │
│     ↓                                                                   │
│  6️⃣ 변경/취소 (양방향)                                                   │
│     학생 변경 요청 → 선생님 승인                                         │
│     선생님 취소 → 학생 알림                                              │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### UI 일관성 규칙

| 요소 | 규칙 | 이유 |
|------|------|------|
| **시간 표시** | 24시간제 (14:00) | 명확성, 국제 표준 |
| **상태 색상** | ○ 가용(초록), ✕ 불가(회색), ● 선택(파랑) | 직관적 인식 |
| **예약 카드** | 시간/학생명/악기 순서 통일 | 스캔 용이성 |
| **버튼 위치** | 주요 액션은 화면 하단 | 엄지 접근성 |
| **알림 문구** | 행동 + 결과 명시 | "김서연님이 예약을 신청했습니다" |

### 에러 방지 패턴

| 상황 | 방지 패턴 |
|------|----------|
| 중복 예약 | 이미 예약된 시간 비활성화 + 툴팁 |
| 운영시간 외 예약 | 비활성화 + "운영시간이 아닙니다" 표시 |
| 버퍼 시간 충돌 | 앞뒤 버퍼 포함하여 시간 계산 |
| 당일 예약 | 최소 예약 시간 미충족 시 비활성화 |
| 과거 시간 선택 | 지난 시간 선택 불가 |

### TeacherAvailability (선생님 가용시간)

```dart
@HiveType(typeId: 71)
@JsonSerializable()
class TeacherAvailability extends HiveObject {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String teacherId;

  @HiveField(2)
  final LessonLocationType locationType;  // academy, home, visit, online

  @HiveField(3)
  final String? locationId;  // 학원 ID (academy인 경우)

  @HiveField(4)
  final String? locationName;  // 표시용 장소명

  @HiveField(5)
  final Map<int, TimeRange?> weeklySchedule;  // 0=월 ~ 6=일

  @HiveField(6)
  final int bufferMinutes;  // 레슨 사이 휴식 (기본 10분)

  @HiveField(7)
  final int minBookingHours;  // 최소 예약 시간 (기본 24시간 전)

  @HiveField(8)
  final DateTime createdAt;

  @HiveField(9)
  final DateTime updatedAt;
}
```

### AvailabilityException (예외 날짜)

```dart
@HiveType(typeId: 72)
@JsonSerializable()
class AvailabilityException extends HiveObject {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String teacherAvailabilityId;

  @HiveField(2)
  final DateTime date;

  @HiveField(3)
  final ExceptionType type;  // dayOff, customHours

  @HiveField(4)
  final TimeRange? customHours;  // customHours인 경우

  @HiveField(5)
  final String? reason;  // 사유 (선택)
}

enum ExceptionType {
  dayOff,      // 휴무
  customHours, // 특별 시간
}
```
