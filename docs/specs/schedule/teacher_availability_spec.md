## 1. 개요

### 1.1 배경

기존 레슨 예약 방식(선생님 3개 시간 제안 → 학생 선택 → 선생님 승인)이 복잡합니다.
스튜디오메이트/GX 방식처럼 **선생님이 가용 시간을 미리 등록**하고,
**학생이 선착순으로 예약**하는 단순한 방식으로 변경합니다.

### 1.2 핵심 변경

```
[기존 - 3단계 왕복]
선생님 → 3개 시간 제안 → 학생 선택 → 선생님 승인 → 확정
         (알림)          (알림)        (알림)

[새 방식 - 2단계 선착순]
선생님 → 가용 슬롯 등록 → 학생 예약 → 즉시 확정
         (1회)           (자동)
```

### 1.3 장점

| 항목 | 설명 |
|------|------|
| **선생님 부담 감소** | 매번 승인할 필요 없음 |
| **학생 즉시 확정** | 예약 즉시 확정 → 불확실성 제거 |
| **구현 단순화** | 승인 플로우 제거 |
| **그룹레슨과 통합** | 동일한 슬롯 예약 로직 재사용 |

## 2. 기존 방식 vs 새 방식

### 2.1 비교표

| 구분 | 기존 (3개 제안) | 새 방식 (선착순) |
|------|----------------|-----------------|
| **스케줄 등록** | 레슨마다 제안 | 미리 가용 시간 등록 |
| **예약 확정** | 선생님 승인 필요 | 즉시 자동 확정 |
| **알림 횟수** | 3회 (제안→선택→승인) | 1회 (확정) |
| **선생님 관여** | 매번 필요 | 초기 설정만 |
| **학생 경험** | 대기 필요 | 즉시 확정 |

### 2.2 1:1 레슨 = 정원 1명 클래스

개념적으로 1:1 레슨은 **정원이 1명인 그룹 클래스**와 동일합니다.

```
┌─────────────────────────────────────────────────────────────┐
│                  통합 슬롯 예약 시스템                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [1:1 레슨 슬롯]              [그룹레슨 슬롯]                │
│  • 정원: 1명                  • 정원: N명                   │
│  • 예약 = 확정                • 예약 = 확정 (정원 내)        │
│  • 참여 시 차감               • 참여 시 차감                │
│                                                             │
│  → 동일한 예약 로직 재사용                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.5 방학/시즌 모드

> **⚠️ 2026-06-01 보강 — 휴가 모드(Vacation Mode)로 통합**: 본 §3.5 의 단일 기간(`vacationMode`/`vacationStartDate`/`vacationEndDate`) 모델은 **다중 기간(`vacationPeriods: List<VacationPeriod>`) + 3옵션 처리(보강 크레딧·무료·이월) + Recovery** 로 확장된다. 신규 SSOT: [teacher_vacation_mode.md](teacher_vacation_mode.md) (E2E 감사 #4 H-001). 본 절의 기존 단일 필드는 마이그레이션 후 deprecate 예정 — 신규 코드/스펙은 신규 스펙을 따른다.

> 일반 휴무(3.4)와 구별: 휴무는 며칠~주 단위 부재. 방학 모드는 **수~달 단위 전체 운영 정지** + 수강권 자동 연장.

#### 3.5.1 사용 시나리오

| 시즌 | 일반 기간 | 효과 |
|------|---------|------|
| 여름방학 | 7~8월 (선생님이 자율 설정) | 학생 레슨 일시정지, 수강권 만료일 연장 |
| 시험기간 | 4월말~5월 중순, 10월말~11월 중순 | 동일 |
| 연말연시 | 12말~1월초 | 동일 |

#### 3.5.2 데이터 모델 확장

`TeacherAvailability` 엔티티에 다음 필드 추가:

```dart
class TeacherAvailability {
  // 기존 필드 ...
  bool vacationMode;            // 방학 모드 활성 여부
  DateTime? vacationStartDate;  // 방학 시작 (포함)
  DateTime? vacationEndDate;    // 방학 종료 (포함)
  String? vacationReason;       // "여름방학", "시험기간" 등 (선택)
}
```

서버 필드는 동일하게 백엔드 모델에도 추가 (`teacher_availability` 테이블).

#### 3.5.3 동작 규칙

| 행위 | 동작 |
|------|------|
| 학생 예약 시도 | 방학 기간 슬롯은 예약 불가 (회색 표시 + "방학 중 (~8/31)" 라벨) |
| 기존 예약 처리 | 활성화 시점에 방학 기간과 겹치는 모든 `Booking` → 자동 취소 + 학생/학부모 알림 |
| 수강권 만료일 | 방학 기간만큼 자동 연장 (Subscription.expiresAt += 방학 일수) |
| 자동 알림 | 학생/학부모에게 "선생님 방학 중 ({startDate} ~ {endDate})" 1회 푸시 |
| 방학 종료 | `vacationEndDate` 다음 날 00:00에 자동 비활성화 (`vacationMode=false`) |

#### 3.5.7 일반 휴무(3.4)와의 구분

| 항목 | 휴무 (TimeException) | 방학 모드 |
|------|---------------------|----------|
| 기간 | 1일~수일 | 1주 이상 |
| 수강권 만료 연장 | ❌ 안 함 | ✅ 자동 연장 |
| 자동 알림 | 기존 예약 있는 학생만 | 전체 학생/학부모 |
| 토글 UI | 휴무 등록 시트 | 단독 "방학 모드" 화면 |
| 모델 | `TimeException` 레코드 | `TeacherAvailability` 필드 |

방학 모드는 내부적으로 `TimeException(type=vacation)` 레코드를 자동 생성하지 않는다. `TeacherAvailability` 자체 필드로 관리.

### 3.6 간소(온보딩) ↔ 풀(설정) 화면 관계

> 출처: `docs/specs/_audits/2026-06-10-teacher-flow-ux-audit.md` §4.11 C5.

선생님 가용 시간 편집 UI 는 **두 진입점**을 가진다. 둘은 같은 데이터(`TeacherAvailability`) 를 쓰지만, 사용 컨텍스트가 다르므로 화면을 분리한다.

| 화면 | 파일 | 사용 컨텍스트 |
|------|------|---------------|
| **간소(온보딩)** | `first_availability_setup_screen.dart` | 가입 직후 1회성. 요일 그룹 + 1쌍 시작/종료 시간 만 입력. 50/10/60 기본값. |
| **풀(설정)** | `teacher_availability_split_page.dart` | 평시 조절. 요일별 다중 시간대 + 레슨 길이/쉬는 시간 + 휴무/방학. |

#### 진입 경로

```
가입 흐름 (Phase B)
  └ first_availability_setup_screen      (간소, 강제)
       ├ 저장 → 홈
       └ "더 자세히 설정" → pushReplacement → teacher_availability_split_page (풀)

홈 (Phase C 이후)
  └ 설정 탭 → "레슨 시간 설정"
       └ teacher_availability_split_page (풀)
```

#### 상호 작용 규칙

- 간소 화면은 **가입 흐름 내부**에서만 노출되며, 가입 완료 후 홈에서 별도 진입점은 두지 않는다. 가입 후 조절은 풀 화면 전용.
- 간소 → 풀 전환은 `pushReplacement`. back 버튼은 가입 흐름의 직전 화면이 아닌 홈으로 떨어진다. (간소를 거치지 않고 풀로 직접 도달하는 사용자와 동일한 back 동작을 보장)
- 풀 → 간소 역방향 전환은 없다.
- 두 화면 모두 `TeacherAvailabilityRepository` 를 공유. 간소가 저장한 weekly schedules 는 풀 화면에서 그대로 보인다.

### 3.7 시간대 추가/삭제 UX (Swipe + 영향 경고)

> 출처: `docs/specs/_audits/2026-06-10-teacher-flow-ux-audit.md` §4.7 C1 + §4.9 C3.

풀 화면의 주간 스케줄 영역은 요일별 카드 안에 시간대 행을 세로로 나열한다. 각 시간대 행은 `SwipeActionTile` 로 감싸져 좌측 스와이프 → 삭제 affordance 가 보인다.

레이아웃 (ASCII):

```
┌── 화요일 ───────────────────────────────┐
│ ⏱ 14:00 - 16:00              [✏ edit] │  ← SwipeActionTile (swipe→삭제)
│ ⏱ 17:00 - 19:00              [✏ edit] │
│                          [+ 시간대 추가] │
└────────────────────────────────────────┘
┌── 수요일 ───────────────────────────────┐
│ 쉬는날                                  │
│                          [+ 시간대 추가] │
└────────────────────────────────────────┘
```

#### 삭제 확인 다이얼로그

삭제 직전에 `affectedBookingsForWeeklyScheduleProvider` 로 영향 받는 **확정/대기 상태의 예약 수**를 조회한다.

| 영향 예약 수 | 다이얼로그 |
|--------------|-----------|
| 0 건 | 일반 확인 — "이 시간대를 삭제할까요?" |
| 1+ 건 | 강조 확인 — "이 시간대를 삭제하면 N개 예약이 영향을 받습니다. 학생에게 자동 취소 알림이 전송됩니다." |

영향 카운트 조건:
- `BookingStatus.isActive == true` (cancelled/unavailable/expired 제외)
- `lessonDate >= today`
- `dayOfWeek` 일치 (LessonBooking 1..7 → WeeklySchedule 0..6 정규화)
- `[startTime, endTime)` 시간 구간이 weekly schedule 의 `[startTime, endTime)` 와 겹침

요청:

```http

Content-Type: application/json

{
  "slot_id": "{teacher_id}-{yyyy-mm-dd}-{HH:mm}",
  "student_id": "student-id",
  "student_name": "학생 이름"
}
```

서버는 `slot_id`를 `teacher_id`, `scheduled_date`, `scheduled_time`으로 해석하고 기본 `duration=60`분 예약을 생성한다. 응답은 기존 `AvailabilitySlot` 파서가 바로 읽을 수 있도록 다음 필드를 포함한다.

| 필드 | 설명 |
|------|------|
| `id` | 생성된 booking id |
| `teacher_id` | 슬롯 소유 선생님 id |
| `date` | 예약 날짜 |
| `start_time` / `end_time` | 예약 시작/종료 시간 |
| `duration_minutes` | 예약 길이 |
| `status` | 슬롯 예약 성공 시 `booked` |
| `booked_by_student_id` / `booked_by_student_name` | 예약 학생 정보 |

일반 `RemoteBookingRepository`가 보내는 `teacher_id`, `lesson_date`, `start_time` 기반 요청은 기존 `BookingResponse` 계약을 유지한다.

### 5.2 학생 변경/취소

> 참고: [ux_guidelines.md](../design/ux_guidelines.md) 섹션 11.3 - 변경/취소 확인 플로우

**정책 원칙:**
- `일정 변경`과 `이번 일정 취소`는 같은 변경/취소권을 사용한다.
- 일정 변경은 바로 대체 일정을 조율하는 액션이다.
- 이번 일정 취소는 대체 일정을 지금 정하지 않고 해당 일정만 건너뛰는 액션이다.
- 사전 취소가 확정되면 수강권 회차는 차감하지 않는다. 예: 3회차 일정 취소 후 다음 실제 진행 레슨은 다시 3회차다.
- 학생 사유의 일정 변경/취소는 변경/취소권 1회를 사용한다. 메시지에는 권리 사용과 회차 유지가 함께 보여야 한다.

**변경 횟수 상태별 UI:**

| 남은 횟수 | UI 표시 | 변경 버튼 |
|----------|--------|---------|
| ≥ 2회 | "🔄 변경: N/M회" | 활성 |
| = 1회 | "⚠️ 변경 1회 남음" | 활성 + 확인 다이얼로그 |
| = 0회 | "🚫 변경 불가" | 비활성 (회색) |

### 5.3 선생님 레슨 취소

선생님이 레슨을 취소하면:
- 학생 변경 횟수 차감 안 함
- 슬롯 자동 반환 (다른 학생 예약 가능)
- 학생에게 알림
- 취소 메시지에는 반드시 회차를 포함한다. 예: `3회차 레슨이 취소되었습니다`.
- 학생이 먼저 취소를 요청한 경우 응답 전 메시지는 `3회차 레슨 취소를 요청했어요`처럼 요청 상태와 회차를 함께 표시한다.

### 6.1 선생님 가용 슬롯 (TeacherAvailability)

/// 슬롯 유형
enum AvailabilityType {
  regular,    // 정기 (매주 반복)
  oneTime,    // 단발성
}

/// 슬롯 상태
enum SlotStatus {
  available,  // 예약 가능
  booked,     // 예약됨
  cancelled,  // 취소됨 (휴무 등)
}

/// 선생님 가용 슬롯
@HiveType(typeId: 75)
@JsonSerializable()
class TeacherAvailability {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String teacherId;

  @HiveField(2)
  final AvailabilityType type;

  // 정기 슬롯용
  @HiveField(3)
  final int? dayOfWeek;           // 0=월, 6=일

  @HiveField(4)
  final String? timeOfDay;        // "14:00"

  // 단발/실제 슬롯
  @HiveField(5)
  final DateTime? startTime;

  @HiveField(6)
  final DateTime? endTime;

  @HiveField(7)
  final int durationMinutes;      // 레슨 시간 (분)

  @HiveField(8)
  final SlotStatus status;

  @HiveField(9)
  final String? bookedByStudentId; // 예약한 학생

  @HiveField(10)
  final String? lessonId;          // 연결된 레슨 ID

  @HiveField(11)
  final String? cancelReason;      // 취소 사유

  @HiveField(12)
  final DateTime createdAt;

  const TeacherAvailability({
    required this.id,
    required this.teacherId,
    required this.type,
    this.dayOfWeek,
    this.timeOfDay,
    this.startTime,
    this.endTime,
    required this.durationMinutes,
    this.status = SlotStatus.available,
    this.bookedByStudentId,
    this.lessonId,

  });
}

- 해당 시간대가 가용할 때 ⭐ 뱃지 표시

```dart
// 추천 로직 예시
bool isRecommended(TimeSlot slot, List<Lesson> recentLessons) {
  final sameDayLessons = recentLessons.where((l) =>
    l.dayOfWeek == slot.dayOfWeek &&
    l.startTime == slot.time
  );
  return sameDayLessons.length >= 2; // 2회 이상 같은 시간 레슨
}
```
