## 1. 개요

### 1.1 배경

기존 레슨 예약 방식(선생님 3개 시간 제안 → 학생 선택 → 선생님 승인)이 복잡합니다.
스튜디오메이트/GX 방식처럼 **선생님이 가용 시간을 미리 등록**하고,
**학생이 선착순으로 예약**하는 단순한 방식으로 변경합니다.

### 1.2 핵심 변경

```
[기존 - 3단계 왕복]
선생님 → 3개 시간 제안 → 학생 선택 → 선생님 승인 → 확정
         (알림)          (알림)        (알림)

[새 방식 - 2단계 선착순]
선생님 → 가용 슬롯 등록 → 학생 예약 → 즉시 확정
         (1회)           (자동)
```

### 1.3 장점

| 항목 | 설명 |
|------|------|
| **선생님 부담 감소** | 매번 승인할 필요 없음 |
| **학생 즉시 확정** | 예약 즉시 확정 → 불확실성 제거 |
| **구현 단순화** | 승인 플로우 제거 |
| **그룹레슨과 통합** | 동일한 슬롯 예약 로직 재사용 |

## 2. 기존 방식 vs 새 방식

### 2.1 비교표

| 구분 | 기존 (3개 제안) | 새 방식 (선착순) |
|------|----------------|-----------------|
| **스케줄 등록** | 레슨마다 제안 | 미리 가용 시간 등록 |
| **예약 확정** | 선생님 승인 필요 | 즉시 자동 확정 |
| **알림 횟수** | 3회 (제안→선택→승인) | 1회 (확정) |
| **선생님 관여** | 매번 필요 | 초기 설정만 |
| **학생 경험** | 대기 필요 | 즉시 확정 |

### 2.2 1:1 레슨 = 정원 1명 클래스

개념적으로 1:1 레슨은 **정원이 1명인 그룹 클래스**와 동일합니다.

```
┌─────────────────────────────────────────────────────────────┐
│                  통합 슬롯 예약 시스템                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [1:1 레슨 슬롯]              [그룹레슨 슬롯]                │
│  • 정원: 1명                  • 정원: N명                   │
│  • 예약 = 확정                • 예약 = 확정 (정원 내)        │
│  • 참여 시 차감               • 참여 시 차감                │
│                                                             │
│  → 동일한 예약 로직 재사용                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```
│                                     │
```


### 4.2 예약 확정 조건

| 조건 | 설명 |
|------|------|
| 슬롯 가용 | 해당 시간 슬롯이 비어있음 |
| 수강권 유효 | 활성 수강권 보유 + 잔여 횟수 있음 |
| 중복 없음 | 같은 시간에 다른 예약 없음 |

### 4.3 동시성 처리

```
[동시 예약 시나리오]

학생 A (14:00:00) ─┬─▶ 2/18 15:30 슬롯 예약 요청
학생 B (14:00:01) ─┘

[처리 방식: 낙관적 락]

1. 학생 A 요청 처리 시작
2. 슬롯 상태 확인 → 가용
3. 트랜잭션 시작
4. 슬롯 예약 (status = booked)
5. 트랜잭션 완료 → 학생 A 성공

6. 학생 B 요청 처리
7. 슬롯 상태 확인 → 이미 예약됨
8. 실패 응답 + "이미 예약된 시간입니다" 안내
```

### 5.4 수강권 재작성 (선생님)

**기존 방식 (스튜디오메이트 등):**
```
수강권 삭제 → 환불 처리 → 새 수강권 발급
(학생 입장: "내 수강권이 사라졌다")
```

**새 방식 (재작성):**
```
수강권 수정 → 사용분 유지 → 변경 이력 기록
(학생 입장: "수강권 내용이 변경됐다")
```

#### 재작성 vs 삭제 비교

| 구분 | 재작성 (lesson-app) | 삭제+재발급 (스튜디오메이트) |
|------|---------------------|---------------------------|
| **학생 경험** | 연속성 유지 ✅ | "내 수강권 삭제됨" 불안 ❌ |
| **이력 추적** | 같은 ID로 이력 관리 ✅ | ID 변경, 연결 끊김 ❌ |
| **구현** | 수정 이력 테이블 필요 | DB 단순 (삭제+생성) |
| **회계** | 변경 내역으로 관리 | 환불+재결제로 명확 |
| **적합 환경** | 개인 선생님, 외부 결제 | 학원, 앱 내 결제 |

## 6. 데이터 모델

### 6.1 선생님 가용 슬롯 (TeacherAvailability)

```dart
/// 슬롯 유형
enum AvailabilityType {
  regular,    // 정기 (매주 반복)
  oneTime,    // 단발성
}

/// 슬롯 상태
enum SlotStatus {
  available,  // 예약 가능
  booked,     // 예약됨
  cancelled,  // 취소됨 (휴무 등)
}

/// 선생님 가용 슬롯
@HiveType(typeId: 75)
@JsonSerializable()
class TeacherAvailability {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String teacherId;

  @HiveField(2)
  final AvailabilityType type;

  // 정기 슬롯용
  @HiveField(3)
  final int? dayOfWeek;           // 0=월, 6=일

  @HiveField(4)
  final String? timeOfDay;        // "14:00"

  // 단발/실제 슬롯
  @HiveField(5)
  final DateTime? startTime;

  @HiveField(6)
  final DateTime? endTime;

  @HiveField(7)
  final int durationMinutes;      // 레슨 시간 (분)

  @HiveField(8)
  final SlotStatus status;

  @HiveField(9)
```

### 8.4 스마트 추천

**⭐ 평소 시간 표시 조건:**
- 최근 3개월 내 동일 요일 레슨 이력
- 해당 시간대가 가용할 때 ⭐ 뱃지 표시

```dart
// 추천 로직 예시
bool isRecommended(TimeSlot slot, List<Lesson> recentLessons) {
  final sameDayLessons = recentLessons.where((l) =>
    l.dayOfWeek == slot.dayOfWeek &&
    l.startTime == slot.time
  );
  return sameDayLessons.length >= 2; // 2회 이상 같은 시간 레슨
}
```

**추천 칩 스타일:**
```

└────────────┘     배경: #FFF5EB (연한 주황)
```
