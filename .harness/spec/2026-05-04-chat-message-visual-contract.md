# Spec — chat-message-visual-contract

> 날짜: 2026-05-04 | 상태: locked

## 1. 목표

레슨요청과 스케줄 조절 상세 화면의 채팅 히스토리 디자인을 하나의 시각 규칙으로 통일한다.

## 2. 성공 기준

- [ ] 레슨요청 `RequestHistoryChat`의 모든 사용자 이벤트는 말풍선 컨테이너를 사용한다.
- [ ] 스케줄 조절 `ScheduleChangeEventBubble`의 모든 사용자 이벤트는 같은 말풍선 컨테이너를 사용한다.
- [ ] 말풍선 정렬과 색상은 viewer 기준이다: 내 메시지 = 오른쪽 + `paperAccentSoft`, 상대 메시지 = 왼쪽 + `paperDark`.
- [ ] 일정 후보/현재 일정/확정 일정 같은 스케줄 데이터는 말풍선 내부에서만 각진 사각형 카드로 표시한다.
- [ ] 수락/거절/응답대기/결정변경/취소 같은 상태 메시지는 별도 색상 박스나 체크 아이콘 Row로 분기하지 않는다.
- [ ] 결정 변경 이벤트는 이전 선택 일정에 취소선을 유지한다.
- [ ] 내가 시간변경 후보를 보낸 직후 하단 액션바는 레슨요청과 동일하게 응답 대기 + 결정 변경을 표시한다.
- [ ] 스케줄 변경 상세 화면 배경은 레슨요청 상세와 동일한 `AppColors.paper`를 사용한다.

## 3. 사용자 시나리오

### 시나리오 1: 레슨 요청 히스토리
- Given 선생님이 학생의 레슨 요청을 확인한다.
- When 초기 요청, 수락, 결정 변경, 메시지 추가 이벤트가 보인다.
- Then 모든 이벤트는 같은 말풍선 문법으로 읽히고, 일정 후보만 내부 각진 카드로 보인다.

### 시나리오 2: 스케줄 조절 히스토리
- Given 학생 또는 선생님이 1~3개 일정 후보를 보냈다.
- When 상대가 후보를 수락한다.
- Then 수락 이벤트는 다른 디자인의 성공 박스가 아니라 같은 말풍선 안의 텍스트 이벤트로 보인다.

## 4. 인터페이스

새 엔티티 없음. 기존 `RequestEvent`와 `TimeSlotOption`을 사용한다.

## 5. 비기능 요구사항

- 접근성: 말풍선 내 본문은 기존 `AppTypography.bodySmall` 이상을 유지한다.
- 디자인: 색상은 `AppColors`만 사용한다.
- 디자인: 상세 화면 `Scaffold.backgroundColor`는 `AppColors.paper`로 고정한다.
- 유지보수: 레슨요청과 스케줄 조절은 가능한 동일한 말풍선 규칙을 코드/테스트에서 공유한다.

## 6. 아키텍처 결정

- 채택: 전체 채팅 이벤트를 말풍선으로 통일하고, 스케줄 데이터만 내부 각진 카드로 분리한다.
- 거절: 상태별로 성공 박스, 안내 박스, 말풍선 없음이 섞이는 방식. 같은 히스토리 안에서 시각 문법이 달라져 사용자가 이벤트 종류보다 디자인 차이를 먼저 인지한다.

## 7. 품질 계약

- Widget test로 다음을 검증한다.
  - 수락 이벤트에 `Icons.check_circle`이 없어야 한다.
  - 수락 이벤트에도 rounded 말풍선이 존재해야 한다.
  - 일정 후보 이벤트에는 rounded 말풍선과 내부 angular schedule card가 함께 존재해야 한다.
  - 레슨요청 히스토리 말풍선도 rounded shape를 사용해야 한다.

## 8. 범위 외

- 색상 팔레트 전역 개편
