## 0. 한눈 요약 (TL;DR)

스펙 14개는 **운영자(=학원장)가 학생/강사/공지/청구를 처리**하는 워크플로우에는 견고하다. 그러나 **경영자(=학원장)가 의사결정**에 쓸 데이터·인사이트·자동화는 얕다.

| 평가 | 비중 | 점수 |
|---|---|---|
| 운영 워크플로우 견고성 | 30% | 8/10 — 권한 격리, 12h 정책, 일괄 휴강 등 견고 |
| 강사 관리 깊이 | 15% | 7/10 — 초대~퇴사 흐름은 OK, 평가/페이/대강은 약함 |
| 학생 이탈 방지 | 15% | 4/10 — 이탈은 사후 처리만, 조기 신호 감지 부재 |
| 수익성 가시성 | 15% | 5/10 — KPI 카드는 있으나 강사별 수익률·코호트 부재 |
| 마케팅/유입 분석 | 10% | 3/10 — 공개 페이지·인박스만, 추천/유입 채널 추적 없음 |
| 데이터/리포트 자동화 | 10% | 3/10 — 세무사용 export·트렌드 분석·예측 부재 |
| 리스크/안전망 | 5% | 4/10 — 노트 일시접근·감사 로그는 OK, 학원장 부재·데이터 이전 부재 |
| **종합** | **100%** | **5.6/10 — 운영 OK, 경영 부족** |

**핵심 누락 3가지**:
1. **강사 페이/송금 자동화 의도적 제외** (Q4) → 한국 학원 현실 반영이라 했으나, 학원장의 매월 최대 업무 (송금 8건 × 강사) 가 앱 밖에 남음
2. **학생 이탈 조기 신호 없음** → 출석률은 집계되나 "출석 저조 N회 → 알림" 자동화 부재
3. **공개 페이지 SEO는 있으나 유입 추적 없음** → 어디서 왔는지(검색/추천/광고) 데이터 없음 → 마케팅 ROI 계산 불가

## 2. 강점 (보존해야 할 설계)

다음 8가지는 한국 학원 현실 + 경영자 관점에서 **잘 설계된 핵심 자산**이다. 향후 보강 시에도 손대지 말 것.

1. **권한 격리 (NFR-A-5)** — 학원장이 학생 노트/녹음/연습 기록 접근 불가. 2인 동의 + 90일 일시 접근 토큰. 강사-학원장 신뢰 기반.
2. **컨텍스트 토글 (context_toggle_spec)** — 학원장 겸직 강사를 위한 JWT 분리, 동시 세션 금지, 명시적 확인 모달. UX 가드 견고.
3. **무조건 위임 + 활동 timeline (academy_schedule_authority §3)** — 강사 일정 직접 변경 + 학원장은 사후 감사. 글로벌 SaaS 5종 패턴 추종 (Q1/Q2 폐기 결정 명확).
4. **수습 강사 onboarding (Q11)** — 권한 OFF가 아닌 가시성 강화 (12h 무관 즉시 푸시). 한국 신규 강사 현실 반영.
5. **12h 강사 사유 취소 정책 (teacher_cancellation_policy)** — 학생 변경권 +1 자동 적립, 페이 차감 안 함 (Q4), 학원장 알림. 페이 차감을 의도적으로 빼서 한국 문화 충돌 회피.
6. **C2 일괄 휴강 (owner_bulk_closure)** — 1시간 유예 + 강사 의견 + Override. 학원장 단독 결정권을 보존하되 강사 의견 반영 채널 확보.
7. **공개 페이지 검토 큐 (public_page §8)** — 첫 게시 운영자 승인 + 위반 신고 3단계 (경고/비공개/권한회수). 플랫폼 책임성.
8. **카톡 알림톡 템플릿 사전 등록 (announcements §6.2, teacher_cancellation §4.3)** — 카톡 비즈 정책 준수, 비용 통제.

## 4. 즉시 보강 가능 (S 사이즈, 24h)

다음은 기존 스펙에 필드/섹션 추가만으로 즉시 효과 발생:

1. **세무사용 CSV export** (Gap-6) — billing §8 에 export 화면 1개 추가. 외부 의존 없음.
2. **강사별 ROI 컬럼** (Gap-7) — teacher_management §5 강사 상세 + `/teachers?sort=roi` 정렬. settlement 데이터 재사용.
3. **미수금 총액 KPI** — dashboard §3.2 에 "미수금 총액 ₩X / 평균 연체 N일" 1줄 추가.
4. **학생당 LTV 표시** — billing §8 에 "평균 학생 재원기간 × 월 평균 단가 = LTV" 추가. 기존 데이터로 계산.
5. **출석률 추세 그래프** — student_management §6 학생 상세에 4주 추세 라인 추가. attendance_rate 데이터 재사용.

이 5개는 1개 PR/24h 작업으로 묶을 수 있음. 매출 가시성 + 강사 평가 + 이탈 신호 셋 다 즉시 개선.

## 6. 메타: 스펙 구조의 강점과 약점

### 강점 (구조)
- 정책 결정 사유가 옵시디언 참조로 추적됨 (Q1-Q11 결정 매핑 표)
- ownership 분기 (academy/teacher) 가 일관됨 — billing/cancellation/closure 전반에 영향
- "이 스펙에서 다루지 않음" 명시 (제외 항목) — Surgical 원칙 준수
- 시퀀스 다이어그램 (mermaid) 으로 흐름 시각화 — billing/closure/inbox

### 약점 (구조)
- **마일스톤 AC-M1~M6 가 운영 워크플로우 중심** — 경영자 인사이트 (BI/리포트) 마일스톤 없음
- **"학원장 페르소나" 인터뷰 산출물 부재** — 5개 학원 인터뷰 결과 (옵시디언) 가 코드에 못 들어와서 갭이 발생
- **외부 연동 (PG/오픈뱅킹/NTS) 마일스톤 보류** — Year 2 로 미뤘으나 학원장 일상 업무의 가장 큰 부분
- **공개 페이지가 SEO 최적화만, 전환 최적화 부재** — 페이지 방문 후 문의/등록 전환율 추적 없음
