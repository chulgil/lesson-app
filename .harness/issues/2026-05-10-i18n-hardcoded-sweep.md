# 이슈: i18n 하드코딩 문자열 도메인별 정리

**우선순위:** 높음  
**상태:** 완료

## 배경

G4 i18n 1차 기반은 완료되었지만, 기존 화면에는 하드코딩된 한국어 UI 문자열이 남아 있다. 전면 ARB 이관은 장기 작업이므로, 먼저 도메인별로 이미 존재하는 `AppStrings`로 치환 가능한 문자열을 정리한다.

## 병렬 작업 원칙

- 도메인별 파일 범위를 분리한다.
- 병렬 에이전트는 `frontend/lib/core/l10n/app_strings.dart`, `frontend/lib/core/l10n/arb/*`, generated l10n 파일을 수정하지 않는다.
- 신규 문자열이 필요한 경우 직접 추가하지 않고 후보 목록으로 보고한다.
- 같은 의미의 기존 `AppStrings`가 있을 때만 코드 수정한다.

## 1차 병렬 작업 범위

- `student_home`, `parent_home`, `home`: 홈/역할별 탭에서 기존 공통 문자열로 대체 가능한 UI 문구 정리
- `schedule`, `subscription`: 스케줄/수강권 화면에서 기존 공통 문자열로 대체 가능한 UI 문구 정리
- `lessons`, `practice`: 레슨/연습 화면에서 기존 공통 문자열로 대체 가능한 UI 문구 정리
- `profile`, `students`, `settings`: 프로필/학생/설정 화면에서 기존 공통 문자열로 대체 가능한 UI 문구 정리

## 제외 범위

- mock 데이터 제목, 샘플 과제명, 예시 콘텐츠명은 번역 리소스가 아니라 데이터 계층 정책으로 분리한다.
- 동적 문장 조립이 필요한 알림/스낵바 문구는 문장 템플릿 설계가 필요하므로 후보로만 수집한다.
- `billing` 유료화 기능은 별도 R4 이슈/커밋 범위이므로 이번 i18n 정리 범위에서 제외한다.

## 이번 완료 범위

- 계정 삭제 화면의 제목, 경고, 확인 다이얼로그, 성공/실패 안내 문구를 `AppStrings`로 공통화했다.
- 레퍼토리 곡 입력 폼의 곡 제목 라벨과 필수 검증 문구를 `AppStrings`로 공통화했다.
- 전체 하드코딩 스캔 결과, 남은 항목은 mock 데이터/샘플 콘텐츠/동적 문장 템플릿이 많아 별도 문장 템플릿 설계 이슈로 분리한다.

## 완료 조건

- 도메인별 즉시 치환 가능한 하드코딩 UI 문자열을 줄인다.
- 각 변경 도메인에서 `flutter analyze`를 통과한다.
- 필요 시 i18n architecture test를 보강한다.
- 커밋/푸시한다.
