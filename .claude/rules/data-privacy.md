# 데이터 프라이버시 — 개인정보 접근 규칙

> OpenCLO External 에이전트 패턴 적용. 민감 데이터의 접근 권한을 물리적으로 분리.

## 민감 데이터 분류

| 등급 | 데이터 | 접근 조건 |
|------|--------|----------|
| **Level 1 (최고)** | 결제 정보 (카드, 계좌) | API 격리, 직접 접근 금지, 별도 서비스 레이어 |
| **Level 2 (높음)** | 개인정보 (이름, 연락처, 주소) | 인증된 사용자만, 최소 권한 원칙 |
| **Level 3 (중간)** | 레슨 노트 이력 | 설정에서 공유 허용 시에만 타인 접근 |
| **Level 4 (낮음)** | 레슨 일정, 연습 기록 | 관련자(선생님-학생-학부모)에게만 |

## 역할별 접근 권한

| 데이터 | 선생님 | 학생 | 학부모 |
|--------|--------|------|--------|
| 학생 연락처 | 읽기 | 본인만 | 자녀만 |
| 학생 주소 | 읽기 | 본인만 | 자녀만 |
| 레슨 노트 이력 | 읽기/쓰기 | 공유 설정 시 읽기 | 공유 설정 시 읽기 |
| 결제 정보 | 청구서 발행 | 열람 불가 | 결제 처리 |
| 연습 녹음 | 공유 설정 시 듣기 | 본인만 | 공유 설정 시 듣기 |

## 코드 구현 규칙

### 금지 사항
- 개인정보를 로그(`print`, `debugPrint`, `logger`)에 출력 금지
- 개인정보를 하드코딩 (테스트 데이터 포함) 금지
- 에러 메시지에 개인정보 노출 금지
- 개인정보를 로컬 스토리지(Hive)에 평문 저장 시 암호화 필수

### 필수 사항
- 개인정보 접근 API는 별도 서비스 레이어(`features/[domain]/data/services/`)로 격리
- 접근 권한 체크는 Repository 레벨에서 수행
- 공유 설정 변경은 설정 화면에서만 가능 (다른 화면에서 직접 변경 금지)

### 검증 grep 패턴

```bash
# 로그에 개인정보 노출
grep -rn "print.*name\|print.*phone\|print.*address" --include="*.dart" features/
grep -rn "debugPrint.*name\|debugPrint.*phone" --include="*.dart" features/

# 하드코딩된 개인정보 (Mock 데이터 제외)
grep -rn "010-\|@.*\.com" --include="*.dart" features/ | grep -v "mock\|test\|Mock"
```
